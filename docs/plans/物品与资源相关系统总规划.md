# 物品与资源相关系统总规划

> 状态：系统样稿  
> 日期：2026-07-22  
> 目的：明确物品与资源系统的职责、数据归属和交互边界。

## 一、已确定原则

1. 只有战斗局内手牌使用卡牌表现。
2. 地图角色、资源、建筑和物品不使用卡牌堆叠或实体附着交互。
3. 同一种物品完全同质；年份、纯度、物品耐久和绑定不进入物品实例。
4. 行囊中的可堆叠物品同类合并为一格，不设单格数量上限；不可堆叠物品每件占一格。总格数仍按角色行囊容量限制。
5. 共享仓库是村庄物品数量的唯一真相。
6. 建筑和资源地点只提供功能入口，不自行保存库存或运行生产计时器。
7. 所有奖励、消耗和交易都通过统一事务接口结算。

## 二、系统总览

```text
物品目录 ───────────────┐
                       v
资源来源 ─> 活动/任务 ─> 奖励结算 ─> 派遣收获 ─> 共享仓库
   ^          ^             ^                         |
   |          |             |                         v
时间日历   角色活动状态   探索/战斗/事件             制作/建造/交易
   |          |                                       |
   └────> 月度刷新、任务完成 <──── 存档系统 <─────────┘
```

## 三、各系统职责

### 1. 物品定义系统

负责回答“这是什么物品”。

静态数据包括：

- `definition_id`
- 显示名称与图标
- 主分类、子分类
- 品阶（由对应物品规则配置或派生）
- 固定词缀
- 是否可堆叠；旧 `max_stack` 字段保留兼容，不再限制行囊中的可堆叠物品数量

物品定义不保存玩家拥有数量。材料品阶由材料规则派生；法宝品级与材料品阶分别定义。

### 2. 共享仓库系统

负责回答“村庄拥有多少物品”。

核心状态：

```text
<item_id> -> <quantity>
<item_id> -> <quantity>
```

仓库提供查询、增加、扣除和原子批量结算。仓库界面只读取这一份状态，不维护第二份数量。

角色背包只承担随身装备和消耗品；基础建设材料默认从共享仓库扣除。

### 3. 统一奖励结算系统

负责处理所有物品流入与流出：

- 资源采集
- 探索奖励
- 战斗掉落
- 任务奖励
- 市场买卖
- 建造和制作消耗

一次结算使用稳定物品ID和数量列表。扣除必须全部满足后才执行，避免部分扣除。

### 4. 资源来源系统

负责回答“在哪里、以什么规则获得资源”。

每个来源定义包含：

- 来源ID与地点ID
- 固定产出
- 单次耗时
- 当前储量与储量上限
- 恢复数量与恢复周期
- 是否一次性
- 解锁条件

静态规则与运行状态分离。东林地“上限200、每月恢复100”是定义；当前剩余137是存档状态。

### 5. 时间与日历系统

负责推进任务并触发周期恢复。

月度恢复不只检查“今天是不是初一”，而是记录上次结算的绝对月份。一次沉睡跨越三个月时，东林地应恢复三次，每次100，最终不超过200。

### 6. 角色活动系统

负责防止同一角色同时修炼、研读、采集和派遣。

角色活动统一为：空闲、村庄任务、外出派遣、修炼、研读、受伤休养。资源系统只申请角色占用，不自行增加零散的忙碌字段。

### 7. 村庄任务系统

用于村庄内可以与其他玩法并行推进的工作。

村庄任务由统一任务管理器保存进度，并通过统一奖励接口结算，不把库存或计时器写入具体地点或建筑脚本。

### 8. 世界派遣与探索系统

世界队伍在地点执行行动时，消耗游戏时间并把奖励加入“本次派遣收获”。队伍归村后，收获通过统一奖励接口一次性转入共享仓库。

探索节点记录本轮是否完成；固定世界资源点记录跨派遣持续存在的区域储量。

### 9. 建筑与资源地点系统

建筑负责解锁功能、提供岗位或改变任务参数。自然资源地点应使用独立的资源地点数据，不再伪装成建筑。

例如：

- 草药采集点：资源地点；具体可采集物必须对应现存、带有效图标的物品定义
- 凡矿点：资源地点
- 工坊：建筑，解锁制作任务
- 仓库：建筑或村庄功能，改变容量与整理能力

### 10. 制作与建造系统

制作和建造以后统一遵循：先检查仓库材料，确认后原子扣除，创建任务，完成后把产物送回仓库或直接落成建筑。

工具只提供耗时、产量或成功率加成，不设置耐久。

### 11. 市场与经济系统

市场拥有独立商品库存和刷新周期。购买从货币中扣除并进入共享仓库；出售从共享仓库扣除。市场是资源缺口的安全阀，不应替代主要采集地点。

### 12. 存档系统

至少保存：

- 仓库物品数量
- 进行中的村庄任务
- 角色活动状态
- 固定资源点当前储量与上次恢复月份
- 当前派遣队伍和派遣收获
- 探索节点完成状态
- 市场库存与刷新状态

## 四、建议实施顺序

1. 清理物品静态数据，建立稳定物品ID。
2. 建立共享仓库和统一奖励事务。
3. 建立资源来源定义与状态。
4. 接通已定义资源地点、派遣收获和归村入库。
5. 接通对应的探索节点。
6. 建立角色活动与已定义的村庄任务。
7. 接通仓库、地点和任务界面。
8. 接入存档后，按现行物品词典扩展其他材料。

## 五、验收边界

- 资源来源使用稳定物品 ID，并由统一接口记录增加与扣除。
- 跨周期结算按日历状态补齐，不漏结算或重复结算。
- 派遣途中奖励先记录在本次收获中，不提前进入村庄仓库。
- 归村结算只发生一次。
- 仓库同 ID 物品合并；角色行囊的可堆叠物品不设单格数量上限，旧 `max_stack` 字段仅兼容旧资源。
- 全流程不生成世界物品实体，不调用建筑计时。
