# 百川行走卡顿与按钮悬停清理（已优化并验收）

2026-11-06。用户反馈大世界行走严重卡顿，并要求去掉“收起人物名单”一类不必要的按钮悬停卡片。本轮只优化既有计算与显示，不改变原底图、地点、8000公里尺度、地形倍率、NPC演算、行走耗时及存档规则。

## 已测得的热点

隔离APPDATA、真实MainScene、同一台机器实测：`_refresh_people`中位398.08毫秒，`get_nearby_person_ids`中位203.14毫秒；主角地点检查中位0.1566毫秒。地图每0.25秒查询900范围人物后，又查询38范围人物，重复遍历全世界。站立100帧已有9帧超过100毫秒；开启人口演算行走100帧中20帧超过100毫秒，平均113.96毫秒。

`get_free_world_map_people`对每个待判定的驻留人物调用旧地点`get_node`，该方法每次复制整份地点数组后线性查找。相同地点被上千人物重复查询。旧空节点本身没有恢复绘制，但人口徽标仍会因隐藏途经点人数改变而重复布局。

## 修订

- 每次人物查询只读取一次地点表，建立本次查询的地点类型索引；驻留/行旅/副本/临时队伍过滤规则保持，不跨时间缓存NPC状态。
- 900范围查询的现有结果直接用于本次38范围接触名单签名；对外的接触查询继续实时读取人物，避免保存、事件及主动交互拿到过时位置。
- 自由地图人口徽标只接收具名地点计数；具名人数未变时跳过重新布局，隐藏途经点不触发视觉刷新。
- 人口数字/名单的信号刷新与地图人物显示采用同样0.25秒节奏；模型中的抵达、死亡、行程和交互资格仍即时结算。每次NPC结算缓存完整的起点/终点/遁速路段费用，结算结束清空，不改时间公式。
- 去掉人物名单折叠、普通返回及只复述按钮名称的交互提示；保留不能执行的具体原因和人物/物品/规则详情。
