## 一、设计目标与当前冲突

玩家在战前配置一个能自动运转的招式构筑：选什么招、各占多大空间、互相如何作用、资源能否支撑、何时使用本人丹药，以及是否御用实际装备的法宝。战斗中观察结果与原因，不再逐轮排一串技能或要求玩家临场出招。

这不是给旧队列换一个格子皮肤。位置用于组织构筑，遍历到招式占格时按当时条件决定是否发动。建议以完整回合作为逻辑单位，保留角色与招式的时序和动作演出；倍速只影响观察节奏，不改变逻辑轮次。

| 现行事实 | 新方向的冲突 | 本案处理 |
| --- | --- | --- |
| 回合由所有角色的 5—10 个队列行动结束定义 | 不再有预先排满的队列，也不设每角色每轮出手总上限 | 全场共用回合，在所有参战者遍历结束后开放整理；旧 5—10 不转换为新上限，轮次等价性待测试 |
| 每项行动按角色行动速度独立跑条，技能本身没有独立行动速度 | 新方案读到占格即按条件触发，角色到点处理一整行 | 保留角色行动速度跑条作为行处理先后；旧版每招跑条变为每行跑条，不能冒称战斗节奏完全相同 |
| 队首应对与来袭行动嵌套结算 | 没有队首可供匹配，多个应对可能同时就绪 | 已确认走格后待命至全员遍历结束，已待命合格招式按盘面顺序选择；同次攻击至多一个应对，心法不再自行自动应对，群攻口径待确认 |
| 休整与服丹均占队列行动位 | 无队列后不再靠行动位限制使用 | 休整必须有自身已确认节奏；丹药消耗真实物品，自动条件和布阵表示须确认 |
| 原技能冷却按完整旧回合计数 | 新回合内触发数量可能不同 | 原冷却与特殊触发逐项审计，不因取消通用倒计时而自行删除 |
| 原技能槽及化法、法宝来源保存在人物和 NPC 快照 | 有形状的新布局无法从旧槽位唯一推导 | 保留旧引用和绑定，先生成可调整的迁移草案；无法映射的项进入待处理清单 |

“保持原费用和效果”只能保证字段及单次结算来源相同，**不保证整场强度、轮次或胜率不变**。单位时间内招式触发次数和每轮资源补给的相对频率都需重新平衡。

## 二、从战前到战后

```text
学会秘籍、公共招式及取得物品
  → 装备法宝、选择主辅修及化法
  → 战前在招式盘摆放招式／器物入口，配置自愿使用的战备
  → 锁定双方快照，自动按回合结算并展示触发
  → 胜负／撤退／切磋结果及真实消耗按既有路径回传
```

建议人物页提供长期保存的常用布阵；战前确认页允许查看和调整本场方案。用户确认战斗中在所有参战者遍历结束后可以调整布阵；是否采用可预约的整理窗口仍待确认。自动施展和自动目标仍是战斗的基础，不要求玩家逐招选招或选人。战前能否依据已公开的对手信息调整、不同遭遇是否允许临时调整，沿原战前流程核对，不借此暴露敌方隐藏信息。

招式盘是**战斗配置**，不是现实行囊，也不是把学会的技能做成需要消耗的实物。秘籍原书、丹药和法宝继续由原行囊与装备管理；布阵只引用角色已学技能、已装备器物或本人实际持有的战备。

## 三、招式盘与位置关系

### 3.1 放置对象

| 对象 | 布阵中的身份 | 原有来源 |
| --- | --- | --- |
| 公共／秘籍／造诣招式 | 一个已学技能的可装配引用 | 原技能、学习记录与资格 |
| 器物主动入口 | 某件已装备器物的技能引用 | 真实器物实例及该实例能力 |
| 丹药／消耗型符箓 | 可选择摆入的真实消耗品引用；如何对应旧战备待定 | 本人行囊及明确允许使用的真实物品 |
| 心法 | 显示在盘旁的主修／辅修被动 | 已学卷章与主辅修，不额外放入盘 |
| 化法 | 用户确认独立占 1 格，定向作用于紧邻的一个合格招式 | 真实化法来源与原适配条件；旧绑定只作迁移及回退，不能与新指向重复生效 |

每种招式分别配置**同时可摆放数量**；达到该招的上限时不能再摆入同招，具体各招数量待设计和确认。网格宽高、解锁方式、各招式形状和允许的旋转方式仍待确认。**旧十个技能槽与新的格子数量不是同一个单位**，不得直接把十槽认定为十格，也不能凭名称或伤害猜测某技能形状。

建议每个放置对象记录稳定来源、占用格、方向和唯一布置身份。放置必须完整处于可用区域、不与其他对象重叠；移动和旋转先预览再确认，取消不改原方案。无法容纳时留在库中，不销毁或降级。用户确认遍历完全空着的格子可额外回复体力；每格回复量须另审，不再沿用旧提案“空格没有效果”。按已选的“一次跑条处理整行”，本行的空格不另各跑一次行动条。

### 3.2 位置如何产生联动

建议使用**有明确来源的定向范围**：只有招式、心法、化法或器物明确写出可作用的相邻格／指向格时，位置关系才产生效果。摆得近本身不默认加伤、不自动连招；没有位置效果的招式仍可因本身有用而装入。

玩家选中对象时应同时看到占地、方向、影响范围、已匹配目标和实际收益来源；改变朝向或移动后立即重新预览，不能让图示命中而实际不生效。相邻是否只算共边、方向怎样随旋转变化、一个目标能否被多个来源作用，以及覆盖的是格子还是对象等公共几何口径须先确认；具体形状与范围由各对象配置。

**纯结构示例，不是任何现有技能效果：**招式甲声明影响其指向区域内的招式乙；摆放时乙进入范围，系统在乙上显示甲的明确追加。若乙移出范围，追加消失。甲、乙的形状、实际追加与数值都不由此示例定案。

### 3.3 身份与联动边界

- 招式、秘籍与实例身份不能只按显示名称匹配；有化法或器物来源时，预览和实算都读取同一来源。
- 现行关键词主要用于检索，不能因为一个对象标了某关键词就让它获得隐含加成。新范围若要匹配关键词，必须在配置、运行和玩家文案中明确支持。
- 同招可按该招的摆放数量上限摆入多份；每份是独立位置的摆放对象，各自在每个共同回合最多成功发动一次。同一份招式覆盖多个格子仍只有一个摆放对象，不因多格产生额外份数。若该招设有总次数，同一角色的同招多份共享并消耗这一个总次数，不同角色不共享；总次数恢复时机及念、原冷却、化法如何关联仍待确认。当前念规则规定同一技能在多个旧技能槽中读取同一份念；本次总次数共享由用户另行确认，不擅改旧念或删除旧重复引用。
- 位置变化不改变人物世界坐标、攻击距离或地图移动；不新增战斗射程或位移规则。

### 3.4 战斗中调整布阵：方向与边界

用户确认：**所有参战者遍历结束后**再调整背包。每个角色按各自盘面的从左往右、从上往下顺序遍历；角色沿旧行动速度跑条，到点处理自己下一整行，速度快时可能连续多行。不是某个角色先处理完整盘就开放整理，也不是每次出招后调整。战斗仍自动施展，不要求玩家手动逐招操作。

**已确认整理时机；具体入口仍为建议。**一轮内所有参战者按已确认的行动条和整行时序遍历各自盘面；建议本轮嵌套事件、回合结束效果和胜负检查完成后，若战斗仍继续，再开放整理，确认后才开始下一轮。战斗若已在遍历中结束，则直接按原终局规则收尾，不等待无效的后续遍历。建议顺序为：

```text
第 N 回合各参战者按行动条到点遍历各自下一行，自动行动与应对
  → 所有参战者遍历结束
  → 本轮结束效果、胜负检查
  → 若玩家预约则暂停并整理；否则直接继续
  → 第 N+1 回合开始：各角色体力补给、更新符合已确认口径的轮次状态
  → 各角色按行动条自动处理各自下一行
```

建议入口与反馈：

1. 默认全程自动连续运行，不强制玩家每轮确认。玩家可以在本轮行动中点击“本回合结束后整理”，界面标记已预约；当前回合继续到上述边界。若此前战斗已经结束，则直接进入结果，不开放事后战中整理。可以取消预约。
2. 为不要求玩家拼反应，可选“每回合结束后暂停整理”；玩家也可以保持默认自动连续。普通暂停仍用于冻结和观察；若在普通暂停期间预约轮末整理，需先继续执行完本轮才能到达整理窗口。
3. 进入窗口后暂停推进，允许移动盘内对象、换入本人已学招式和补入本人真实持有的丹药／符箓，并按经确认的摆放规则处理旋转；预览并确认整套布局后，从下一回合使用新位置。取消拖动或放弃修改保留原布局。新旧战备位如何衔接、预留及移除在场法宝的行为另行确认；符箓须在对应内容正式开放后才能实际使用。
4. 建议本次先不对整理本身收取体力或法力，也不因操作时长额外推进回合；是否限制整理次数、是否引入其他代价留待测试和用户确认。对手与队友何时可调整也要遵守相同战斗边界，具体 AI 策略及信息可见性待确认。

**时机影响**：轮末整理不会打断攻击与应对，但玩家请求整理后本轮仍要继续，不能用它阻止尚未结算的本轮来袭。自动预约、逐轮自动暂停及调整本身是否免费均是候选交互，不能因时机已确认就视为已决定。

按已确认的回合间时机，还需要为调整保留以下核对边界，作为实施候选而非已实现功能：

- **同一对象移动与换入**：招式的真实来源与摆放对象应可追溯，移动或旋转不能平白刷新旧冷却与已用次数。同招多份共享总次数；旧冷却和念如何关联须按最终规则处理，不能假定各份共享或独立。换下后再放回不能凭操作自动恢复总次数，实际恢复时机待确认。化法独立占格，移动后按新方向与相邻关系重算目标；旧绑定只保留作迁移／回退。器物还保留该实例的在场状态和器体。
- **影响何时生效**：移动后的相邻关系只能从经确认的生效时点向后影响；已完成的伤害、费用、状态和已消耗物品不倒算。被改变位置影响的持续效果，需区分“只在接触时存在”和“已施加、按时长存在”，逐项依来源定义，不能一概删除或重施。
- **行动遍历与同一招式**：按已确认的从左往右、从上往下遍历；该摆放份的每个占格分别检查同一份，最后占格之后本轮不额外补查。未成功时后续占格可继续检查，成功后后续占格虽仍检查，该份本轮不能再次成功发动；同招另一份有各自本轮资格。移动在所有人本轮遍历结束后进行，不能因换位置重复结算已完成的行动，也不能将多次检查误作多份技能或角色总出手上限。
- **丹药与符箓**：已实际消耗的物品不会因为移动、撤销布局或切换方案而恢复；用户允许战中补入本人真实物品，未消费物品的预留、回收与旧战备限制如何衔接仍需确认，不能复制或自动生成库存。
- **法宝**：已经召出的器体、剩余器体与持续灵识占用 D 不能因拖动刷新或复制；从盘面移除一个已召出器物时是保持在场、主动收回还是禁止移除，须确认并明确 D 的释放时机。不同选择不能靠 UI 直接删状态。
- **原子与结算**：拖拽取消、无效落点及退出编辑不产生费用或改变正式布局。若允许在结算中请求调整，必须明确当前攻击及嵌套应对、多段、周天完成前后由哪个布局生效；不把半次拖拽当成已经生效。

所有人遍历结束后的整理时机、换入已学招式及补入真实丹符已确认；预约、可选的自动暂停及整理本身不额外收费仍是推荐，尚待用户确认；预留、旧战备限制及整理次数待确认。固定整理次数、体力费用或自动补货不在本案猜定。

## 四、建议的自动回合时序

### 4.0 参考游戏与出手顺序的历史比较

《背包乱斗》战前整理背包；战斗时物品有各自的时间间隔或事件条件，会按自身进度自动触发。它并非规定双方一人从左到右处理完整盘、再换另一人，也不等同逐格轮流；这里的观察以[物品冷却机制说明](https://backpackbattles.wiki.gg/wiki/Cooldown)及[游戏机制说明](https://backpackbattles.wiki.gg/wiki/Game_Mechanics)为依据。本机虽已安装该游戏，本轮没有重新实玩，不推断同一时刻所有物品的精确排序。它所称的准备与战斗阶段也不能直接当作本项目现行的“完整战斗回合”。

位置联动与用户希望的“从左往右、从上往下”和回合结合，按本项目确认的逐格检查处理。下面的编号只是位置示意，不代表招式费用或具体参数：

```text
              [甲3] [甲4]
遍历顺序：    甲1 → 甲2 → 甲3 → 甲4
```

| 候选 | 单挑时的直观顺序 | 优点与待解决问题 |
| --- | --- | --- |

### 4.1 全场回合与按行动条逐行处理

按行动速度到点处理一整行、快者可能连续处理多行已确认；以下细节及轮末事件顺序仍须审阅：

1. **回合开始**：存活角色依既有回合开始接口处理状态、轮次次数与资源补给；按已确认规则更新每份的本轮发动资格。另行配置的触发总次数是否在此时恢复及其他恢复时机待确认，不能自行设定。
2. **确认可用条件**：按本轮状态、实际费用、合法目标、原有冷却和各项次数判断该份是否可施展；实际触发检查发生在遍历占格时，状态展示不另造发动机会。
3. **行动条与逐行遍历**：各角色按现行行动速度并行积累人物行动进度，建议先复用原阈值与同到点顺序。角色到点后处理自己尚未处理的下一行，行内从左往右；经过普通招式的每个占格时分别检查该份，在本轮尚未成功发动、如有总次数则尚未耗尽，并按其确认的触发方式满足费用、目标及其他条件时发动。成功后该份其他占格仍检查，但不能在本轮再次成功发动；同一角色的同招其他份各自检查本轮资格并共同消耗该招如有的总次数，不同角色分开。经过应对招式占格后该份进入本轮待命，待命本身不计成功；真正成功应对才消耗该份本轮机会和该角色该招如有的共享总次数。真正空格按最终确认的空格回体规则处理。多格招式跨行时，各占格分别在所属行检查；空格与其他格子属于同一次整行处理，不各自额外跑条。处理完成后继续走条，速度快的角色可领先或连续处理多行；处理完整盘者等待其他角色。旧机制每项行动各跑一次条，新方案一次到点处理一行，二者频率不等价。
4. **嵌套事件**：来袭攻击、多段、周天及心法触发按各自规定结算；一组效果完整结束后才进行下一项普通行动。应对走格后待命，待命期间有合法来袭时按盘面顺序选择已待命且合格的应对份；同次攻击最多成功触发一个应对。心法不再自行自动应对，但招式应对后原有心法被动保留；首项概率失败处理仍待确认。旧效果若可能令同一摆放份本轮再次施展，其与每份限次的冲突须逐项审阅；同招其他摆放份的每轮资格各自计算，不擅自设例外，也不自行删除原效果。
5. **回合结束**：所有参战者完成本轮各自的盘面遍历时，本轮应对待命结束；已触发事件的收尾与回合结束、状态时长的精确顺序仍待确认。战斗继续时在下一回合前开放整理。普通招式的最后占格已遍历后，即使本轮条件随后变化也不额外补查；在全员走完前，已待命应对可按确认规则响应来袭，不视为普通补查。待命应对及等待未来事件或资源的物品／招式不阻塞本回合结束。胜负在当前结算组结束并满足原终局检查后立即结束战斗。

同一行及同一回合均可由同一角色施展多份符合条件的招式，因此不把“人物行动条到点一次”当成整场或整个回合的总出手额度。行动速度影响人物跑条；各招不另设通用倒计时，不能暗中改变原属性公式。

**一轮示意，不指定实际速度：**甲行动条先到点，按从左到右处理甲第一行中招式的占格与空格；若之后甲的行动条又先于乙到点，可继续处理甲第二行，再轮到乙处理乙第一行。应对及周天按照各自确认的触发规则嵌套结算；甲先完成盘面后等待乙也完成，战斗仍继续时才进入整理窗口。每个人每轮基础体力补给只结算一次；空格的额外回复量仍待定。

**跨行招式示例：**仅为说明顺序，假设一个两格招式甲竖向占据第一、第二行，第一行还存在空格：

```text
第一行：[甲上] [空格] [其他]
第二行：[甲下] [其他] [其他]
```

遍历甲上时，甲因体力不足未发动；之后经过第一行的空格回复体力。到第二行的甲下时，系统再次检查同一份甲；若此时体力、目标、次数及其他条件均满足，则甲可在甲下发动。若经过甲下时仍不满足，即使随后体力增加，本轮也不额外补查甲。反过来，若甲上已成功发动，则经过甲下时仍检查同一份甲，但因本轮已成功发动而不能再发动。甲上和甲下均不是空格，也不是两份招式；此例不决定每空格回复量。

### 4.2 逐格检查、总次数、冷却与失败

用户确认不设招式通用等待进度；遍历到占格且各项条件满足时立即发动，不再为每个招式额外配置统一倒计时。原本具体招式若有已定义的冷却或特殊触发，仍需逐项审计迁移，不能因取消通用等待而删除原规则或猜造新数值。

遍历到每个普通招式占格时，检查该摆放份本共同回合是否已经成功发动、该招若有总次数是否耗尽，以及现有原有限次、回合冷却、费用、合法目标与技能自身条件。应对招式走到占格后进入待命，不计成功；来袭时按第四节已确认的盘面次序判断，成功应对消耗该份本轮机会及该角色该招如有的共享总次数，原费用和效果保留。每份本共同回合最多成功发动一次，普通招式成功后按原技能规则扣费、计次并处理其明确的冷却；下一共同回合能否发动仍须检查当时条件。成功发动如何认定（例如被打断、未命中时）也需单独核实，不能仅因走过占格就计成功。

部分招式配置触发总次数；同一角色已摆放的同招多份共同消耗这一份总次数，耗尽后该角色所有同招摆放份都不可再用，图标变暗并标明“次数耗尽”。不同角色分别记录和消耗各自的总次数，不共用池。图标仍占原格，不作为空格回复体力。没有配置总次数的其他招式不因本条自动增加总次数限制。具体各招数值、总次数何时恢复及持久化范围仍待确认；检查经过但未触发不能仅凭经过格子扣次。

**共享次数示例，只用用户举出的 3 次说明，不为任何现有招式指定数值：**假设某角色的某招可合法摆放甲、乙两份，且两份总共剩余 3 次。所有费用、目标等条件均满足时，甲、乙可以在本共同回合各成功一次，共用次数剩余 1；假设进入下一个共同回合时尚未发生次数恢复，若先由甲成功发动，剩余次数变为 0，甲、乙两份都变暗且不可再用。其他角色的同招不消耗这一池；次数何时、如何恢复仍待确认。

没有合法目标、体力不足、法力不足且没有明文允许的替代支付方式、灵识峰值不足或技能条件未满足时，不支付、不计次；其他合法招式仍可行动。该份若还有未遍历占格，到达时按当时条件再次检查；最后占格之后本轮不额外补查。每次检查失败不等于一次实际行动；实现须防止在同一状态下无限重试。目标死亡后的选择、多个合法目标的自动策略，需要明确配置并遵守现有敌我与技能目标规则，不能读取未揭示的敌方内部信息。

自动追加施展、应对和周天等旧效果与“每摆放份每个共同回合最多成功发动一次”及共享总次数可能冲突时，连同是否构成一次独立招式发动一并列为待审，不能自行建立例外、删除原效果，或私自改变玄枢的原费用与递归保护。

### 4.3 无总出手上限、休整与防循环

用户已明确：**招式每个摆放份每个共同回合最多成功发动一次，不设角色每回合的总出手次数上限**。同招不同摆放份各有本轮成功次数，但若该招设总次数则共用并消耗同一份总次数；不同招式、应对、服丹和器物行动不共享一个 5—10 次的每轮角色额度。招式还须满足费用、目标、原有冷却与触发条件；丹药、符箓和法宝是否有各自限次按其专题另行确定。同一回合有多少实际施展取决于摆放份和具体效果，而非角色总次数上限。旧空行动位要独立等待却不回复，新盘真正空格在整行处理期间额外回体力；空格回复量以及新旧每轮出手频率差异都须重新平衡。

招式的盘面遍历检查次数由该份实际占格决定；同一份第一次成功后，即使仍有后续占格或条件变化，本轮也不能再次成功发动。若同招摆了另一份，该份的每轮资格独立，但同时受该招如有的共享总次数约束。旧有额外施展、复制和周天自动施展若会令同一份同回合再次发动，或影响共享总次数，与新规则的冲突须逐来源审阅，既不直接宣布例外，也不直接删除旧效果。出现能在同一事件中无限反复自触发的配置时，应在配置验证阶段报错并阻止该配置进入战斗；不能靠一个静默的角色总次数上限截掉本应发生的效果。

一次招式发动内的原有多段效果，要与另一次招式发动区分。例如[《乘势再攻》现行结算边界](../../秘籍词典/md/太和感物养元宝册.md#结算边界)已写明其追加攻击不额外消耗技能使用次数；不能把“每招一次”理解为只能结算一段伤害，或因此直接删去原有追加段。其他复制或额外施放是否构成再次发动，仍按各来源逐项确认。

休整仍以现行自带系统行动、回复 2 体力、不占技能装备位置为迁移来源；没有通用法力回复行动。无队列后，必须给自动休整明确的自身触发与推进节奏，不能因为体力未满便在同一结算瞬间连续免费休整到满。建议只在有可预见用途时自动考虑休整，其何时就绪、同轮是否可再次触发以及是否需要盘面位置均待用户确认。休整无需共享角色总出手额度，但这与旧规则的时间成本不等价。0 费与返费仍按来源限制审计；旧额外施展可能与单招限次冲突，须另审。

### 4.4 应对：走格后待命，按盘面顺序选择

用户已选择[方案 A](逐格招式盘与受击应对候选_20261106.md)：**走到应对招式占格后，该份进入待命；待命持续到所有参战者完成本共同回合遍历时结束**。该角色先走完整盘，其他参战者仍在遍历时，这份应对仍可对符合条件的来袭参与判断；最后占格之后的来袭判断是已确认的待命事件，不是普通招式回头补查。与最后结算组收尾、轮末效果及整理的精确先后仍待核对。

一次来袭有多份应对招式同时待命且符合条件时，按当前盘面**从左到右、从上到下**选择。多格属于同一摆放份，可用最靠前的实际占格定位该份顺序；这只是选择顺序，不因多个格子生成多个应对，也不改变每个占格各检查一次的规则。用户明确：**同一次攻击最多成功触发一个应对**；待命本身不计成功，成功消耗该份本轮一次机会及该角色该招如有的共享总次数。

所有心法不再自行发起自动应对，因此不再有心法与招式应对的优先级问题；首项概率失败后能否尝试其他来源、群攻的每个受击者是否各有名额、多段攻击如何归组仍待确认。

旧规则中攻击来袭先判定整招规避及首个伤害段闪避，新方案是否沿用这一命中边界仍待审阅。应对与来袭的结算关系及原有效果、化法仍须按具体技能逐条核对；不能凭选择待命就改写原有攻击、伤害或费用。原《架招》仍针对物理攻击并获得原有化解；《虚怀纳劲》仍按其原条件获得护盾。若旧应对招式确有独立普通分支，何时使用普通分支与应对须逐招确认，不能将两分支都自动施放。

百骸原第三、四卷心法自动应对及该事件附带的化解、气血回落在新方案中取消；显臂、近身追加、主修加成及架招化法保留。太和在招式应对后按原条件获得气血是被动收益，并非自行发起自动应对，也予以保留。旧正式代码、主图与资源仍实现／描述百骸自动应对，尚未迁移；[受影响位置及太和原事件差异](逐格招式盘与受击应对候选_20261106.md#六旧实现与图文的迁移审计)须在实施时核对。针对服丹／休整等“破绽”的应对仍是未接入提案，不能因为现在取消队首就宣称已经实现。

- 用户确认体力先按共同回合每轮 +3、基础上限 6 及余额保留；法力开战按有效容量初始化、跨轮保留，不因回合自动回复，继续使用周天和原本明确的回复效果；灵识仍是持续 D、临时 T 和其他占用共享的容量。不同新旧回合长度导致的数值表现必须单独验证。

| --- | --- | --- |
| 体力 | 每个完整旧回合开始回复 3，基础上限 6；未用余额保留 | 已确认每个共同回合开始为每名存活角色各结算一次原补给，施展每个招式仍支付该招体力；不因每次遍历格子或每次出手重复补给 |
| 休整 | 自带系统行动，不占技能槽；每次回复 2 体力，上限内有效；旧队列中占一个行动位 | 自动触发与自身节奏待设计，可在有后续体力需求时考虑；不能因无行动总上限就无限瞬间补满 |
| 法力 | 战斗开始按有效法力容量初始化，跨回合保留；不按回合自动恢复 | 保留原身份和支付；只有具体技能或明确效果可以回复 |
| 炁与周天 | 当前有效法力上限为 M 且 M>0 时，炁达到或超过 2×M，清空全部炁、法力回满至 M，再结算周天效果；超出炁不保留 | 保留原公共机制、事件顺序及防递归限制，不因换成布阵自动给炁；容量改变时按原条件重算 |

“共同回合”由全场共用：建议所有角色本轮应处理的行及可立即结算事项完成后才进入下一轮。已选行动条到点处理整行，每名角色的基础体力补给只在共同回合开始时结算一次；处理真正空格的额外回复另行结算。普通招式的资源条件在其每个占格到达时按当时状态检查，最后占格之后本轮不因资源变化额外补查；应对走格后待命至全员遍历结束。

### 4.7 真正的空格与体力

用户确认：每个共同回合开始仍按原规则补给体力 3 点；遍历盘面时，**完全没有摆放任何招式或物品的空格**还会额外回复体力。已有对象但因本轮已发动、总次数耗尽或其他条件不足而没有发动，不属于空格；多格对象占据的每个格子均不是空格。回复受实际体力上限约束，已有余额保留。每个空格的回复数由盘面尺寸、招式及丹符占格、现有技能费用和可复现的样例共同平衡，尚未确认，不从旧休整数值直接推导。

若某行先经过空格，再到需要体力的招式，空格增加的体力可能使该招满足费用；若先经过招式的一个占格，因体力不足未发动，随后经过空格，则在该份仍有未遍历占格时，可到达后续占格再检查。若该份的最后占格已过，本轮不因后来回体额外补查。实现需避免同一空格重复生效、背包移动刷新、超过上限或因没有可用招式就跳过整盘的空格回复。空格在整行处理内不额外各跑一次行动条；它与原休整行动如何共存仍待确认。

**说明性例子，使用原有数值而非新招式参数：**甲在共同回合开始后体力为 3/6；假设遍历到《应敌》时满足全部条件，支付 1 体力后为 2/6，再施展《痛击》支付 2 后为 0/6。若还有只缺体力的招式，后续只能在该份尚未遍历的占格处按当时条件再检查；之后可否自动休整以及休整何时触发取决于待确认的休整规则。若没有本轮其他体力来源，进入下一个共同回合后才获得下一次 3 点基础补给；不是甲每打一招都回复 3。两招若在同一行，乙的普通行不插入其中；若分属不同行，两行之间可以轮到乙。例子不决定这两招的占格。

新回合的长度和每轮招式数量与旧队列不同，所以每轮 3 点是否足以支持新节奏、是否会让休整过强，须在确定时序后用原值测试再请用户决定，不先猜修改数值。没有炁来源或法力回复效果的构筑不会因新回合自动恢复法力。

## 五、秘籍、心法、招式与化法

### 5.1 四者职责

| 层次 | 决定什么 | 迁移建议 |
| --- | --- | --- |
| 秘籍与卷章 | 学习资格、已授招式、心法版本、修持和化法来源 | 原学习进度、主辅修、灵根和分支保留 |
| 心法 | 开战后持续生效的流派规则 | 仍随当前主辅修生效；若未来影响盘面，只通过该心法明确写出的范围和条件 |
| 招式 | 按条件施展的具体技能 | 沿用原目标、费用、效果与限制，另配置经确认的形状、同时摆放数量及需限次招式的总次数；旧特殊触发逐项适配 |
| 化法 | 对指定技能的明确追加或改写 | 用户确认每项占 1 格，以方向指向紧邻且符合原范围的一项招式；效果及来源资格不变 |
| 修持 | 战斗内属性修正 | 原来源与详情继续保留，不把它擅自转换成格子数量或人物永久属性 |

一本秘籍现行提供 1—3 项不同专属战斗技能；公共基础技能、心法、化法和大世界术法不计入。新构筑机制不要求每卷都提供一招，也不因盘面有空位就给旧秘籍补招。

建议未来分别设计三种协同抓手：招式自身提供明确方向／区域；心法响应符合其文字的战斗事件，或在明文范围内改变招式关系；化法改变指定招式的具体效果／作用范围。三者可以组合，但同一个收益的来源须可追溯，不能仅因为同书或相邻重复叠加。所有新联动属于后续逐本审阅，不在本提案直接添加到现有技能数据或玩家文案。

### 5.2 需要逐条改写的旧接口

| 旧接口或实例 | 为什么不能直接照搬 | 迁移处理 |
| --- | --- | --- |
| 队首应对、普通分支及免费空放 | 不再有唯一队首 | 已确定走格后待命至全员遍历结束，盘面应对按从左到右、从上到下选择；待命不计成功，应对成功计本轮机会及共享总次数；逐招核对原费用和普通分支 |
| 念赋给后续队列中的某技能 | 未来队列位置不再存在 | 为每个具体来源提出明确的新选取对象，可能是指定对象或明确的盘面范围，用户确认前保留待迁 |
| 玄枢第十槽周天自动施展 | 旧第十槽是固定技能位置，新格子不是槽序；每份每回合一次可能与周天再次施展冲突 | 建议在盘中显式指定一个符合旧限制的周天对象；是否占格、与每份限次及共享总次数如何衔接待确认。原非应对、付费、合法目标及递归保护保留为审计依据，不擅设例外或删除效果 |
| 复命与其他复制／下一次技能效果 | 复制目标、执行顺序可能依赖旧行动历史或队列，也可能与每份每回合一次冲突 | 以原可复制对象、费用、次数和随机目标边界逐条审阅，确认新时间点及是否构成同一份的再次发动、如何影响共享总次数；不擅设例外、不删除原效果，也不复制预测行动或循环自触发 |
| 斫基燃烧法力上限及化法 | 自动触发可能发生不可逆的本场资源代价 | 清楚展示原代价并确认自动使用策略；不在迁移时改费用、转化或上限 |
| 百骸气血、显臂与太和应对 | 依赖原状态、出招风格、命中及应对事件 | 继续订阅原事件，只迁移事件如何被调度；新位置效果另审，不凭盘面自动增益 |

新旧回合不是天然等价。所有“每回合首次”“下一回合”“持续 N 回合”“自身回合开始”等效果要列出来源、旧触发点与新触发点，连同冷却一起检查；未完成确认的效果不能靠默认事件名静默接入。

对依赖后续队列的“念”，优先提出两种可核对的迁移候选：其一，战前由玩家为赋念来源指定一个符合条件的盘面招式；其二，由明确的指向区域决定符合条件的招式。两者都需定义无合格目标和多个合格目标时的处理；也可另行讨论是否改为下一次实际成功施展的合格招式。它们会产生不同构筑和时序，不能自动等价迁移，待逐来源审阅。

对玄枢原第十槽，候选是把原本的合格招式放入盘面，并由玩家显式标记为“周天施展对象”；原有的非应对限制、费用、目标和递归保护须作为审计依据。普通自动施展是否禁用、周天发生时如何与单份每共同回合一次和共享总次数衔接，以及该特殊施展是否构成招式发动，都须确认后才能定稿；不能将候选写成已定例外或直接删除原效果。形状、旧档对应及该特殊施展与占格检查的关系也仍待确认，不能自动绑定新对象或改动原技能。

### 5.3 一套已有秘籍如何迁移：百骸示例

此例只说明已有关系如何进入新时序，不新增百骸的盘面加成，也不指定任何招式的摆放上限或总次数。假设角色已满足《百骸衍枝化生宝册》及相关招式的学习与装配条件，并已选择相应主辅修与化法：

1. 战前将已学的《催血》《血臂撼岳》放入招式盘。秘籍仍提供心法；角色也可把具备原资格的一格化法放在《催血》旁并指向它，两招具体形状和位置待定。
2. 战斗中，遍历到《催血》且满足其条件时按自动规则发动，按现行技能效果获得气血；若指向有效且符合原化法条件，再结算该化法的明文追加。
3. 气血达到该角色已学心法版本的显臂门槛后，心法按现行规则显化手臂。之后遍历到《血臂撼岳》且满足费用、目标等条件时自动施展；近身物理攻击的手臂追加段依该心法实际版本结算。
4. 若本书的《血臂撼岳》化法来源合法且其一格对象正确指向紧邻的该招，并满足原条件，再按化法原文结算追加段；该段与心法手臂段各有来源，不因两张招式相邻而再加一次。

这个例子保留了“招式产生气血—心法读取气血—另一招受心法及正确指向的化法影响”的原有构筑。两招遍历时能否各自满足条件、第一次能否在同回合配合，以及移动位置是否产生未来明确的新效果，都要由新规则和逐招配置决定，不能仅从图上左右顺序断定。

## 六、丹药和其他消耗品

### 6.1 现行事实

现行每名角色的战备为 3 位，每位最多预留 5 颗同一正式物品；从本人真实库存预留，服丹只作用于本人，占一次行动位，不额外支付体力／法力／灵识。实际使用前检查存活、库存和有效条件；确实生效才扣一颗、增加对应丹毒并在战后回传。首批战斗可用包括回春、凝罡、金肌、轻身、续生、接骨、和中；纳灵、返元是大世界用途，通脉和静心仍下架。完整药效、五档及丹毒以现行专题为准。

### 6.2 自动布阵候选

用户提出丹药和符箓都作为一次性物品，且已确认战中整理时可以补入本人真实持有的丹符。建议两者使用同一套**真实物品引用与单次消费流程**：每个盘面对象代表本人实际预留的一颗丹药或一张符箓，成功使用该件后该对象耗尽；其占格何时释放仍待确认。由玩家在整理时选择真实库存，不把盘面图标当成无限次数。是否另支持自动补充待确认。若玩家摆入多件，必须逐件预留，各自只有自己的剩余件数和触发状态，不复制药效。未触发的物品仍由本人保有。

这是具体的盘面候选，并非已确认的战备迁移：旧设计是丹药与消耗型符箓共用 3 个战备位、每位最多 5 件同一物品；现行丹药已接入，消耗型符箓尚未开放。若新盘改成每件独立摆放，需要确认它与旧 3×5 限制的关系：保留旧位限制并将预留件逐个映射，或改为由新盘面约束。不能在载入旧档时自行解除上限、把一堆仅变成一颗、自动消耗、或丢掉多余物品；未映射部分保留为可见待摆放内容。

盘面显示物品名、实际品质／丹效、使用条件和消耗状态。玩家战前明确选择要带哪些真实物品；是否仅摆入就意味着授权自动使用，或还要配置额外开关／阈值，待确认。没有授权时不因自动战斗擅自使用。符箓的形状、效果、可用目标、费用、触发条件及消费时机均需符箓专题确认；旧资源文件中的符名不等于已经开放可消耗符箓。

每种药只有在其**真实效果可能合法生效**时才进入候选，例如生命有缺口的回春、存在对应伤势的接骨／和中。是否采用生命阈值、开战使用、对已有药效的覆盖策略，以及多个丹药同时满足时的先后，都需要玩家可见的策略与明确默认值；具体阈值不在本案猜定。沿旧战备方向，不因改成自动战斗而给全部丹药额外添加统一的每回合或每场使用次数上限。

已授权的丹药仍要在实际使用时检查本人存活、原物品、库存及药效条件；**实际生效才扣一颗、增加该丹毒并记入战后回传**。库存不足、条件已失效或角色死亡时不扣。服丹是系统物品使用，不自动视为施展招式、应对或可复制技能；实际治疗、护盾、气血或炁变化仍可触发对应现行事件。同一回合可以依次使用多件已授权且各自满足条件的物品，前一件生效后必须重新检查后一件；例如第一颗回春已补满生命，后一颗不再合法使用。自动触发的具体节奏、多个就绪物品的顺序和被应对／打断仍需明确，不能把“使用一颗”变成“生成一份免费药效”。

一次消耗事务须唯一登记并防重：战前预留不扣库存；确认成功使用后扣对应的一件；战斗提前结束或物品未触发则保留；撤退、失败或胜利均按实际消耗回传。视觉消失与真实扣除以同一次确认结果同步，不以动画是否播放作为扣除依据。丹药品质、炼制与世界效果不因本案重算。

### 6.3 丹药和符箓的区别

“一次性”描述两者共同的物品生命周期，不决定效果相同。建议保留不同的设计重心，但不设互相排斥的效果禁区：

| 维度 | 丹药 | 消耗型符箓（方向提案，尚未定稿） |
| --- | --- | --- |
| 来源 | 炼丹或其他真实取得方式 | 制符或其他实际开放的取得方式 |
| 使用 | 现行战斗丹由本人服用，作用于本人 | 按符箓明示目标生效，可设计为对己、友方或敌方；不预设所有符都攻击 |
| 代价 | 实际生效才消耗一颗并按药物增加丹毒，原有费用规则保留 | 消耗一张；是否另有体力、法力或灵识费用由具体符箓规定，不因类别自动免费或自动收费 |
| 效果重心 | 药效、调养、强化或状态，具体以丹药原文为准 | 事先写入的一次性术式，可设计为攻击、防护或辅助；具体效果和数值待符箓专题 |
| 等待／触发 | 依据丹药可用条件和获准的自动策略 | 依据该符明示的使用和触发条件；是否支持被动等待和自动目标须逐项配置 |

丹药不只是回血，符箓也不只是打伤害；二者可以都有护盾或其他相同结果，区别来自实际来源、目标、触发和代价。对符箓建议在合法施用成功时消耗，命中失败是否仍消耗、被打断是否保留以及是否触发招式事件须由符箓专题明确，不能套用丹药的“药效实际生效才消耗”。没有正式战斗用途或使用规则的物品不能因进入格子自动生效；现行“破绽”应对提案也仍未实装。

### 6.4 在新战斗中的具体处理示例

以下只用现有回春丹规则和抽象符箓说明流程，不新增任何正式符箓或数值：

1. **战前**：玩家选择本人真实持有的回春丹与未来可用的符箓，按最终确认的旧战备／新盘规则预留。预留、摆放、移动或预览都不扣库存。
2. **丹药候选**：当已配置且合法的自动用药条件成立，核验本人存活、对应丹药仍在预留中、生命确有缺口。回春实际治疗按原丹效、丹毒和受疗规则计算，成功生效才消费该颗、累计对应丹毒；若在轮到它前已被其他效果补满，保留该颗。
3. **符箓候选**：未来若某张攻击符具备已确认的自动触发规则、费用和单体敌方目标，系统按用户确认的随机合法敌人规则选目标；没有合法目标或未满足支付条件则不施用、不因预览扣符。合法施用之后若被闪避是否仍耗符，建议定义为施用成功即消费，但须在符箓专题确认，不能把该候选冒称现行规则。
4. **效果与盘面**：使用后该件真实物品不再可触发；已使用对象的空间、作用范围何时更新，与战中是否允许整理共同确定。该物品先前合法产生的持续状态不因图标消失自动撤销，除非具体效果明文规定必须持续存在。
5. **战后**：按实际确认的每次消费和唯一物品记录回传，胜利、失败与撤退都不能重复扣减；没有用掉的实物继续保留。丹毒只随实际服用结算，不能把符箓消耗自动当成服丹。

多个丹或符在同轮都准备好时，不存在共享的角色总出手额度；按最终确认的行动顺序逐项检查。前一件会改变资源、生命或目标，后一件须基于更新后的状态再判定，避免满血重复服丹或攻击已经死亡的对象。

## 七、装备、法宝及其他持续实体

装备仍引用实际物品实例，常规装备／手持本身不占灵识。法宝的装备收益、器蕴、化法、直施和御用分别按各自来源生效，不能因物品显示在招式盘而重复获得一份属性。

建议将已装备且确有御用能力的器物入口摆入招式盘：

1. 开战时显示未召出分支；轮到该器物行动且条件满足后，尝试召出。
2. 召出成功才建立器体和在场 D；同一布置对象切换为在场御使分支，不另占一块盘面、不复制器物，也不凭切换刷新原次数和冷却。
3. 在场主动施法检查真实目标、费用及 T；T 在该次施法结束释放，D 随在场持续。召出是否另需 T 仍按该器物模板明确配置；不为缺失模板猜费用。
4. 召出失败不扣不该扣的资源，不能假装在场或免费施放御使。器体崩解、主人死亡、离场与战斗结束时按原接口清理 D／T；是否再次召出及重试策略待确认。
5. 直施型能力不强制先召出；实际引用已装备本剑的物理剑招才使用该剑锋锐。成套按一个真实器物及其既有结构处理，不按图标或多柄表现复制收益。

原规则中每次召出和御使都占一次队列行动；新案不再有每回合的角色总行动机会，两态如何按各自确认的条件、费用和原有冷却尝试仍需专题确定。召出成功后在场分支的处理、失败重试及崩解后的选择需逐项确认，不能在转换时立刻无限召用或无代价刷新。器物 D/T 相关参数和器蕴尚有已知待定或未完成部分，沿器物主案，不因新布阵接口宣布全部实装。

候选状态流用于审阅具体边界：

| 器物状态 | 盘面显示及自动行为 | 灵识和持久化边界 |
| --- | --- | --- |
| 未召出 | 同一真实器物入口显示召出分支；按该分支确认的触发条件尝试 | 装备本身不占 D；实际召出前检查目标、费用及该模板明示的峰值 |
| 在场 | 召出成功后原位置显示其真实在场技能；达到条件后自动御使 | 器体在场占 D；每次施法按实际峰值临时提交 T，结束释放 T |
| 崩解／收回 | 不再把该器物当作仍可御使；是否允许再次尝试召出待定 | 按器物主案释放该实例 D，不能顺带扣除或释放其他实例的占用 |
| 战斗结束 | 清理单场召出、器体、D/T与临时状态 | 仍保留本人原器物实例及合法装备；长期耐久或其他影响按对应正式规则处理 |

例如：某件真实已装备的法器因灵识不足未能召出，应在盘面显示原因；不扣未成功召出的费用、不虚构器体，也不把该次失败变成免费御使。之后灵识条件变化时何时重试仍须结合该器物模板确认。法宝效果、D/T 数值及召出与在场分支的触发不能凭这个流程表猜定。

阵旗、傀儡、召唤物和其他持续实体按实际存在的来源和 D/T 规则接入；没有已确认模板时只保留扩展接口，不猜射程、位移、额外行动或费用。多单位各自拥有自身配置与资源，不共享一个人物的资源池；实体是否有独立招式或如何触发仍以对应专题为准。

## 八、自动目标、信息和特殊战斗

### 8.1 不让玩家选人，但每个效果仍有目标

用户已确认：**单体攻击自动随机选择合法敌人，玩家不手动选目标**。系统在每次真实施展时依照该效果原本的阵营、目标数量及其他合法条件自动确定对象。“不手选目标”不是把单体伤害改成无目标或全体伤害；治疗、增益等单体友方效果也不要求玩家手选，其具体自动规则仍需确认。

| 原目标 | 自动目标候选 | 例外／边界 |
| --- | --- | --- |
| 自身 | 施展者本人 | 丹药沿用本人服用，不自动递给队友 |
| 单体攻击敌方 | 从当前活着且合法的敌方候选中自动随机选一人 | 用户已确认；沿现行随机转火的合法候选等概率抽选口径，不能预先抽定 |
| 单体友方治疗／增益等 | 由系统在合法友方中自动选一人 | 随机、优先自身或按实际需要选择尚待确认；不能据技能名字猜目标 |
| 全体／范围明确的群体 | 按原效果取所有符合条件的对象 | 盘面覆盖范围不是战场空间范围；原技能没战场射程时不新增 |
| 随机若干目标 | 按原效果的数量、重复命中与随机规则 | 原文允许重复与否继续分别处理 |
| 应对 | 匹配的来袭者及应对者，按该招原效果分配 | 不把应对的对象随机换成其他敌人 |
| 目标规则特殊的招式／符箓／器物 | 依具体已确认规则 | 缺少规则时标记待适配，不将“不手选”解释为无条件合法 |

自动随机选择单体攻击对象与现行“原目标失效后从合法对象中随机转火”不同：旧规则允许玩家先选，只有目标失效才随机；用户现已选择新方案的首次自动随机。它不会自动集火虚弱敌人；若某个技能明确规定不同目标规则，须另行核对并向用户确认，不能让 AI 暗中读取玩家看不到的敌方数据。

每次施展前先检查自身是否仍可行动、是否存在合法候选及其他前置；真正确定本次目标后，再按原技能费用、限次及灵识规则结算。无合法目标时不扣费、不计次；普通招式须等到该份尚未遍历的下一占格才再次检查，最后占格之后本轮不额外补查。耗尽的一次性物品也不能重新选目标。单次技能已经按原规则锁定的对象在多段间死亡或失效时，如何处理仍按该技能和现行结算接口逐项核对，不能静默为每一段重新随机。自动随机只在实际需要时抽取，界面预览、悬停和重复刷新不抽随机数；战斗记录展示实际目标，便于解释结果。战斗随机种子和判定记录用于复现，不把随机结果预写成必然事件。

### 8.2 可见信息与战斗结果

- 不能把敌人隐藏构筑信息透露给玩家或让敌方自动针对玩家未公开信息；技能自身明定的目标条件仍要合法验证。
- 自动战斗不意味着无条件使用所有资源。丹药、会改变法力上限的技能，以及撤退策略，应在战前清楚展示已启用的行为及其真实代价。现有自动模式默认不为主控安排服丹或撤退；新策略若改变该边界需用户确认。
- 撤退、宗门切磋的非致死条件、正式敌对、战后伤势与物品结果继续走各自既有正式场景和回传；全自动下是否允许战前设置撤退条件、何时实际执行仍待确认。
- 战中应显示本回合、双方角色、行动先后、实际触发的招式及目标、主要资源变化、状态／应对、因条件不足未施展的原因。允许暂停和查看事件记录；视觉特效的持续时间不改变逻辑结果。

## 九、平滑迁移与旧档保护

### 9.1 数据映射

| 现有数据 | 候选新表示 | 保留／待处理 |
| --- | --- | --- |
| 人物十槽 `combat_skill_references` 和兼容路径 | 布阵中指向同一技能／器物来源的对象 | 保留旧数组及其中重复引用，不推断尺寸或摆放上限；新上限、空间不容纳或尚未配置时列为可见待摆放项，不删原记录 |
| 招式资源的 `uses_per_round`、`uses_per_battle`、`max_charges` 与原有冷却 | 原样保留作旧规则和新限次的逐招审计依据 | [旧次数字段](../../../csharp/gongfa/ActiveSkillData.cs)各自的 0 表示该字段不设次数限制；每场次数未配置时仍须核对兼容的 `max_charges`。不能把未配置误作 0 次，也不能把旧每轮／每场次数直接推定成新共享总次数或其恢复方式 |
| `skill_rewrite_bindings` | 作为旧绑定读取、迁移预览和回退依据 | 新盘根据 1 格化法方向与相邻合法性建立唯一生效关系；旧绑定不能同时重复加成，无法放入或原目标无法邻接时保留原记录并提示 |
| 主辅修、已学卷章、节点与修持 | 原样参与布阵资格和开战被动 | 不因改战斗方式补书、补卷章或重置成长 |
| 法宝唯一实例及技能引用 | 以同一实例 ID 显示器物入口 | 不复制器物、重新炼制、改 D/T 或补造主动技能 |
| 本人战备和库存 | 继续引用原物品、档位及实际数量 | 不在迁移时扣药或自动开启用药；不复制战备库存 |
| 旧战斗测试预设 | 可读取原技能与配置，给出新布局草案 | 不覆盖旧预设；无法放下或不支持的条目列出 |
| 世界 NPC 的学习／装配记录 | 基于本人真实已学内容生成新布局 | 可确定地复用已解锁来源；不能补发秘籍、章节或未知能力 |
| 战斗中进度 | 按现行正式存档规则不恢复中途队列 | 不根据旧队列推测新盘面、共享次数、状态或战中结果 |

迁移草案可按已确认的形状、各招摆放上限和新盘容量提供可见的放置建议，并列出放不下、超出上限、不可用、来源失效及需要重新指定的特殊绑定。**生成草案不等于提交**：玩家调整确认后才保存新布局；仍需保留旧配置，以便版本回退、旧预设读取和问题排查。旧档、损坏引用、重复技能、满盘与旧玄枢第十槽必须分别处理，不能静默丢失对象、将额外旧引用当成新学习记录或改变技能来源。

新布局数据应版本化，存盘位置、正式存档版本号及向后兼容策略在实施时结合当时的现行存档链确定；不在提案中猜写新版本。新格式无法安全读取时保留原档并给出明确提示。布局和已确认的物品策略是战前配置；器体、D/T 和旧规则明确为单场的状态按原生命周期处理。新共享总次数何时恢复、是否跨场及如何持久化尚待确认，不能预设开战回满、战后清零或直接写回旧档。

### 9.2 分阶段落地

1. **先定规则并审计**：确认第十节的核心待决问题；对已开放招式、心法、化法、丹药、器物及状态逐条列旧接口与新适配，不修改现行正式战斗。
2. **独立最小验证**：隔离快照、独立入口，只选择已经确认形状／摆放上限／触发和适配规则的一小组技能、一个心法关系；不使用正式旅程存档、不生成正式收益。验证摆放是否有决策价值、自动逻辑是否可读。
3. **扩展物品与多单位**：逐项接入已确认的应对、药品、单件法宝、队友和敌方；回归资源、状态、器体和一次性回传。未确认的对象明确标记不可在试验中使用，不自动套默认值。
4. **对照与平衡**：在相同角色／物品和可复现随机条件下对比旧队列与候选系统的行动频率、资源走势、结算事件及战斗结果；检查不同盘面能否被玩家理解。结果只是平衡依据，不要求战局逐帧相同。
5. **迁移与正式切换**：确认存档、旧预设、世界 NPC、战前页、遭遇／切磋／撤退、死亡和战后结算后，提供可回退切换；经用户确认再替换正式入口。旧技能、秘籍词典、状态展示、NPC构筑及相关专题同步修订，不把提案提前标成已实装。

### 9.3 验收条件

- 摆放、移动、旋转、越界／重叠拒绝、方向范围与实际生效对象一致；真正空格按最终确认的空格回体规则验证，不将被多格对象占据或未触发的格子误判为空。
- 验证每招按已配置的摆放数量限制，超限拒绝，已学同招可摆多份；每个占格检查其所属摆放份而不复制技能。跨行首格条件不足、后续条件满足时可在下一占格发动；首格成功后后续占格仍检查，但该份本共同回合不能再次成功发动，最后占格后条件变化不额外补查。
- 验证同一角色的同招两份每份每共同回合可各成功一次；若该招设有总次数，则两份合计消耗该角色的同一个总次数，耗尽时该角色的所有同招份均变暗且无法发动，格子仍占用；不同角色同招的次数互不影响，无总次数配置的其他招式不受此池限制。恢复时机与持久化按最终确认方案验收。
- 自动对战验证不同招式及同招不同份的合法触发不受角色总次数截断，以及下一共同回合按当时费用、目标、原有冷却和条件重新检查、同轮资源争用、费用不足与无目标；不把跨回合重新检查当成必定发动，全程不要求玩家逐轮确认。
- 在迁移审计中逐条列出额外施展、复制、周天或其他旧效果与单招限次的潜在冲突，确认其发动计数及处理后再验收，不把冲突默认成例外或将原效果静默移除。
- 验证所有参战者完成遍历后才开放整理、轮末效果和提前胜负及确认／取消布局；若最终采用预约和每轮自动暂停，还应验证预约、取消预约、暂停与继续。验证不重复回合补给、不因布局操作擅自刷新次数、不恢复已消耗物品或复制在场法宝，并核对新位置从下一回合生效。
- 验证应对走格前不由该份响应、走格后待命至所有参战者遍历结束，多个已待命且合格的招式按从左到右、从上到下选择，多格仍属同一份并逐格检查；同一次攻击最多成功一个应对。待命不计成功，成功消耗该份本轮机会和该角色该招如有的共享总次数。验证心法不再自行自动应对，而太和招式应对后气血收益、百骸显臂和架招化法保留；命中／首段闪避及首项概率失败按后续确认方案验证。验证回合起止、资源补给、状态时长、周天／念、失败与终局无重复结算或无限循环。
- 验证人物／NPC真实学习资格、主辅修、化法来源和位置变化；不能靠关键词或摆放生成未确认效果。
- 验证丹药／符箓的逐件引用、授权、合法目标与条件、单次扣除、重复事件防重和胜负／撤退回传；丹毒只按丹药实际使用规则增加，不使用时库存不变，世界丹不进战斗。
- 验证器物实例、同槽两态、D/T峰值与释放、失败、崩解／死亡／结束；不因重复入口复制装备收益。
- 隔离旧档和正式格式往返，验证旧技能、特殊槽、化法、战备、装备与 NPC 记录均不丢失；正式遭遇、切磋、撤退和胜负回传逐项验证。

## 十、实施前需要用户确认的关键问题

已确认：战前摆放、战斗全自动、回合结算；取消招式通用倒计时，遍历普通招式占格并符合条件即触发；角色按行动速度跑条，到点处理下一整行，速度快可连续多行，各自盘面从左往右从上往下；每个招式配置同时摆放上限，单份的每个占格到达时分别检查、最后占格后本轮不额外补查普通招式，每份每个共同回合最多成功发动一次；部分招式有总次数，同一角色的同招多份共用、不同角色不共用，耗尽后该角色的同招份全部变暗、不可再用，不同招式不设角色总出手上限；应对招式走格后待命至所有参战者遍历结束，多个已待命合格招式按盘面从左到右、从上到下选择，同次攻击最多成功一个应对，待命不计成功、成功计每份本轮机会及共享总次数；所有心法不再自行自动应对，其他被动保留；所有参战者遍历结束后可整理、换入已学招式和补入真实丹符；轮初体力 +3，完全空格额外回体。以下均为**提案，尚非已定规则**：

1. 战中整理是否支持预约、默认连续战斗及可选每轮暂停，调整的具体代价及旧战备上限；多个角色同时到点的精确处理。所有人遍历结束后整理、行动条逐行、招式逐占格检查和体力基础补给已确认，不再讨论旧 5—10 行动容量作为角色每轮出手总上限。
2. 空格每格回复多少体力、与休整如何共存；各招同时可摆放的具体数量、哪些招式配置多少总次数、总次数何时恢复及其持久化范围；原有冷却与特殊触发如何逐条对应。
