# NPC 四本秘籍自动构筑与队列规划

> 2026-10-21 实施记录。遵循《即时队列战斗系统设计》第6节及当时的四本秘籍词典；2026-11-10起，NPC卷章修持与化法同时生效，不再选择辅修分支。下文旧分支选择记录仅作历史兼容，不覆盖当前规则。

## 一、本轮范围

用户确认：世界 NPC 只优化已有学习记录者，不为无记录修士补发秘籍或卷章；战斗测试提供自动搭配。当前目录仅包含玄枢含章经、斫基损契玄经、百骸衍枝化生宝册、太和感物养元宝册。

构筑和队列分两步：战前从已学内容选择主辅修及技能槽；局内每轮根据当前资源、状态及公开战况重新规划本角色的5—10个行动位。已学卷章的修持与化法一起进入战斗构筑。

## 二、世界 NPC 的学习与装配记录

- `learned_gongfa_ids` 记录已学秘籍，支持当前秘籍名称或资源路径。
- `learned_gongfa_chapters` 记录该书明确学会的卷章 ID 数组，键支持书名或资源路径。只保存书名，不等于完成首卷或全书；缺少卷章时不补猜心法升级或技能。
- `unlocked_skill_node_ids` 保存已解锁公共技能节点，不自动解锁节点。
- `combat_main_gongfa_path`、`combat_sub_gongfa_paths`、`combat_chapter_routes`、`combat_skill_paths` 保存最近一次战前自动装配结果。字段均随 NPC Resource 存档。
- 世界遭遇、切磋、副本及观战等共用 `create_npc_battle_package`：先导入学习记录，再通过正式 Character 装配和快照接口进入战斗。没有秘籍和节点学习记录者继续沿用公共基础技能。

现有世界人口生成器尚未批量填充这些学习记录。本次依用户选择保留这一边界；不能把本次接线描述成全世界 NPC 已学会四本秘籍。

## 三、战前构筑

选择仅依赖自身已学内容与属性，不根据玩家隐藏技能或队列反向配装。选择过程确定，不因同一人物再次进入战斗而随机换书。

- 已学卷章数量与体魄、灵慧、神魂参与主修取舍；主修／辅修资格、灵根兼容和辅修槽数沿用角色接口。
- 百骸与太和优先考虑气血、显臂及应对的配合；玄枢与斫基优先考虑燃烧法力上限、炁与周天的配合。评分属于 AI 内部偏好，不是新的角色属性或额外加成。
- 主修与辅修都应用全部已学卷章的修持与化法，不记录或选择左右支。
- 公共基础技能、明确解锁的公共节点技能和已学卷章技能共同组成候选池；同名技能不重复装配。角色正式解析器合并多本秘籍对同一招式的化法。
- 装配玄枢时，第10槽优先放可支付的非应对攻击／护盾，且不再把同一招式放入普通槽；复命不优先放自动槽。第10槽继续由周天自动施展，不入普通队列。
- 换装过程保留世界人物当前生命、体力、法力及其上限，避免刷新派生属性时重置现场资源。

## 四、战斗测试入口

双方配置栏各增加“自动搭配技能与心法”按钮。

1. 已选择主修或辅修时，按所选秘籍搭配；两项均为空时，从开放四本中推荐一主一辅。
2. 对练学习池按原测试定位使用所选秘籍全卷及公共节点技能；这不写入世界 NPC 或玩家正式学习记录。
3. 生成结果直接填入原主辅修与技能选项，并显示构筑说明。之后可以手动改动；开战不再次覆盖。
4. 自定义体力／法力上限参与推荐。费用和施展资格仍在战斗中按实际状态复核；上限过低不能保证任何流派联动都可运作。
5. 原对练方案保存直接记录生成后的秘籍、技能及资源配置，无需额外开关。野兽配置下自动搭配按钮随修士配置一同禁用。
6. 进入战斗时，测试技能沿用人物正式化法合并接口；主修与辅修应用相同的已学卷章效果。

## 五、局内整段规划

采用有限候选搜索，每一步比较若干种招式和有用休整，保留少量完整草案及尚未兑现收益的铺垫分支。搜索窗口等于角色本段行动位数，不改变5—10行动位规则。

草案独立保存预计体力、法力、有效法力上限、炁、气血、护盾、目标生命与护盾、技能次数、冷却及费用转化状态。规划不执行招式、不支付真实费用、不改变真实状态、不提前抽取随机结果。

- 百骸：预估催血后的显臂门槛、近身追击和血臂撼岳追加段；达到有效层数后再比较攻击，不在气血已满时继续无效催血。
- 玄枢：预估确定产炁、周天回满法力和第10槽费用；自动招式的随机目标按合法结果平均估价，不假定选中最优目标；自动施展中的周天不递归自动施展。
- 斫基：预估当前法力与法力上限支付、至少保留1点上限、焚元每轮次数、一次性体力替代法力，以及主修燃费后技能的本场转化。每轮首次燃费产炁只预留一次。
- 太和：乘势再攻作为正常攻击参与配合；应对估价考虑本心法收益，但不把尚未触发的气血、护盾或回复当成后续必然可用资源。
- 复命：要求有可复制的非应对招式，同时检查自身与被复制招式的费用、次数和冷却；随机目标按合法结果平均估价。
- 回复、防护、破盾、有效击杀及队友已规划伤害参与取舍；同阵营共享预计生命变化，不再重复扣除同一份预计伤害。
- 休整仅在还有后续位置、体力未满且能支撑实际后续技能时参与。无有用行动可留空。
- 外祭法宝草案区分祭出与御使，祭出计费用和灵识占用，不提前算御使伤害。

## 六、情报与预测边界

敌方规划不读取玩家私有队列或未展示的技能。应对窗口只根据对手已经施展的公开招式和角色速度估计，不保证对手下次重复同一招；纯应对缺少可依据的来袭记录时不盲排。队友可沿用玩家已锁定队列的共享伤害预估。

条件产炁、应对返还、概率控制及概率气血增长不用于证明后续费用一定可支付。伤害、护盾和时序是战术估计，不能保证命中、击杀或应对；真实执行仍走共用规则并重新检查费用和目标。本轮不声称已经完整模拟每一种状态、全部公共节点或跨回合最优解。

## 八、战斗测试入口闪退修复

用户反馈点击“开始战斗测试”退出。原日志出现 `gchandle.is_released()` 与 `Handle is not initialized`，在独立 Godot 场景载入现有“玄枢含章”对练方案后重现，进程异常退出码 -1073741795。

修复涉及同一次操作中的资源生命周期：

- 测试技能配置一次构造完整化法技能池，批量生成运行时副本；避免每槽反复调用完整角色快照与技能解析链。
- 自动构筑直接使用同一次生成的技能池，并保存已验证的槽位引用；保留共享化法合并和原测试方案路径。
- 公共基础技能池定义持有强引用，供角色与测试构筑共用；AI 搜索缓存有限状态目录的定义，避免在大量候选分支中反复加载和回收同一个 C# Resource。
- 旧世界存档中的卷章分支记录仍可读取，但当前构筑忽略该记录；NPC 按已学卷章汇总两项效果。

回归场景为 `tools/BattleTestEntryCrashSmoke.tscn`：打开原测试配置、载入既有方案、可选点击双方自动搭配、强制资源回收、点击开始测试、战前确认、进入战斗规划并确认队列，继续执行300帧。只读取对练方案，不覆盖方案或正式角色存档。传入用户参数 `--auto-build` 检查自动搭配路径。

修复后普通方案与自动搭配路径通过；额外使用本机 D3D12 Forward Mobile 渲染完成自动搭配至战斗执行的运行检查，进程正常退出，无 ERROR。仍有归档技能旧 UID 回退警告，与本次已定位的致命句柄错误不同。
