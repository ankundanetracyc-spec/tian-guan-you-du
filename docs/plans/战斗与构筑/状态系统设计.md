一、状态的生命周期类型
----------------------

即时队列战斗中的逻辑状态/Buff使用完整回合数、全场行动数、明确触发条件或战斗时长，不以模拟帧作为新状态的持续单位。每个状态实例使用一种主要生命周期；状态时长和周期效果的触发时机分别配置。

  回合：
  duration_type = Rounds，duration_default 与运行期 remaining_rounds 均以完整回合计。
  回合由一次完整规划与行动循环构成：所有参战单位的队列均已结算、跳过或清除后，该回合结束。
  状态在第 R 回合获得时，不在第 R 回合末扣除时长；从第 R+1 个完整回合结束时开始递减，归零后移除。

  行动数：
  duration_type = Actions，duration_default 与运行期 remaining_actions 均以全场队首行动结算数计。
  每个独立队列项到达队首并被处理，计为一次行动；正常结算与跳过均计数。尚未到达队首而被清除的队列项不计。
  应对与其触发的行动组成一个结算组，合计扣除一次行动时长；同组内的多个伤害段不分别扣时长。其他独立队首行动各自计数，即使它们处于同一模拟时刻。
  结算组中获得的状态从下一结算组开始扣除行动时长，不会在刚获得它的结算组末立即失去一层时长。

  有效战斗时长：
  duration_type = CombatTime，duration_default 与运行期 remaining_combat_seconds 均以秒计。
  只要战斗行动阶段的模拟时钟运行就递减；暂停与动作演出期间不递减。计时使用全场战斗模拟时间，不依赖受影响角色自身的行动条，因此状态冻结目标行动条时仍会自然结束。

  触发结束或战斗结束：
  duration_type = Trigger 时不自动倒计时；状态在明确的战斗事件中消耗或移除。
  duration_type = Battle 时持续至本场战斗结束。

  旧数据兼容：
  Frames 与旧 Turns 仅供既有资源兼容和迁移记录使用。新建逻辑状态不得使用帧数或旧 Turns。
  旧状态上已有的 720/1200 帧等数值不按固定比例自动换算；按下方逐项迁移建议改为回合数、行动数、有效战斗时长或明确触发。纯动作表现的时间可继续按帧计。

  展示：
  状态图标悬停信息显示效果说明与“剩余 N 回合”“剩余 N 次行动”“剩余 N 秒”或持续条件；战斗结束型显示“持续至本场战斗结束”。尚未迁移的旧资源暂时保留帧数展示。

  2026-10-20 补充：局内 Buff 悬停信息显示当前层数／该状态的 max_stacks。心法被动按既有界面约定不显示层数。气血与血炉显示当前值／各自上限；炁显示当前值与周天触发阈值，并说明阈值不是储存上限、触发后清空；护盾说明当前值按受击吸收扣除且没有固定层数上限。

  2026-10-11 用户补充：获得状态时，在角色身上显示“状态名称+本次实际增加层数”的上浮文字，例如“气血+3”“身法+2”。达到上限而只刷新时长时不显示虚假的增层；不同来源叠层按本次增加值显示，常驻图标仍显示总层数。护盾、气血与血炉数值增加同样接入该反馈。治疗、体力及法力回复用绿色显示本次实际回复量，不显示溢出部分；该反馈不改变状态时长、上限或结算规则。

  触发时机与时长分离：
  duration 只决定何时移除，不代表每次行动都触发伤害或治疗。
  周期效果必须明确写出触发时机，例如回合开始、回合结束、结算组结束或匹配事件；未声明周期触发的属性增益只在状态存在期间持续生效。


二、状态层数系统
----------------

  所有状态均可叠加层数（stacks），默认最大叠加 = max_stacks。

  层数影响：
    - 每次明确配置的周期触发效果 = 基础值 × stacks
      （如 damage_per_trigger * stacks、heal_per_trigger * stacks）
    - stat_modifiers 的修正值 = 基础修正值 × stacks

  层数叠加规则：
    - 同效果 ID 叠加层数，不超过 max_stacks。
    - 同 ID 的层数共用该状态计时器；是否刷新时长由具体状态规则说明，不默认给每层分别计时。


三、状态的数据结构
------------------

  StatusEffect（定义模板，.tres 资源）：

    effect_id        → 唯一标识（如 "示例状态"、"灼烧"）
    name             → 显示名称
    description      → 描述文本
    is_debuff        → 是否为减益
    max_stacks       → 最大叠加层数
    duration_type    → Rounds / Actions / CombatTime / Trigger / Battle
    duration_default → 默认持续量；CombatTime 以秒计，Trigger 与 Battle 不使用自动递减数值
    tick_timing      → None / RoundStart / RoundEnd / ActionGroupEnd / MatchingEvent

    # 周期触发效果（受 stacks 倍乘；不按渲染帧自动触发）
    damage_per_trigger  → 每次明确触发的伤害
    heal_per_trigger    → 每次明确触发的治疗
    shield_per_trigger  → 每次明确触发的护盾
    stamina_per_trigger → 每次明确触发的体力回复

    # 属性修正
    stat_modifiers      → {"属性名": 修正值}，受 stacks 倍乘

  StatusInstance（运行期实例，挂在战斗单位的 `statuses` 上）：

    effect              → 关联的 StatusEffect 引用
    remaining_duration  → 按 duration_type 记录的剩余回合／行动数／有效战斗秒数；触发型与战斗结束型由生命周期事件管理
    stacks              → 当前层数
    source_id           → 来源标识（技能ID、装备名等）
    applied_round_id    → 记录施加回合，避免施加回合提前扣除回合时长
    applied_group_id    → 记录施加结算组，避免获得状态的结算组提前扣除行动时长

### 当前公共战斗状态的时长与清理规则

以下数值用于队列制设计与词典同步，不是把旧帧数按比例换算。运行时资源仍需在方案确认后迁移。

| 状态或资源 | 生命周期建议 | 叠层、触发与移除规则 |
|---|---|---|
| 身法 | 1 回合 | 最多20层，每层提高基础身法1%；受击不消耗。获得新层时刷新整个身法状态为1回合。获得回合不扣时长，从下一完整回合结束时递减；战斗结束清除。 |
| 内伤 | 1 回合 | 最多4层，与外伤分别计时；同类新增层刷新内伤总时长，主动消耗只移除相应层数，不刷新计时。 |
| 外伤 | 1 回合 | 仅由明确效果施加，常规受击不自动获得。最多4层，与内伤分别计时；同类新增层刷新外伤总时长，主动消耗只移除相应层数，不刷新计时。 |
| 履薄 | 1 回合 | 获得回合不扣时长；持续期间，每第二次敌方攻击造成实际生命损失时，按履薄明确效果获得外伤1层（没有通用受击外伤）。重新施加刷新时长并将该效果的受击计数归零；到期或战斗结束清除。 |
| 游骸 | 触发型 | 剩余层数不自动倒计时；抵挡整招或被技能主动消耗时扣层，并计入本场已耗游骸；战斗结束清空。 |
| 借力 | 触发型 | 保留至下一次自身主动施放的物理伤害技能结算后消耗；挟势等明确写明保留借力的技能不消耗；战斗结束清空。 |
| 化解 | 触发型 | 只对应当前匹配的来袭行动；所有层组成该行动共用的固定抵消池，每层抵消1点物理伤害，按伤害段顺序消耗，覆盖该招全部物理伤害段；剩余层在来袭行动结算组结束后移除，不跨到下一招。化解在固定物防和百分比减伤之前结算。 |
| 逐猎 | 战斗型 | 保留现有层数和属性效果，持续至本场战斗结束。 |
| 心法被动 Buff | 战斗型 | 战斗开始时将当前主修与辅修秘籍的心法被动显示在 Buff 栏，作为常驻被动持续至本场战斗结束；具体触发限制记录在效果中。修持修正只列入对应心法 Buff 的信息详情，不单列路径标签或生效方式。 |
| 气血、血炉 | 战斗资源 | 不设时长倒计时；当前值大于0时以独立 Buff 图标和数值显示，悬停说明资源效果；气血基础上限8层，每下降1层按当前回落回复率恢复生命，基础回复率为最大生命的5%，修命与明确战斗效果可调整上限或回复率；血炉按其独立规则变化；战斗结束清空。 |
| 炁 | 战斗资源 | 公共战斗资源，跨回合保留，战斗结束清零。当前法力上限为 M 时，炁达到或超过 2×M 立即完成一次周天：清空全部炁、法力恢复至 M，再结算周天触发效果；超额炁不保留，单次获得事件最多触发一次。法力上限改变后立即重算阈值；若已有炁达到新阈值，在该效果结算后立即触发一次。M 为 0 时不触发周天。炁在战斗 Buff 栏显示独立图标、当前层数与周天阈值说明，不按回合或行动数衰减。 |
| 周天 | 触发机制 | 由炁达到阈值自动完成，不是独立状态或资源，不在局内 Buff 栏显示；仅在百科中提供机制说明与专属图标。 |
| 念 | 技能附着层数 | 逐个已装配主动技能记录，不显示为角色Buff。可由技能或秘籍按固定技能槽、成功结算后的队列位置赋予；技能施展和强化不消耗念，念不自动触发行动，战斗结束清零。公共规则不设统一上限，具体秘籍须限制赋念频率与每次数量。 |
| 归元（《抱朴归元篇》） | 触发型 | 第三卷起每回合首次周天后获得1层；第四卷起，若触发该周天的炁获得事件在阈值外至少溢出1炁，额外获得1层，最多2层。每层分别作用于一项后续技能：该技能基础法力费用大于0且可正常结算时，法力费用减1、最低为0，并消耗1层；无合法目标、资源不足或已跳过的行动不消耗。基础法力费用为0的技能不消耗归元。显示为带层数Buff图标，悬停说明剩余触发条件；持续至本角色本回合队列全部结算、跳过或清除时移除，战斗结束清空。 |
| 疲倦 | 条件结束 | 属于非战斗精力状态；精力恢复达到解除条件时移除，不接入队列制战斗计时。 |

现有公共 Buff 暂无必须使用“剩余 N 次全场行动”倒计时的效果；Actions 类型保留给明确需要跨队列短窗口的后续状态，不强行把触发型效果改成行动数。眩晕、灼烧等尚未注册的通用状态仍待逐项定义；《太和感物养元宝册》的僵直已接入运行时。

### 僵直

- 类别：形类减益。1层对应1战斗帧，每推进1战斗帧减少1层，归零解除；再次施加刷新为本次计算的层数，不累加。
- 生命周期：`duration_type = CombatTime`、`frame_counted_layers = true`。使用有效战斗时钟，跟随战斗倍速；暂停、规划和动作演出不消耗层数，不依赖画面渲染帧率。局内只显示层数及对应战斗帧，不显示秒。
- 效果：层数大于0时行动条停止推进，已有进度保留；解除后继续推进，不取消已经结算的行动。
- 施加：各招式分别定义概率与初始层数公式；两者最低为0。《乘势再攻》概率上限99%，层数上限120；0层不挂状态。施加者每低于目标一个大境界，概率和时长各乘20%，最终帧数向下取整；不得在削减后补到1%或1层。
- 《太和感物养元宝册》第四卷化法只对每段命中的追加攻击独立判定；基础攻击段不判定。详见秘籍现行图谱。


2026-11-04动作版击退：赤潮催劲的血浪已接入形类承载控制，按本招的体魄公式、骨部位承载抵抗及现行跨境界概率／时长削减判定，不读取旧版1%保底或通用韧性。击退是短时地面推移过程，不叠层、不附带僵直或自动打断；其距离同步随境界削减为本招明确规则。完整参数、覆盖／边界、暂停及结束清理见[百骸云息即时实装专题](百骸云息篇即时实装与自选对练_20261104.md#血浪击退已确认)，不将本招概率公式推广为所有控制的通用公式。

四、特殊触发状态的配置约定
--------------------------

  对于"触发后消失"的状态，在技能 ActiveSkillData 中
  通过 special_effects 字段配置：

    special_effects = [
      {
        "effect": "status",
        "status_id": "状态名称",
        "stacks": 5,
        "source_id": "触发该效果的技能"
      }
    ]

  BattleManager 在对应触发点（如 on_take_damage）检查角色身上的
  状态列表，匹配 status_id 后执行对应逻辑并清除状态。


五、状态命名约定
----------------

  状态资源文件（.tres）统一放在：
    resources/battle/statuses/

  命名规则：
    <效果ID>.tres

  示例：
    灼烧.tres
    中毒.tres


六、目前已规划的状态
--------------------

六点一、状态机制保留边界
------------------------

  化解、身法、借力仍保留运行时机制，但不在血条 Buff 栏显示；三者均制作独立图标供百科查阅。血炉作为公共战斗资源，也在百科中使用独立图标。

  护盾是公共战斗资源，优先吸收伤害并在战斗状态栏显示；视觉意象为法力在自身周围凝成护罩。它继续使用单位的 shield 数值，不另造一套可叠层 StatusEffect。

  2026-11-09 [守攻阵状态控制实装](../百工技艺/阵法/守攻阵状态控制实装_20261109.md)补充来源账本：公共总值仍为shield，按取得先后吸收，旧聚合增减与清零写法保持可用；命名阵器只撤自身剩余防护，不清普通来源。来源记录不是新资源、层数或固定总盾上限。持续段替换以最终总量通知，净增0不等于本器没有真实续段成功。

七、状态命中概率（v2.0 新增）
-----------------------------

  ~~旧方案：韧性（tenacity）作为万能抗性~~  已废弃（v2.0 移除）

  新方案：每个技能独立写状态命中公式

  每个主动技能（ActiveSkillData）可配置 status_hit_formula 字段，
  存储一个公式字符串，执行技能时由 SkillExecutor 计算。

  命中判定流程：

    技能释放 → 伤害结算 → 读取 skill.status_hit_formula
                             ↓
                       rand() < 公式结果?
                       ├─ 是 → 添加状态
                       └─ 否 → "抵抗"飘字，无状态

  公式语法：

    base_chance + caster.属性1 * mult1 - target.属性2 * mult2

  支持的操作：+, -, *, /, (), 小数常量
  支持的变量：
    - caster.体魄/灵慧/神魂/身心协调值/精准/身法/会心/护心
    - target.体魄/灵慧/神魂/身心协调值/精准/身法/会心/护心

  公式示例：

    | 效果 | 公式 | 逻辑 |
    |------|------|------|
    | 燃烧 | 0.6 + caster.intelligence*0.02 - target.soul*0.015 | 法伤类，神魂抗火 |
    | 眩晕 | 0.3 + caster.physique*0.03 - target.physique*0.02 | 体魄类技能的硬控 |
    | 冻结 | 0.4 + caster.intelligence*0.025 - target.physique*0.015 | 法伤类，体魄抗冻 |
    | 中毒 | 0.5 + caster.intelligence*0.02 - target.physique*0.02 | 体质好抗毒 |

  实现要点：
    - ActiveSkillData 新增 status_hit_formula: String 字段
    - SkillExecutor 新增 _eval_status_hit(formula, caster, target) -> bool 方法
    - 公式为空或为"1.0"时视为必中（自身增益类状态）
    - 公式结果 clamp 到 [0.01, 0.99]，保底

  删除字段（v2.0）：
    - tenacity（韧性）— 从 LivingData / 战斗单位运行期数据 / BattleEntityData /
      AttrKeySets / EquipmentCard / 面板 全面移除
