# 信件与限时邀约界面

状态：2026-10-14 用户授权设计并实装；范围已确认：先做信件与限时邀约框架，宴席、结伴任务／副本活动后续接入。每封邀约独立配置时间，不设置统一通知天数，不自动随机生成活动。

正式入口、保存和原生信件面板已接入；首页增加独立美术预览，效果见[界面记录](../美术规范/信件界面_20261014/README.md)。

## 本轮范围

- 玩家闭关时，正常来访若未能见面，可留下署名信件或由具体活动提供的邀约。熟人、陌生人均可来信，但沿用真实 NPC、来访资格和认知边界，不因来信自动成为熟人。
- 首批复用已有玉虚来访候选与每月最多一位的限流，闭关跨月结算后的本次候选改为留书；不补发所有错过月份，不在闭关中弹窗。没有合格来访者不强制生成。
- 首批自动留书覆盖玉虚峰内闭关突破与归元养息：推进时间前记住所在峰，世界结算后只处理结束时本月可来访者，不按最终人口推造中间各月的来访史。普通看面板、读信、行旅与休息不误算成闭关。其他地点的正常来访及活动通过实际投递接口接入。
- 宴席、结伴任务／副本是后续活动类型；本轮不编造活动、人数、费用、奖励或副本组队规则。真实活动通过投递接口提供邀约正文、地点、应答截止、举办起止时间及活动标识。
- 阅读、未读、应邀／婉拒、过期状态随旅程保存。阅读不推进时间、不扣精力、不交换姓名、不改变好感，不自动接受任务、领取奖励或传送。

## UI 与操作

1672×941 设计画布等比缩放；复用人物页无字外壳、宣纸纹理、楷体、信件图标及角笔，不重复放正文页标题横栏。左侧分类，中间信笺列表，右侧纸面展信；长列表及长正文各自滚动，分类、检索、邀约信息与底部操作固定。

按用户后续精简要求，分类仅保留“全部、未读、邀约”，删除相识／初次来信、事务通知和珍藏分类；删除珍藏按钮、标题珍藏标记以及正文头部的来信类型标签。不同用途信件直接进入同一信匣。列表显示署名、标题、摘要、投递日期和未读标识；支持正文／标题／署名检索及日期排序。打开面板不自动拆开第一封信；点击信件才标已读。正文保留完整文字。

邀约在信尾独立展示活动、地点、应答截止与举办时段。应邀／婉拒只改变该邀约的答复；没有真实活动处理入口时“赴约”保持未开放，不能以阅读或点按钮伪造活动完成。活动结束不会自动判为已赴约。

按钮保留原素材，以边缘和轻微提亮响应，不覆盖灰色实心块；说明浮层沿用黑色墨底。空信箱显示完整空状态，不把示例信写入正式存档。

## 接口与保存

`LetterData` 保存收到时的署名与正文快照、来源事件 ID、未读及可选邀约。旧珍藏字段保留存档兼容，不再提供分类或操作。`LetterInvitationData` 保存该封信的时间、地点、活动和答复。`LetterMailbox` 以来源事件 ID 防止重复投递；不按自由文本推断活动或奖励。

信匣独立保存于正式进度和战前内存快照；旧档缺省空信匣，不补造历史信件。闭关留书待结算的上下文也保存，读档不把现实离线当作来信时间。自动来访与留书共用原月度游标。

正式保存格式为 v6，v5→v6 只增加空信匣，原有迁移链、人物、地图、公库与天气状态保留。底部信件入口沿用首封信后可用的现行规划，显示未读数；无信时保留入口及暂无来信提示。首页可随时查看独立示例。

接口：`MainScene.deliver_letter` 接受真实信件快照与稳定事件 ID；`deliver_npc_letter` 从真实 NPC 读取署名与是否相识，可明确提供原始投递小时；`register_letter_activity` 由后续活动注册实际赴约处理，`complete_letter_invitation` 仅由真实活动完成后回写。未知活动键不开放赴约。阅读及应答不会在框架内扣费、发奖、移动或生成交往记忆。
