# 玉虚生态与玄基后续内容实施路线

> 状态：现行实施路线。本文负责安排专题和实现顺序，不替代境界、宗门、委托、剧情等主策划案，也不将待讨论内容写成既定规则。
>
> 范围：优先做出玉虚仙宗的一圈可玩生态，当前游玩终点为云息十层圆满、准备铸玄基。真实跨峰物资领用与生产供给循环暂缓；在云息与玄基两个大境界的玩法都能完整跑通后再单独规划，不作为当前一圈游玩的前置条件。

## 一、当前基线与约束

1. **目标上限不等于当前实装。**《策划案摘要》记录的当前运行时境界为云息一至十层及归元九息；十层之后准备铸玄基。玄基旧小游戏规格已废止，八回合凝核牌局已有独立试演，但正式铸玄基的完整规则与转换仍未全部确认。玄基工作包延期处理，不阻挡玉虚生态实现。
2. **高境界已有世界观框架，缺的是可执行玩法专题。**《高境界体系与天人设定确认稿》确定了金丹、神胎（元婴）、天人、五太与二十果位等结构；其中突破条件、阶段流程、算法、资源、失败后果和数值仍有待专题规划。
3. **宗门不是主线门槛。**玉虚仙宗提供可选的身份、师承、传承、资源与事务支线；不加入玉虚也必须能继续个人修行和主线。
4. **已接入描述必须逐项对照当前代码。**生态和师承方案记有已接入的首轮循环，但每个实现对话仍须先核实当前分支、存档字段与场景状态，不能把文档状态直接当作代码现状。
5. **不自行补造规则。**不新增境界、资源、物品、属性、境界门槛、概率、耗时、费用、奖励或失败惩罚；只用现行有效物品及已定义接口。遇到规则缺项、文档冲突或接口不支持时，先产出清晰的待确认方案，确认前不实现该规则。
6. **时间与存档遵循现行总案。**行动由玩家主动推进时间；不增加后台时钟或离线结算。会改变身份、任务、贡献、资源、师承或境界进度的状态须纳入正式存档并避免重复结算。

## 二、交付目标

### 目标 A：玉虚仙宗的一圈可重复游玩

```text
按现行资格自愿入门
  → 在当前身份对应地点生活、修习与接触事务
  → 选择宗门公事或已开放的同门事务
  → 完成可核验行动并结算资源、贡献与关系记录
  → 用所得继续修行、兑换或申请身份晋升
  → 存档后仍能正确继续，不重领、不重扣
```

闭环须支持不做宗门任务的玩家继续自由修炼；宗门公事、私委、野外采集、战斗和贡献流水分别按各自规则结算，不能把行动本身默认等同于贡献。

### 目标 B：玄基及越境后的逐境界体验

玄基正式境界衔接完成后，再处理金丹、神胎与天人；这些工作不得反过来阻塞玉虚生态闭环。

金丹、神胎、天人各自形成独立专题，再按顺序实现。新境界每一步都要说明：玩家为何开始、做什么、依据什么获得进展、如何面对代价或风险、完成后给下阶段留下什么。规则未确认前只整理方案与决策，不做猜测性实现。

### 阶段 0 玉虚普通弟子主循环核对状态（2026-10-11；静态代码核对）

现行资格入门、观复峰普通弟子起居/静室/休息/授业/月例、和光峰八项宗门公事、贡献流水、善功堂现有物品兑换及杂役→外门→内门测试晋升均已接入。公事进度、唯一接取实例、贡献流水、月例月份游标、东林地巡查路线与东林地 NPC 冲突结构化案卷写入正式存档；事务结算按唯一来源事务 ID 防重。雾铃花采收后若交付结算失败，已采收物留在行囊，可重试上缴而不重复采收。正式存档升至 v4，独立持久化公库物资流水和 NPC 冲突案卷；旧存档不会从 NPC 行动自由文本推定案卷事实。兽骨 ×1、雾铃花 ×3 入库，苦苔根仍只记原事务回执。后续真实领用与生产不属于当前云息至准备铸玄基游玩的前置，按本路线延期处理。本轮增加的天问演法公事目前仅做静态代码核对；不据此宣称运行时验收通过。

### 阶段 1 多峰公事与供给流程模拟（进行中；2026-10-11 静态代码核对）

八峰逐项核对后，和光、观复、紫府、玄览、天问、瑶圃已有真实入口或事件；天工峰可在峰内打开既有百工面板，目前只有阵法页可操作，其他工艺页仍为规则占位。执中峰现已接入东林地 NPC 对 NPC 冲突的结构化事实记录、和光峰按具体案卷 ID 接取、执中峰来源事实查看与一次性上呈。案件只记事实，不判责任、不惩戒、不改人物关系；每案沿用 5 点普通短公事测试贡献，上呈后待裁断，不含最终裁断或申诉。未从旧行动记录自由文本推定补录案卷。天工面板复用 `HumanData.formation_circuits`；没有新增制作配方、物品、材料扣除、制作产出或耗时。独立公库流水继续接入兽骨 ×1、雾铃花 ×3 的既有公事交付，存档格式升为 v4，旧 v1/v2/v3 可读取并迁移。

天问演法已接为可计贡献的宗门公事：先在和光峰接取，再到天问峰完成现有凶狼演法并回传结果，核发 5 点测试贡献、不掉落物品、按接取实例单次结算。没有新增胜负门槛，也没有重复首轮六项基础公事。兽骨 ×1、雾铃花 ×3 现在从弟子行囊扣除后进入独立公库流水；贡献回执与物资账使用同一唯一事务来源并共同结算。库存属于宗门，不能直接退回弟子行囊；既有入库规则保留，但当前目标不要求新增真实领用或生产。若需表达后续供给，只复用已有公事回执或叙事，不虚构物资、数量、扣库或产出。真实跨峰领用与生产至少延后到云息、玄基两个大境界的玩法都能完整跑通后再规划。苦苔根继续只按原事务回执处理，不进入公库。执中峰事实核验与上呈已落地，最终裁断、申诉和责任后果仍不在首期。天工新制作、玄览独立公事的具体缺项和暂停边界记录在《玉虚仙宗宗门生态规划》第十二节；阶段 1 继续聚焦不依赖新物资规则的公事闭环。

本轮尝试执行项目编译但未通过：当前诊断集中于 `csharp/panel/InfoPanel.cs` 调用了 `Character` 尚未定义的道胎相关方法，以及 `GongfaChapterConfig.allowed_bearings` 不存在；这些位置不在本次天问公事改动范围内。未运行测试或场景试玩，因此不声称天问公事运行时验收通过。

### 阶段 2 暂缓工作包：同门名册与私委闭环（2026-10-11 静态核对）

静态核对确认玉虚地点已使用程序生成的稳定 NPC 身份与 `npc_id`；完整 NPC 快照随正式存档恢复。和光峰任务板已有公事/私委切换、详情和空状态；玩家贡献流水及私委流水类别已定义。但 NPC 没有可用贡献流水或余额，NPC 宗门公事也没有贡献核发来源；现有随机抽象资源不作为贡献。现行候选私委类型也没有已接入的完整自动核验事件链。因此本阶段功能实施暂停，不能依据现行规则发布可支付私委；未开放玩家发布。唯一前置待决问题已记入《玉虚仙宗委托发布与贡献结算设计》第十一节：首批私委采用哪一项现行可持久化的 NPC 贡献流水来源及哪一种自动核验目标事件。来源确认后，再完成托管、接取、结算/退款和唯一流水闭环；不以预置贡献、抽象资源兑换或新报酬值绕过规则。

用户决定本阶段先暂缓，优先完成阶段 1 多峰公事；供给部分只做流程/叙事模拟，真实领用与生产延期。恢复私委工作前仍须先确认上述 NPC 贡献入账来源与自动验收目标事件；本轮未修改私委代码，也未新增或运行测试、编译或场景验收。

### 云息至玄基准备状态（2026-10-11；当前已运行验收）

云息正式配置现已补齐至十层，七至十层灵力门槛接入；普通闭关不能绕过六→七凝核。归元九息基准为9504小时／396日，完整闭关达到九息后自动打开境界页并播放圆满演出，显示“准备铸玄基”。编译与独立 Godot 场景运行验收通过；动画不额外推进时间，也不自动更改为玄基。完整验收边界见[云息十层归元九息修炼设计第十二节](云息十层归元九息修炼设计.md)。

突破丹药策划已确认：云息三→四、九→十必须有丹药，其他普通晋层不要求丹药。依用户要求，本轮只写入策划，不新增丹药代码、占位物品或界面拦截；丹药物品细节及制作、获取、检查、消耗接入留到丹药系统开发。现运行时仍缺这两个关口的丹药条件，因此圆满演出已接入不等于从云息前期到“准备铸玄基”的端到端晋层路径已经可玩；要达成整轮游玩，后续仍须补上丹药系统，不能用其他物品或移除硬性条件绕过。

**玄基工作包仍延期。**当前交付目标止于云息十层圆满并准备铸玄基；正式准入、玄基转换、消耗、奖励、失败与重试尚未定案，也没有玄基过程或结果存档字段。规则确认前不实现依赖这些规则的境界切换或结算。当前路线优先级仍为完成阶段 1 中不依赖新增物资规则的多峰公事闭环；真实供给领用与生产至少等云息、玄基两个大境界的玩法都能完整跑通后再规划，私委暂缓，玄基实际突破继续延期。

## 四、分对话实施约定

- 每阶段使用一个独立的 Luna 高推理 Codex 对话，按阶段顺序执行；前一阶段完成或明确停在待确认项后，再开启下一阶段，避免多个对话并行修改同一工作区。
- 每个对话先重读策划摘要、阶段对应主文档和项目指令，再检查当前分支实现；只处理路线表中对应工作包。
- 若前置规则完整，按现行专题实现并记录代码与存档影响；若关键规则缺失或冲突，先在对应 `docs/plans/` 专题中列出最小决策问题并暂停该规则实现，不擅自选择数值或流程。
- 完成后更新对应专题的状态、验收边界和本路线进度。不要把“编译成功”“试演可运行”写成尚未完成的实机验收。

## 五、完成定义

路线完成不是把所有境界一次性堆进运行时，而是每个阶段都有唯一现行策划、可理解的玩家循环、与存档和主线相接的实现，以及与本阶段相称的验收记录。未完成的高境界规则保持明确待定；不得由代码、旧稿或临时平衡值反向确定设定。
