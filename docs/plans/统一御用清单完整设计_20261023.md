# 统一御用清单完整设计

状态：2026-10-23，完整提案，未实施。用户要求在“不召唤在场不占灵识”的前提下继续补全。已确认规则与新增建议分列；4件上限、同类并用、攻击来源选择、崩解收益保留等不视为已获确认，也不直接放开当前单器实现。

## 一、当前规则与本案建议

已确认：衣、剑、甲、珠等统一器物管理，不保留常规穿戴和法宝两套收益栏；持有不生效，御用不占灵识，只有器体成功召出在场占灵识；普通词条优先固定值，多段物伤逐段获得完整加成；器蕴先惊鸿/抱朴两种，激活奖励用百分比；同器化法只选择一个技能；主动技能仍须装入现有技能栏。

本案推荐：通用御用上限首版4件、每件占1个名额，凡器/法器共用；不设身体部位与专属器类位；允许同类不同实例并用；局外换装、战斗锁定；各攻击明确引用一件器物的本体属性。以上为可评审基准，不是当前运行规则。

来源：[最新灵识规则](器物灵识占用规则修订_20261023.md)、[器蕴与词条](器蕴与剑类词条设计_20261023.md)、[固定值收益](剑关键词与器物固定值收益设计_20261023.md)。本案覆盖此前维系计费、按身体部位装备的讨论方向，不更改炼器材料公式与正式平衡。

## 二、持有与御用

行囊统一保存器物唯一实例，不按名称堆叠。器物进入御用清单只增加一条实例引用，仍是原物品，在行囊显示“御用中”。同一实例不得由多个角色同时御用，不因同件授予多个技能而重复占名额或重复贡献器蕴。

每件占同样一个名额，不引入大器占两格、特殊袋子额外容量或隐性御用负重。上限先统一，不按凡器/法器、境界或造诣另设未经讨论的解锁曲线；成熟后再用实战比较决定是否成长。

允许同类不同实例并用是候选规则：例如两把剑、两件衣甲均无需伪装为饰品才能配置。它们的平衡成本来自有限名额、真实材料效力与属性收益，不以画面上的持物数量决定属性。若测试中出现某类全面压倒其他类别，应先检查效力折算与实际收益，不临时补一张身体部位限制表。

普通服装只用于人物外观选择时不提供战斗收益；具有器物属性的衣甲通过相同御用清单生效。外观选择与收益引用分开保存，不要求御用四件衣甲就叠穿四层立绘。旧服装/装备的数据与外观不能未经迁移直接删除。

## 三、单件提供什么

| 内容 | 何时生效 | 是否另配置 |
| --- | --- | --- |
| 本体属性 | 真正由该器物参与的适用行为 | 攻击来源需要明确 |
| 基础固定属性 | 有效御用期间 | 无 |
| 常驻效能 | 有效御用且具体条件满足 | 无，不要求逐技能绑定 |
| 化法 | 已配置合格目标，随原技能结算 | 一件器物绑定一个技能 |
| 获授技能 | 已御用且由玩家装入技能栏 | 手动装配，按原费用和目标使用 |
| 器蕴贡献 | 有效御用期间 | 汇总激活，不逐件手动开启 |
| 器体/御器能力 | 召出并按技能执行 | 另检查在场灵识等条件 |

因此，凡器有本体性能与基础属性，没有其他专属能力，也占一个通用名额；灵识为0的角色仍可普通御用。法器有机会形成更多表达，但不保证每件都有主动、化法或器蕴。

## 四、多件属性、本体来源与效果叠加

### 4.1 基础属性与常驻效能

不同实例的合法固定属性进入角色已有属性汇总；不同实例的同向固定修正合计后作用于各合法伤害段。同一来源不因UI刷新、技能副本或多次装配重复注册。固定值与百分比始终分开保存，不把一个换算成另一种单位。

涉及现行全局上限的属性沿用其上限，不能由每件器物单独绕开。百分比沿用对应战斗通道，不为了器蕴新增独立相乘区；具体比例基数、已有同类比例的合并与取整要在战斗实施前统一。

### 4.2 剑的锋锐来源

建议在构筑配置中为需要武器来源的攻击技能指定一件已御用的合格器物。只有一把剑时可默认引用它；多把时由玩家选择，技能清单显示小图标与名称。引用与化法绑定是两个不同关系，不因改用另一把剑就擅自改化法。

同一次攻击只读取来源剑的锋锐；不求全部锋锐之和、不默认为最高值。另一把剑的合法角色固定属性、常驻条件效能、化法及器蕴仍按自身条件生效，不把“不是本次攻击来源”解释为整件停止御用。

例：御用甲剑锋锐5、乙剑锋锐3；斩剑引用甲剑，则只忽略甲剑提供的5点物防。本次若两件都有合法的“带有‘剑’关键词的技能，每段物伤+N”常驻，则各按普通汇总规则处理；锋锐仍只取来源甲剑。

原本不要求器物的技能不能因失去一件来源就整招被删除。来源卸下后，清除该器物的本体修正并提示重新选用，不能继续引用失去的锋锐；真正依赖来源器物的获授技能按来源丢失规则失效。自动改用其他剑是否启用需另定，首版建议不暗中替换。

## 五、化法与十个技能位置

建议同一技能最多接受一件器物化法，秘籍化法按已有规则保留，先生成秘籍结果再追加器物修正。一件器物只绑定一个合格技能，全部修正共同展示，不把每条数值当作单独绑定额度。

化法生成阶段必须保证存在共同合格对象。推荐在共享效力分配中把攻伐、应对、养意等不兼容方案当作互斥候选，最终只生成一个可实现的方案；不能先把所有方案各分满额，再让玩家免费任选。放弃方案的潜力可按原公共约束重新投向合法表达，没有去处则保留为未实现量。方案选择目标、并列稳定规则及参数仍需离线验证，不假定旧样本已解决这一问题。

御用器物后，获授技能进入可装配列表，不自动占格、不挤掉原技能。仍保留十个固定位置，空位不前移；同一获授技能实例不重复装进多个位置，但可按现有队列规则重复使用。卸下来源时清空它授予的技能位置、器物化法绑定和本体引用，保留其他技能与秘籍化法。

替换时列明哪些配置会失去来源。恢复御用不自动恢复此前获授技能装配；保存的构筑预设可以显式包含装配意向，并在完整合法后由玩家确认恢复。

## 六、器蕴组合

维持惊鸿、抱朴两种候选器蕴：

- 惊鸿：带有“剑”关键词的技能，造成的物理伤害提高对应百分比。
- 抱朴：角色物理防御提高对应百分比。

贡献按实际御用实例累计；同件重复引用只算一次，持有未御用不算。每件贡献1—3点、2/4点门槛仍是原提案待标定，不因4件上限建议而自动获批。高档显示总比例，不重复叠加低档完整倍率；溢出点数不循环触发。

不为凑套额外收灵识，也不因激活器蕴新增免费装备名额。器蕴本身不改变灵识上限或占用，首版避免自我维持循环。它依然在炼制时占真实材料效力预算。

4件基准下可比较以下非配方组合：

| 组合 | 取舍 |
| --- | --- |
| 惊鸿3＋惊鸿1，另两件选单件强效 | 保留攻击高档，追求独立属性/化法 |
| 惊鸿2＋惊鸿2＋抱朴2＋抱朴2 | 双高档，但每件形成贡献占用了材料效力 |
| 抱朴3＋抱朴1，另两件提供应对或主动能力 | 防护与手动行动组合 |
| 用一件3点贡献替换两件较低贡献 | 贡献集中可节省名额，空出的名额再选择单件强度 |

这里不存在“达到4点就永远优于3点”的预设；跨档奖励与换下器物的实际损失共同决定收益。比较时需要同档真实材料成本和战斗技能组合，不凭示意表证明全局最优。

## 七、在场灵识与器体

```text
可用灵识 = max(0, 总上限 - 已在场实体占用 - 其他当前真实占用)
```

御用件数与灵识互不兑换：御用四件可以不占灵识，能召出几件由其追加占用及全局余量决定。没有御器能力的器物不显示无意义的器体/占用零值。

召出成功才登记占用，御使不重复登记，召唤失败不付占用。离场、崩解、战斗结束释放对应在场占用。器体不独立加入角色行动列表，不影响胜负条件，仍按原御器模板承受合法伤害和结算。

本案建议把崩解失效范围限定在本场召唤/御使分支，本件仍处于御用，独立常驻属性、化法、器蕴贡献继续生效。旧测试的整件“本场禁用”不能直接推广到新多表达器物。此失效范围尚需用户确认；长期破损/耐久规则另定，不将器体崩解当作物品永久销毁。

若灵识上限被临时压低，仅处理在场实体超限，不暂停不占灵识的普通御用。建议允许玩家预设收回优先级，在安全结算边界收回足够实体，仍按相应离场规则处理，不倒改已结算效果。其他系统占用与容量变化须共享总账，不能把O随意清零。

## 八、界面与完整操作

页面采用统一纸墨风格，三个区域：左为行囊器物筛选，中为御用清单与选中器物详情，右为构筑汇总。不是在人物立绘周围摆身体部位槽。

顶部显示“御用2/4”及真正的“在场灵识占用/上限”。后者在局外无实体时正常为0；不显示已经撤回的维系费用。4仍为讨论基准，最终界面从配置读取上限。

行囊条目显示图标、名称、阶位、大类、本件器蕴、御用标记；支持大类、蕴种、是否御用筛选。每个器物仍可悬停读取完整物品信息。详情按本体、基础属性、器物效能、集中化法、获授技能、器蕴贡献组织，没有的内容可隐藏。

御用清单只显示实际条目和一个添加入口，不画十几个未来锁定位。点空余添加从行囊选择；名额满时进入替换，明确选择撤哪件，不能自动挤掉最弱或最早装备者。

右侧显示两蕴累计、当前总比例与各来源；换装预览显示固定属性变化、蕴种升降档、失去来源的化法/技能和攻击引用。仅试选不实际应用；确认时一次校验并提交，失败完整保留旧配置。

成功御用后可直接点“配置化法”或“查看获授技能”，不自动替玩家绑定。相关操作仍可在技能页完成，两个入口引用同一份人物配置。

## 九、构筑预设与使用限制

建议允许保存命名预设，内容包括器物实例引用、技能来源、化法绑定、十个技能位置和收回优先级。预设不复制物品或器物属性，不保存成器重新生成指令。预设数量与解锁不先写死。

局外应用预设前检查持有、数量、来源与技能资格，预览差异后整组确认。物品缺失则明确缺项，不静默替换成同名另一件，不自动把一半配置当作完整成功。改名通过实例引用自然保留关系。

建议战斗中锁定御用、技能装配和化法配置，保留队列规划权限；不能换装刷新技能次数、冷却或通过切换最大生命获得治疗。因外部事件失去来源时统一失效，不视为玩家免费换装。战斗后器体状态清空，人物原御用配置保留。

普通御用不压缩炼丹灵识。正式炼丹读取真实当前其他占用；制作过程资源提交与释放遵守其生命周期，不能靠关闭面板腾出同一份灵识。外观切换不触发御用重算。

## 十、实例、保存与旧数据

器物固定快照保存实例ID、类别、实际阶位、形态/图标引用、阴阳、本体属性、实际收益列表、化法兼容方案、获授技能模板、器蕴贡献及来源/规则版本。不新增器物五行、主功用、内炼/外祭互斥字段。

人物保存持有的唯一实例与御用ID列表、化法与来源绑定、技能位置和预设。战斗保存当前运行态与来源引用；召出在场、剩余器体、占用不写回永久器物。长效耐久只有正式维护案确认后接入，不用器体字段冒充。

旧武器/衣甲/饰品与旧法宝必须分别迁移：保留物品所有权和稳定引用，转换已明确的能力字段；废弃字段留迁移审计，不用旧五行/主功用强行补新效果。若旧装备数量超过拟定新上限，应提供首次迁移的配置选择，未选择部分仍保存在行囊，不能删除或自动宣称继续全部生效。转换不了的效果先报告规则缺口，不凭推测生成。

## 十一、验收与实施顺序

1. **物品层**：正常入包、图标/悬停/详情、唯一实例与容量、同名不混淆、重启读档；现有展示样例不自动发放。
2. **单器御用**：统一来源与固定属性，零灵识能普通御用；未御用收益为0，卸下完整撤销，反复刷新不重复叠加。
3. **单器技能**：化法共同条件、秘籍保留、获授技能手动装配、来源丢失清空且不前移、攻击本体来源正确。
4. **多器独立验证**：在用户确认上限、同类规则与来源选择后，验证同类实例、多来源固定值与两蕴聚合；4件提案不直接成为正式存档上限。
5. **御器**：真实在场占用、重复提交、容量不足、离场释放、器体崩解收益边界、角色倒下及战后清理。
6. **完整操作与迁移**：换装原子性、预设缺项、旧装备超额处理、战斗锁定、场景截图与人工操作。

当前新成器仍未正式入包；固定值生成、器蕴奖励、普通新器物存档与多器均未因本稿而实现。正式炼制扣料/时间接入须另做事务闭环，不能把独立试炼库存直接变成正式资源。

## 十二、需要优先确认的新增建议

- 通用御用上限是否采用4件，凡器同样占1件；不设身体部位及额外维系费用。
- 是否允许同类不同实例并用，以及按技能选择一件攻击来源的方式。
- 器体崩解是否只禁用本场召出/御使，保留独立的常驻、化法与器蕴。

其余具体比例、贡献点刻度和材料转换系数继续标定，不以界面样例数值代替定案。
