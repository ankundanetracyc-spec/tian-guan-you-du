# 玉虚仙宗委托发布与贡献结算设计

> 状态：现行专题。定义宗门公事、同门私委、贡献结算与未来发布委托的统一格式。首期费率与任务奖励均为可调原型；本文件不代表委托发布、托管或全部任务类型已经实装。地图依赖任务须等百川地图首期稳定后接入。

## 一、目标与边界

玉虚仙宗的委托要让宗门像一个有人办事、有人求助、有人承担责任的组织，而不是把所有任务都塞进同一个无来源的列表。玩家应能看出任务是谁提出、为何需要、由谁承担报酬、完成后如何核验；任务结束后贡献流水也必须能追溯到具体事项。

宗门修行的首期可玩闭环是：入门并获得身份 → 在身份对应的峰生活与修习 → 接取并完成可验证的宗门事务 → 获得贡献 → 在善功堂兑换现有秘籍，或以境界与累计公事履职记录申请普通弟子晋升。天灵根入门即为真传，真传仍不可通过晋升取得。首轮测试已采用可调整的月例、兑换价与晋升门槛，具体数值见《玉虚仙宗宗门生态规划》“首轮宗门循环测试参数”；这些值只用于验证闭环，不代表最终平衡。尚未接通托管和自动核验的同门私委不计入当前流程。

本专题只规定宗门内任务与贡献的结构，不开放新的世界地图节点，不复活旧家族、契约、木材、凝血草、灵米粥或回春丹等废案内容。委托涉及物品时只能选择项目中已有且有有效图标的物品；不得用自由文本创造资源、配方或掉落。

## 二、两类委托及其区别

| 维度 | 宗门公事 | 同门私委 |
| --- | --- | --- |
| 发布者 | 和光峰或其他有职责的宗门机构、执事 | 有稳定身份的宗门成员；未来也支持玩家发布 |
| 目的 | 完成宗门职责、秩序维护、公共供给或明确的宗门需求 | 解决某位成员的个人需求，体现同门之间的求助、协作与竞争 |
| 报酬来源 | 宗门核发；通过可验证的任务结果入账 | 委托人支付，不能凭空生成或从办事者余额扣取 |
| 宗门费用 | 不向承办弟子另收受理费 | 委托人另付受理费；首轮原型按报酬的 10% 向上取整。报酬 50 时，报酬 50 + 受理费 5，共预留 55 贡献 |
| 失败责任 | 按任务条款处理，不能因未完成就自动处罚身份或关系 | 报酬按失败/撤销规则退回或结算；费用与报酬分账，不能重复扣款 |
| 社会反馈 | 可能形成宗门履职记录，但不自动改变百川声望、势力态度或 NPC 私交 | 可能触发委托人明确的对话/关系反馈，但不自动改变区域声望或势力态度 |

宗门受理费是私委使用宗门告示、登记与争议留痕的服务费用，不是对宗门成员一律征收的税，也不从宗门公事报酬中暗扣。10% 是本轮可调原型，不是不可改的世界定律；按整数贡献结算，向上取整以避免小额委托出现零费用。宗门如何支用该费用、是否设公账余额，仍须与公库和兑换经济一并定案，首期只记入可审计的宗门费用流水，不创造另一种货币。

同门私委须有真实的发布者和可支付能力。发布时校验委托人的可用贡献，并预留“报酬 + 受理费”；玩家不能接自己的委托。接取后锁定目标与条款，不能由发布者单方面改价、改目标或撤单。所有首期任务必须自动核验；不支持“我说完成了”或发布者任意拒绝验收。

## 三、同一任务板、明确分区

和光峰“宗门事务”仍使用现有的全屏办事地点背景、弧绳与竖签控件，不新造黑框、地图节点或第二套任务 UI。顶部中央增加同级切换签：**宗门公事 / 同门私委**。境界大档翻页、三根弧绳、由下至上的境界顺序、两字竖签、悬停约 1.5 秒预览、点击后中央详情，以及逐层 Esc 返回全部沿用现有任务板规则。

- “宗门公事”页只显示机构发布的任务；签牌保留两字类型，不在绳签上堆发布者详情。
- “同门私委”页显示发布者姓名/身份、任务状态与报酬摘要；受理费由委托人承担，不伪装成承办人的扣款。
- 悬停只展示简要目的、境界条件、报酬范围或发布者摘要；点击后在屏幕中央打开完整详情和操作按钮。
- 详情仍用一个自然段介绍事务；出现的地点、物品、对象和完成要求使用下划线强调。地点、物品不是强制字段。
- 私委详情必须明确显示：发布者、指定对象/境界（如有）、报酬、受理费、完成期限（如有）、失败/撤回规则，以及“报酬由发布者托付”的说明。
- “接取 / 取消 / 交付 / 领取”只在当前状态允许时出现；不显示不可用的假按钮。首轮并行接取数量沿用当前任务板限制，待任务完成回路验收后再决定是否扩展。

## 四、统一委托数据格式

未来由策划、NPC 或玩家创建的委托都必须从同一任务模板生成。显示文案可以变化，结算依赖的字段必须结构化，不能只靠自然语言猜测目标。

| 字段 | 用途与约束 |
| --- | --- |
| 委托 ID / 模板 ID / 版本 | 唯一识别任务与任务规则版本；每个完成奖励只能结算一次 |
| 委托来源 | `sect_official` 或 `member_private`；决定发布权限、资金来源与费用规则 |
| 发布者 ID / 承办者 ID | 指向稳定的宗门角色或玩家实体；不得只保存显示名 |
| 两字类型 / 短标题 | 用于竖签分类与列表识别；详细叙述放在中央详情，不把整段文案塞进标签 |
| 叙述文本 / 悬停摘要 | 只负责表达目的和情境，不作为任务完成条件的唯一来源 |
| 对象与境界条件 | NPC/玩家/物品等目标使用稳定 ID；境界使用现有境界枚举及范围，不写模糊的新境界 |
| 地点条件 | 使用现有地点 ID、场景 ID 或允许的范围；地图尚未开放的地点不得进入可接取目录 |
| 结构化目标 | 目标类型、数量/次数、完成事件、校验参数；所有判定均由游戏事件记录验证 |
| 期限与取消规则 | 可选；按游戏内时间推进。未写期限的任务不得暗中超时 |
| 报酬、受理费与托管状态 | 贡献整数；宗门公事记核发依据，私委记录发布者预留、费用入账、承办者到账或退款 |
| 贡献流水类别 | 使用稳定机器类别区分公事奖励、私委报酬、私委托管、宗门受理费、退款和兑换支出；不得从展示文案猜测账目含义 |
| 状态与结算流水 | `草拟→待接取→已接取→进行中→待交付/待核验→已完成`，并允许依规则转为已撤回、已过期或已失败；状态转换均写原因 |
| 关系/声望后果 | 默认为空；只有另有明确规则且由具体事件触发时才填写，禁止贡献奖励自动改私交、地区声望或势力态度 |

所有贡献变动使用唯一任务 ID 与唯一结算 ID 记账。重复点击、重复读档回调或同一完成事件再次触发，都不得重复发奖、扣款或收取受理费。任务退款、任务报酬、宗门受理费、累计履职记录是不同流水含义，必须能区分。

## 五、私委资金与状态规则

以下作为首轮交互原型，具体期限和费率可调：

1. 发布者填写模板并确认后，系统校验其当前可用贡献足以覆盖报酬与受理费，将两笔数额分别预留；未能全额预留则不能发布。
2. 尚无人接取时撤回或自然过期，报酬和费用均退回发布者；已有人接取后，受理费结转为宗门费用，报酬继续托管。
3. 条款锁定后由游戏事件自动核验。成功时只把托管报酬转给承办者一次；宗门受理费不再重复扣除。
4. 承办者主动放弃、任务到期未完成或客观失败时，报酬退回发布者；已经发生的受理费不退。若因存档/场景/系统错误导致目标无法完成，则按系统撤销处理，报酬与费用一并退回，且不得把技术故障记作玩家失败。
5. 已接取的任务不能由发布者单方撤销；双方同意撤销时，首期建议退回未结算报酬，受理费不退。撤销原因留在记录中。
6. 同一模板可否重复发布、每位成员的同时委托上限、过期时间和取消窗口先由配置控制；不在规则未确认前写死新的数值。

贡献账本至少区分：可用余额、私委托管、宗门公事奖励、私委报酬收入、发布支出、受理费、退款。可用余额按所有已结算的贡献正负流水计算；晋升所需服务量则从已完成且未撤销的正向宗门履职记录累计查询，不直接读取当前可用余额，花费贡献兑换不会抹除过去的服务记录。两者是同一账本的不同统计口径，不是新增货币，也不与百川区域声望、势力态度或个人关系混为一谈。个人档案分别展示可用贡献与累计公事履职贡献；首轮晋升原型暂定杂役→外门为云息三层且累计公事履职贡献 10、外门→内门为云息七层且累计履职 20，真传仍只由天灵根入门取得。正式门槛及私委是否计入晋升服务量仍待平衡/定案。

## 六、标准任务类型目录

类型标签统一为两个汉字。类型只是目标模板，实际开放还要满足对应系统已存在、目标可稳定识别、结果可自动验证。

### 宗门公事

| 类型 | 标准目标 | 地图/系统依赖 | 首期建议 |
| --- | --- | --- | --- |
| 值守 | 在已开放的宗门设施完成指定时段/次数的值守 | 可验证的地点停留与游戏时间 | 可优先做宗门内短事务；不接受挂机刷贡献，需有明确行动与单次结算 |
| 研习 | 完成指定静室/传承入口的一次有效研习 | 现有研读动作与完成事件 | 可复用既有研读，不新造修为资源或导师数值 |
| 清点 | 按清单交验已经存在的物品或设施记录 | 物品图鉴、数量与交付事件 | 仅选有效物品图标；不出现木材、凝血草、灵米粥、回春丹等废案 |
| 提交 | 将现有物品交宗门登记或入库 | 现有物品定义、数量、交付地点与事务流水 | 首期可用已有妖兽掉落物；交付后从弟子行囊扣除并写明数量 |
| 传讯 | 在已存在的宗门内角色/地点之间完成消息交付 | 稳定 NPC 与已开放地点 | 待角色目录和交互事件具备后开放 |
| 巡查 | 按指定路线抵达并记录可验证的巡查点 | 百川地图、路线与到达事件 | 地图首期完成后开放 |
| 接引 | 引导满足条件的新入门者完成指定登记 | 招收/角色生成与身份流程 | 待招生角色可稳定存在后开放 |
| 核验 | 检查已定义的事务结果/记录并提交结论 | 事务记录、证据与核验机制 | 待证据记录接入后开放 |

首批宗门公事以可在宗门内完成的 `研习` / `值守` 等候选为先，不先把“采药、伐木、猎兽、修缮”等尚无确定资源或任务验证链的标题做成可玩任务。首期每一项必须有明确开始事件、完成事件和单次奖励；没有完成回调时宁可不发布。

### 同门私委

| 类型 | 标准目标 | 参数模板与核验条件 | 依赖阶段 |
| --- | --- | --- | --- |
| 切磋 | 与发布者或明确指定的同门进行一次非致死切磋 | 对手角色 ID、境界范围、战斗模式、胜负/完成条件；使用演练结果，不掉落物品，不自动增贡献 | 需稳定宗门角色及同门切磋战斗模式；不可拿天问峰对兽演练冒充 |
| 同行 | 陪指定成员抵达某地点并完成一件已定义行动 | 随行者 ID、目的地 ID、同行状态、到达/行动事件 | 需地图旅行、同行者跟随与路线事件 |
| 寻人 | 寻到特定人物并完成约定的会面/传话 | 目标角色 ID、允许地点范围、会面或传讯事件 | 需稳定 NPC 身份、位置与会面记录 |
| 寻物 | 找到并交付某个已存在物品 | 物品 ID、数量、交付对象；物品必须在正式图鉴中 | 需物品所有权与交付接口；未生成图标物品不可选 |
| 代办 | 执行一个已登记的简单代办模板 | 必须选择受支持子模板，如送信、交付或代为核验；不允许自由文本驱动任意效果 | 依具体子模板逐项开放 |

“切磋某境界同门”“陪某人去某地做某事”“寻找某个具体人物”都由上述类型和参数表达；文字可以鲜活，但目标、对象、境界、地点和结算条件须可机器验证。未来可以增加类型，但不能用泛化的“其他”绕开验证与资金规则。

## 七、让 NPC 委托显得真实

同门私委不应由无名、随机刷新的假角色无限发布。每份委托必须来自当前有稳定身份、境界、所在位置和明确需求的成员。发布动机来自角色职责、近期目标、手头资源或人物关系；同一人物的委托要有数量上限与时间间隔，不重复刷新同一句话。

前期委托发布者使用符合条件的程序生成同门；剧情模板人物以后续内容再加入，不作为当前功能前置。发布者必须使用稳定角色 ID，并将委托与托管状态写入当前世界/正式存档。随机生成只决定人物初次建立，不得在任务板刷新时重抽发布者。正式游戏存档接入前，不把 NPC 名册或委托状态写入独立的旁路存档。

委托人的境界影响其能提出的切磋对象范围与同行能力；其贡献余额决定能否担保报酬。承办者的境界只用于资格和提示，不自动决定任务成功。委托完成后，发布者可在已有关系系统内产生具体反馈，但反馈需有事件与理由；贡献奖励本身不等于好感，也不自动增加声望。

NPC 接单、拒单、改为自行处理或因目标变化撤回，都必须由角色目标、位置、能力、关系与资金状态等已存在数据驱动，并留下可读记录。第一版不做复杂谈判、竞价、多人抢单或主观纠纷裁判。

## 八、未来玩家发布委托

模板从第一天就把发布者与承办者作为通用实体字段，因此未来玩家既可接取 NPC 委托，也可作为发布者委托有稳定身份的 NPC；若将来支持多人，再扩展参与者类型而不另造一套任务格式。第一版不开放“写任意任务文本并自动实现效果”，玩家只能从已上线类型中选择参数。

未来发布流程：选择“同门私委” → 选择类型 → 选定对象/境界/地点/现有物品与可验证目标 → 输入有限长度的情境说明 → 系统展示报酬、受理费和总预留额 → 检查余额并托管 → 发布 → NPC 按身份/能力/目标/关系接单或拒单 → 游戏事件核验 → 自动结算并写入双方记录。

玩家发布的委托在本单机项目内，含义是“委托宗门 NPC 承办”，不是实时多人玩家市场。NPC 是否可接单、如何推进其行动、失败如何告知玩家，须依赖稳定的宗门角色名册和可复现的 NPC 月度演算；相关基础未具备前，先预留数据结构，不显示发布按钮或假装 NPC 已经完成任务。

## 九、首期制作顺序与验收

1. **分区与数据结构**：复用当前和光峰任务板控件，加入“宗门公事 / 同门私委”切换；任务详情与流水有统一字段，旧接取/取消行为不回归废案 UI。
2. **宗门公事闭环（已接入五项原型）**：和光峰任务板刊登“静室研读一卷”“瑶圃药园值守”“培育雾铃花”“东林地巡查”“上缴兽骨”。研习沿用已有章节完成事件；值守原型为瑶圃峰当值 4 个游戏时辰、消耗 2 点体力，正式修仙时间观下的完整轮值通常以数日计，当前缩短值仅供测试；培育在瑶圃峰照料幼株消耗 1 点体力，等待 24 个游戏时辰后采收现有雾铃花四株，其中三株交宗门、一株自留，原型核发 10 点贡献（高于普通短事务，仍为可调测试值）；巡查沿东林地标定路线逐节点行进并消耗游戏时间，东林地节点基础耗时暂定为遁速 100 时每跨一个相连节点 1 个游戏时辰，实际按当前遁速缩放，不为每条路线边分别指定固定小时数；抵达静冠洼地并完成路线复核后，通常记为“未见异常”，核发 5 点贡献，不采集资源、不要求携带物品；提交任务使用现有图标物品兽骨一份，提交后从行囊扣除并核发 5 点贡献。各项开始/阶段/完成记录在正式角色存档，贡献以唯一接取实例流水防重复；已交物品在事务流水中注明，但宗门公库的独立库存账尚未建设。取消事务不发贡献；以上时长、数量与贡献均为测试参数，正式长周期培育与数日值守仍待平衡。
3. **私委托管**：在稳定宗门成员名册与非致死同门切磋模式可用后，优先打通“与发布者/指定同门切磋”的托管闭环；若切磋战斗条件尚不具备，则先选另一个完全可验证的宗门内模板。流程为 NPC 发委托 → 校验余额 → 预留报酬和费用 → 接取 → 自动核验 → 报酬转账/失败退款。
4. **玩家发布**：稳定宗门角色名册、NPC 接单与月度行动可验证后，再开发布入口；使用同一模板与 10% 原型费率。
5. **地图任务扩展**：百川地图与到达/同行/地点交互稳定后再开放同行、巡查、寻人等跨地点任务。不得为了委托先改动仍在制作中的地图基线。
6. **晋升与兑换联动**：当前以宗门生态主案中标注的首轮测试价与晋升条件打通贡献兑换和普通弟子晋升原型；后续依据可获得任务次数、秘籍价值及游玩反馈调整，再确定正式价格/库存规则与晋升门槛。晋升读取境界和累计已核验的公事履职贡献，不读取可用贡献余额；天灵根真传不可由晋升获得。

首期验收必须证明：任务有清楚的发布来源；境界/地点/物品条件不超出已定义数据；私委余额不足时不能发布；50 贡献报酬能准确显示“报酬 50、受理费 5、合计预留 55”；撤单、退款、成功转账均只结算一次；贡献流水能解释每笔变化；完成、退款和关系变化互不混账；地图未完成前不会出现不可达委托；所有界面复用现有任务板、悬停和中央详情交互。

## 十、当前实装边界

- 东林地巡查原型至少推进四次相连节点，并抵达静冠洼地复核才完成；按实际路线节点推进计数，每步耗时使用副本节点基础值与当前遁速动态换算，不采集资源。
- 宗门公事当前开放静室研习、瑶圃值守、雾铃花培育、东林地巡查与兽骨提交五项原型；贡献、时长、数量和体力消耗均是可调测试值，不是最终平衡结论。巡查只按路线节点与动态行程时间核验，不采资源；节点基础耗时暂定为遁速 100 时每节点 1 个游戏时辰，实际随当前遁速缩放。培育大部分交宗门、小部分自留；长线设计中的培育和轮值周期均长于当前测试时长。东林地 NPC 按遁速同步移动、依性格/声望/立场选择攻击目标、进入既有战斗、掠夺实际随身物品及持久化 NPC 死亡均已接入首轮原型；不得把“夺宝”简化为 NPC 捡取地面掉落物。玩家主动攻击与逃离/保护选择仍未接入，详见《地点模板与节点互动框架》。
- 完成判定仅响应玩家在其身份对应静室内触发的现有功法章节完成事件；普通弟子对应观复峰，真传对应紫府峰。其他地点完成章节不代替该事务目标。
- 当前已有运行期随机生成的同门，但其个人贡献托管、明确需求与可自动核验的任务目标尚未接通，因此同门私委分区仍为空；不能把“已有随机 NPC”误写成“已有可发布委托”。
- 除上述五项原型外，清点/传讯/接引/核验以及私委各模板继续隐藏，待其对应数据与可验证事件落地后逐项开放。
- 贡献账本使用现有唯一流水接口；贡献奖励不会自动改变百川声望、势力态度或人物关系。
- 个人档案将可用贡献与累计公事履职贡献分开显示；后者统计正向的已核验宗门公事奖励，不随兑换支出减少。首轮晋升原型只读取此公事累计；同门私委尚未接入，因此既不计入也不预留其晋升规则。当前门槛为可调测试值，后续再根据任务与身份成长节奏平衡。
