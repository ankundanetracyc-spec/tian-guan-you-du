# 炼器与战斗场景资源释放验收

2026-11-04。接续[炼器至战斗接入修复](炼器至战斗接入修复与验收_20261104.md)，处理其保留的纹理、字体、CanvasItem及对象退出清理告警。本轮只修改界面资源所有权和释放时序，不改战斗、炼制数值或规则。

## 定位与修复

### 隐藏的旧技能栏控件没有归属场景

`CombatSkillBar.CreateBar` 创建了旧资源行、体力／法力格、队列文字等控件，随后隐藏，却没有把其顶层容器挂到场景。Godot节点不会仅因失去托管引用而自动销毁，因此退出一场战斗留下21个孤立节点；连续4场实测为21、42、63、84。它们还持有样式和字体，引起CanvasItem、FontFile、TextServer字体以及资源缓存退出告警。

现在将该隐藏容器明确挂入技能栏的列容器，保持原有隐藏状态与布局。技能栏销毁时整组子节点、样式及字体引用随场景释放，不再创建无人管理的界面树。

### 临时像素副本未及时释放

战斗界面纹理缩放、未导入PNG的备用加载、头像边界读取和光标缩放中，存在临时 `Image` 只依赖后续托管回收的路径。现在用明确作用域释放这些独有像素副本；不手动销毁共享的原始纹理、字体或其他场景仍在使用的缓存。

### 自定义光标比渲染服务更晚释放

无窗口退出已正常后，实际Windows/OpenGL窗口仍报告一个12280字节的纹理泄漏，随后出现 `ImageTexture` 析构时 `RenderingServer` 已为空的错误。它对应48×48自定义光标的纹理及其缩略层：全局输入系统一直持有纹理，直到渲染服务关闭后才释放。

`CursorSetup` 现在明确持有自己创建的光标纹理，并在自动加载节点退出时先解除全局光标引用，再释放这张独有纹理。修复后实际窗口关闭也没有相应的GLES3纹理或渲染服务关闭顺序告警。

## 循环验证

新增 `tools/SceneResourceLifecycleSmoke.tscn`，支持 `--mode=forge`、`battle`、`mixed`、`info`，默认每组先热身3轮，再检查20轮：

- 炼器走真实地点页面宿主，打开参考投料弹层，再逐层返回并确认页面释放。
- 战斗使用正式场景及战斗包，建立双方单位与界面，再结束器物运行态并销毁场景。
- 交替模式每轮进入并退出炼器和战斗。
- 检查场景及管理器不再有效、没有新增孤立节点；用弱引用确认页面独有主题及技能栏／队列样式可回收。
- 每轮等待延迟删除及两次托管回收，确认热身后资源数量不增长。实际窗口同时检查纹理显存不增长，并要求确实建立非无窗口渲染环境。

初次定位中，独立人物面板和炼器页面未产生孤立节点，泄漏来自战斗技能栏；没有把正常共享缓存视作泄漏或粗暴销毁。

## 回归与复现

完整回归已通过13组：原有炼制到正式战斗48项、跨进程读取19项、炼制集成48项、剑器适配64项、新材料24项、器蕴28项、器物运行态27项，自然／强制回收各40轮，以及上述四组场景进出验证。

编译为0警告、0错误。13组进程的退出日志均没有 `ERROR`、孤立节点／对象泄漏、资源仍在使用、纹理或字体RID泄漏。旧《卸力》资源UID回退仍是独立的既有警告，不在本轮修改卡牌资源。

一键回归：

```powershell
powershell -ExecutionPolicy Bypass -File tools/run_forging_battle_regression.ps1 -WindowedLifecycle
```

默认12组无窗口回归，`-WindowedLifecycle` 增加实际窗口组。脚本现在将运行错误和退出泄漏告警视为失败，不再仅凭成功标记和退出码0放行。

本轮指定日志目录为 `tmp/scene_resource_cleanup_20261104/final/`；汇总为 `tmp/scene_resource_cleanup_20261104/final_suite.log`。`battle_before_output.log` 记录原始孤立节点累积，`window_mixed.stderr.log` 记录光标修复前的实际窗口退出错误。测试使用隔离人物与场景，没有写入玩家旅程；现行费用、目标、关键词、伤害、锋锐及炼制规则均保持。
