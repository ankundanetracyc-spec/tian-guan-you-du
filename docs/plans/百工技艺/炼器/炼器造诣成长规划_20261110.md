# 炼器造诣成长规划（2026-11-10）

> 状态：首轮已接入，待局内试玩（2026-11-10）。本案记录当前运行规则；数值是首轮观察参数，后续可按进度和资源压力调整。人物的基础炼器造诣代表天赋，研习和实践只增加单独保存的固定造诣加成。
>
> 权威边界：制作过程以[材料与过程量驱动炼器设计](材料与过程量驱动炼器设计_20261022.md)、[炼器过程量与成器推导细案](炼器过程量与成器推导细案_20261022.md)、[器物系统现行主案](../../物品与装备/器物系统现行主案_20261023.md)及正式人物入口为准。旧剑类炼器试算中的 D 难度和 +0.25／+0.10 成长只属于旧模型候选；当前材料过程与成器模型不同，不沿用旧公式或旧结果。

## 一、问题与目标

角色创建时炼器造诣可在 0～10 之间设置，默认 5；造诣20、32、50分别解锁更多和材、辅体及性材位置。原先没有从初始值逐步解锁这些工艺位置的稳定路径。本轮加入器理入门和正式成器实践成长。

成长需要奖励工艺理解，而不是单纯的投料数量或成器价格。不能把旧炼器试算中的三器型、岗位数量、旧 D 公式或旧增量搬进新模型；实践难度必须由现行实际使用的材料、工艺过程与成器结果重新定义。

## 二、当前成长来源

| 来源 | 规划作用 | 发放边界 |
| --- | --- | --- |
| 器理入门 | 正式器作页顶部的“研习器理”按钮；不要求先达到更高工艺门槛。 | 每名角色一次，增加最多3点（当前造诣上限100）；每点消耗8点精力、1时辰。默认5升至8，消耗24精力、3时辰。 |

| 专题研习 | 后续可由新的材料工艺内容提供稳定成长。 | 本轮尚未接入，不影响当前规则。 |

不新增器种经验条、材料熟练度或通用工艺货币。成长进入人物单独保存的炼器固定成长加成，不改写代表天赋的基础造诣。

## 三、成器实践规则

### 可计入的结果

- 必须是正式人物已提交的真实炼器事务。配伍预览、独立试炼样稿、配方保存、库存检查、工艺未开始及空间／资源预检失败均不成长。
- 只有实际成功生成并提交器物，才触发首轮数值成长。合法启动但最终未成器的事务继续保留失败记录和材料／过程诊断；没有真实复盘入口前，不因每次失败自动发造诣。
- 本次炼制完整使用开炼前冻结的造诣、材料定义与工艺输入计算。成长在成器和资源事务提交后发放，只作用于之后的炼制，不回算本件器物的属性、化法、技能、器蕴、工时或精力。
- 一次炼器事务最多增加2点；额外投料、成品售价、自动命名或同类效果数量不直接提高奖励。若一笔成功事务带入多个新材料／岗位，全部记为已掌握，但本次仍只加2点，避免批量投料放大奖励。

### 当前里程碑

一项材料知识以正式成器快照为证：材料必须实际保留量大于0，身份使用稳定材料定义 ID，岗位使用成器时的正式输入岗位。相同材料在相同岗位再次使用不再成长；换用新材料定义或首次在新岗位发挥作用可形成新里程碑。未实际保留的投料不计入。

首次正式成器与首次炼成法器各有一个专属 ID。单纯重复成器、提高数量或价格不会奖励；同一笔事务的多个新 ID 只触发一次实践成长。

本轮不需要新建“挑战档”或更改成器公式。成长只确认实际成功结果和材料贡献；旧剑类试算 D 值及小数成长不沿用。

## 四、事务、精度与存档边界

- 成长须跟随真实事务提交，并与材料扣除、精力、历法、成器快照及炼器记录保持同一提交边界。重复提交、重进页面和读档不得重复授予。
- 人物 `forging_proficiency_growth_sources` 保存已完成教学、材料岗位和首次成器里程碑，`forging_proficiency_training_bonus` 保存固定成长加成；不解析玩家可读文本判重。旧角色缺少这些字段时按默认空记录开始，不追溯旧器物补发。
- 研习和实践增加人物炼器固定成长加成，不改写天赋基础造诣。有效造诣按基础造诣×适用成长倍率＋境界定额加成＋研习实践固定加成＋其他固定修正计算；已生成器物快照不重算。
- 成长采用整数+2，下一笔正式炼器会按现行取整后的有效造诣计算。有效造诣继续受正式评估器0—100范围限制。

## 五、首轮平衡判断与验收

定数值前至少需要：

1. 默认5点研习后为8点，消耗24精力、3时辰；当前首个额外位置门槛20、复合身材门槛32、第三和材位门槛50均在首轮实践可达范围内。
2. 当前炼器材料定义提供23种有效的材料×岗位组合；另有首次成器与首次法器两个里程碑。按来源总量粗算为58点（默认5天赋＋3入门＋25项来源×2）；首次成功的一笔事务会同时记下必需材料岗位和首次成器来源、但只奖励一次，故实际可达值会略低。预估仍有机会超过50门槛，需用基础配方逐炉验证；100仍是评估器硬上限，不代表当前内容能到100。
3. 只有成功成器提交后才检查来源。失败、预览、预检失败、零保留来源和重复材料岗位不成长；同炉多个新来源都记账但本次至多+2。
4. 下一笔制作读取成长后的整数造诣，当前成器本身与存档快照保留制作前数值；重复提交不重领。
5. 已完成 `dotnet build Stacklands.csproj --no-restore`，0警告、0错误。当前本机 Godot Mono 运行器在.NET模块初始化阶段未进入场景，故尚未完成人工鼠标试玩；需在可运行的 Mono 编辑器／游戏窗口观察20/32/50解锁速度、材料来源是否易理解及入门费用压力。

后续观察重点：默认5点是否能以合理炉次抵达20/32/50；课程和炼制成本对库存／精力的压力；不同岗位新材料是否容易被玩家理解为“学会了新工艺”；新材料和新器类加入后是否需要新增里程碑。旧试算小数奖励与 D 难度不作为现行成长规则。
