## 一 现行依据与改造边界

### 权威来源

- [云息期无剧情自由修行与玉虚宗门闭环](../../人物与修炼/云息期无剧情自由修行与玉虚宗门闭环_20261013.md)第三节：现有雾铃花无任务培护、个人收获、公事互斥与独立存档。
- [宗内生态补充](../../剧情与宗门/玉虚仙宗宗内生态补充_20261107.md)：日常与公事各按其真实归属和结果结算。
- [游戏历法与纪年显示](../../世界与探索/游戏历法与纪年显示.md)：游戏时间由主动行动推进，日期只显示年月日，持续时长可以显示小时。
- [UI 视觉规范](../../界面与美术/UI视觉规范.md)：水墨淡彩场景、浅纸深墨、峰内公共入口及 HUD 安全区。
- [行囊索引与空间联动方案](../../物品与装备/行囊索引与空间联动方案_20261029.md)、[储物戒指与行囊尺度修订](../../物品与装备/储物戒指与行囊尺度修订_20261104.md)：真实占格、空间校验、原子提交与戒内物品访问边界。
- [副本生态来源与刷新](../../世界与探索/副本生态来源刷新与多层地图提案.md)：已有材料与生境；野外刷新周期不直接作为种植周期。

以上是一轮培护的现有规则，不是多田经营的完整模型。多田各自产出、批量行动费用和总体供给需要重新设计，不能将示意图中的田块数量直接乘以当前 4 株产量。

旧农田与灵田的肥力、灵气字段没有足够的现行规则；旧辖地药圃产出抽象账本“药材”，不作为本系统实际收获，也不恢复青溪长期经营。

## 二 经营感从哪里来

### 田是实际经营对象

每块可操作田有稳定身份、独立页面和独立状态。田地入口负责选地，进入后只展示和操作这一块田。种下以后，该田页面长出对应的作物；采收后，植物消失并留下空畦。离开再回来、切换田地或读档后，种植安排应保持。

一眼能分辨“哪里有事可做”：空田可以播种，幼苗正在生长，成熟田可以采收，尚未开放的边缘土地与已耕田有明确区别。作物需要成行、成片生长，不能用放大物品图标代替整田植物。

### 推荐的经营决策

| 决策 | 玩家实际考虑 | 可见结果 |
| --- | --- | --- |
| 田地怎么分配 | 哪些田种常用药材，哪些位置留给下一批 | 不同田块有不同种植安排 |
| 先种什么 | 按炼丹需要或可交易材料选择，比较等待与投入 | 场景出现对应形态的作物 |
| 一起种还是分批种 | 集中安排一次收获，或错开几批成熟 | 园里同时出现空畦、幼苗、成株与成熟田 |
| 收完接着种什么 | 补种原作物，或在下轮改种 | 田块经历“空—种下—长满—收空”的循环 |
| 什么时候拓展 | 现有田是否够用，是否承担更多种苗与照料投入 | 荒地逐步整理成可用新田 |

这些是本案的推荐经营玩法，尚未配置作物平衡参数。首版应让数块田能独立安排；单株培护只可作为旧进度迁入的一块田，不再作为完整首版。

### 经营投入与回报

种植需要同时考虑可用田地、种苗、实际操作的游戏时间和精力；产出使用现有正式材料，可进入炼丹或既有交易。种苗是否消耗实物、从哪里取得、是否允许留种以及具体费用，都须在作物表中明确后实施。

先完成“相同基础地块、选择灵草、配置改造、对照需求、定植培护、采收”的闭环。各灵草有相应温度和环境灵力需求；水分、光照、土层与附着等具体条件逐种定案。水渠、泉眼、遮阴与培护设施需要真实规则，不因画面存在就免费产生供给或加成。

## 三 田园设定与内容

### 场地

地点承接瑶圃峰，每块地的独立页面以正俯视表现该地田面与田埂。相同初始条件下，地块先呈现同类基础状态，改造后再按实际添加材料及其他配置变化地表。装饰不赋予地块先天加成。

田地的法律归属和使用权限另行定案。“个人种植”只说明收获归玩家；可以是获得使用权的宗门田，也可以是以后明确取得的个人药田，不能仅凭界面授予土地所有权。

### 不同田地的差异

地块从相同起点出发，由玩家的改造形成适生条件差异。温度、环境灵力等仍会影响灵植，水分、光照、土层与附着条件及特殊需求逐物种定义。界面比较当前配置、改造预览与目标需求，不能把自然位置当成已配置效果。

可用田块需要明确范围；未来扩田必须对应实际开放的位置和已确认费用。示意图里的田畦数量、宽高和荒地面积只用于评审布局，不是正式容量或扩建档位。

### 作物

| 作物 | 已有依据 | 种植规划 |
| --- | --- | --- |
| 雾铃花 | 已有瑶圃培育与正式材料 | 作为首个完整田块样例，表现整田幼苗到开花 |
| 苦苔根 | 阴湿森林、湿地边缘的根材 | 后续候选；需先确认种苗、周期与收根后的田地状态 |
| 月露苔 | 阴湿岩地、林间浅洼的苔类 | 后续候选；适合通过低矮苔床与草本田作视觉区分 |
| 灵泉藻 | 水域与灵泉中的藻类材料 | 后续水生候选；设施与投入产出待定 |
| 朱阳花籽 | 当前已是正式工艺材料 | 不因名字带“籽”就默认可播种；产物定义与留种关系另定 |

新物种即使已经有材料图标，也不代表已支持种植。理想图可表达种植分区，但不能用候选图示反推真实物品来源或数值。

### 成长与材料品质

生长进度记录在田块中，画面表现为出苗、长叶、成株与成熟；这些阶段首先用于辨识长势。采收后仍是正式物品定义，不随摆放时间额外生成“百年”“纯净”或高品变体。

## 四 玩家经营流程

    到达药田 → 在田地入口选地 → 进入该地独立页面
        空田 → 选择目标灵草 → 查看环境需求 → 从行囊拖入或选中加入可用基质 → 查看环境与成长，需要时从独立入口进入阵法系统 → 满足条件后播种或栽植
        生长中 → 查看长势与成熟预期 → 按已定义需要照料
        成熟田 → 查看收获及归属 → 采收 → 留下空畦
        空畦 → 补种原作物／下轮改种
        拓展入口 → 查看拓展条件 → 条件定案后开放新田

### 日常的一轮操作

玩家从田地入口选择需要处理的田，在其独立主页面查看田面、长势和条件差距，需要改造时进入基质材料页，再到成长预览检查方案；阵法由独立入口接入。可以先进入成熟田采收，再切换到空田安排下一批；也可以保留某块空田，等取得想要的种苗后再种。执行的时间与费用应在确认时清楚列出。

这段情境只说明可选择的经营安排，不锁定首版田块数量和每轮产量。主角完成播种或照料后可以去修炼、旅行或炼制，这些行动推进的游戏时间也推动田里的生长。

### 查看与执行分开

选择田地仅进入该地页面，查看当前环境、灵植需求和长势原因，不直接播种、收割或扣资源。选种苗后，在确认处列出适生缺项、本轮成本、预期周期与收获归属；提交成功才改变田里作物、扣除投入并推进时间。

采收成功后，田块按该物种采收方式更新。满包导致入包失败时不能消费本轮收获，植株保留在田间并继续按正常环境规则生存；不因事务失败而枯死，也不因此获得永久免受环境伤害。

### 批量经营（后续候选）

当前按一块地一个页面逐田查看与操作，不在该页面混排其他田地的配置。批量安排与批量采收仅保留为后续候选，不作为本版入口或按钮。

若后续启用批量规则，须先明确每田成本如何合计、操作时间如何结算、某田不合格时如何处理，并保留逐田归属、真实物品占格和防重复结算。不能默认多块田只花一份费用。

### 宗门公事

公事仍从和光峰接取。公事田用清楚的田牌或用途标识表达交付责任，其产物和个人田分账；不能把个人田中的成熟花直接改为一轮已经履职的宗门培育。

现有个人与同类公事互斥规则保留为旧原型基线。若多田版本允许两种用途同时存在，须明确是否划分专用田位、各自额度和共享限制，再变更任务接取规则。一地一页的界面方向已经明确，这项并行机制仍待定。

### 基质发挥材料功用

基质即往原有田地加入其他实物，不设固定套餐，不默认替换整块土层。正式作用链为“实物加入田地—形成基质—材料功用按培育规则发挥—影响对应条件或培护结果—对照灵草需求与长势”。

沿用[物品词缀主案](../../物品与装备/物品词缀系统设计.md)十二功用及单项九品至一品，不另造基础词典，不用物品总品阶代替功用品级。筛选和来源清单帮助选材，实际发挥仍由材料、处理方式、适用条件与物种规则定义，不把生直接变为催熟或把聚直接换算成灵力增量。

样稿采用项目已有紫砂灵土、泥脉石团、兽骨、地脉焰炭：名称、图标、材性与单项功用品级真实，库存为演示数据。地脉焰炭仍属炼器燃料，可选择不等于已定入田资格；兽骨不等于完整遗骸。

列表先按行囊持有量与基质资格筛选，不能以具有功用替代正式入田资格；当前资格与库存为独立演示夹具，不是正式白名单。拖入右侧或选中数量后点击“加入”，立即更新本田材料记录及演示剩余量，不再另存方案。件数校验、同材合并、取消拖拽、重复投递、无效来源与跨田剩余数均须保持一致。当前不操作真实行囊或改土；计量、混合、持续消耗、替换、返还与费用待定。见[材料与遗骸](灵植生境与培育规则候选_20261107.md#添加材料与遗骸需求)。

### 阵法属于独立系统

田地概况正文只留当前田地的阵法打开入口，与基质操作并列；阵法退出顶栏。不设计具体阵式、布阵位置、数量、范围、配方、费用或功用映射；此前新增的三阵及其编辑器退出当前方案。基质功用清单只包含基质材料。

[现行阵法系统](../阵法/阵法系统设计.md)及其专题继续负责阵法规则；种植不把个人战斗的阵脉、阵源或触发直接换算为田地效果。后续需要的已生效环境影响由独立系统与正式培育规则提供，本轮不猜返回协议或数值。

### 培育详览

独立页面查看当前环境与本田已加入基质。默认清楚对照温度、环境灵力、水分、光照和附着条件，显示需求与不足；基质来源和投入清单按需打开。

月露苔为定性排版示例，雾铃花不臆造新需求。未定义的培育作用、周期与耐受时长不计算成熟日期、速度、概率、品质或产量。各必要条件不能互相抵消；持续不适先长慢、停长，持续严重不适才受损或枯死。完整结算仍按生境专题处理跨季、长行动与未知天气。

### 样稿状态与验证

视觉沿用项目木纸材质、楷体、深墨与整纸中灰绿选中反馈，不复制善功堂建筑背景。田面图继续暂撤，左侧生境、右侧灵植与长势，基质和阵法并列在正文下部。普通按钮22字／46高，实际加入22字／52高；数量为输入槽内上下三角，返回和切田同行。按下只移动整纸与内容，命中区不动；六态及减少动态效果按全局现行规范，完整说明与来源按需打开。

三块田不代表正式容量，加入记录仅存浏览器内存，刷新恢复，不读写真实人物、库存和旅程。v2.2 两档62项操作／排版回归、44项控件专项通过，另核对本地打开、四份材料、共用素材及脚本语法，见[验收与新截图](../../../美术规范/种植灵圃界面样稿_20261109/README.md)。v2.1 的62项、v2.0 的55项及更早记录分别归档，不计入本轮。真实生长、投料、费用、权限和存档未接入。

## 六 与既有系统衔接

### 物品与采收

材料继续使用正式物品定义与真实占格，种苗如需实物则另行定义。产物统一经既有物品事务进入普通行囊，不进入旧辖地的抽象“药材”账本，也不自动塞入储物戒指。

满包时田里的成熟作物保留，整理后重试。通用领取页结束会确认放弃未领取部分，与田里保留成熟作物的语义不同；未经来源边界调整，不能直接替换为该领取流程。

### 炼丹和交易

经营的回报可以是常用材料自给、为下一炉准备原料，或把实际剩余收获拿去交易。种植页读取正式材料信息，不修改丹方、药效和售价，不承诺 NPC 回购或自动给坊市补货。实际炼丹仍从天工峰丹房发起。

### 贡献、公库与灵感

个人田不因经过时间、查看或采收自动增加贡献。公事核验、交付、公库与贡献流水仍按独立任务来源结算；真实公库供料和跨峰生产没有随种植界面开放。

现行云息闭环主案已暂停灵感系统；种植不生成、预约或消费灵感，不恢复旧采集加成，也不引入小说式收获光团。

### 时间与平衡

游戏时间仍由主动行动推进。播种和照料花费其明确时长，作物生长不持续占用主角；现实等待、关闭界面或离线均不产生生长。

当前单轮雾铃花的 24 小时与野外慢生点 30 日恢复属于不同测试配置。多田经营必须结合可用田数、种苗供给、主角投入、实际材料用途和交易收益一起评估，不能直接把旧单轮变成无限供给。

## 七 实施拆分与待定规则

### 必需的数据变化

现有一份人物培护状态无法记录几块田各自种了什么、何时成熟。多田经营需建立田块记录：稳定地点与田块身份、支持物种、是否可用、本轮作物、用途归属、开始时间和采收阶段；旧雾铃花进度迁入对应田块，不能复制到多块田。

田块数据独立于界面图片和控件存在。成熟可以通过游戏时间推导；不为每张图创建现实时间计时器。个人与公事是否共用可用田位、是否并行，需要先定规则，再扩展任务限制。

### 制作顺序

| 阶段 | 交付 |
| --- | --- |
| 生境与信息结构 | 确认物种条件、地块差异、逐步恶化与补救，再重做环境检视和条件对比的 UI |
| 多田最小闭环 | 不同田位可分别种下、生长、采收，画面状态持久化；先用已定义作物验证 |
| 经营选择 | 按已确认的种苗、投入和物种表加入选择、补种与改种 |
| 场地拓展 | 明确田权和条件后，把可开垦位置变为实际可用田 |
| 扩展生境 | 需要时再加入苔床、水生田或个人洞府药田 |

### 实施前待定

- 田地取得方式、玩家可用地块数量、可用范围与扩田费用。
- 新版种苗取得与消耗、每田作物周期、产量与主角操作费用。
- 逐田或批量操作的成本合计方式。
- 照料能否改善结果，以及与不照料的区别。
- 个人田与公事田的容量、归属和并行限制。
- 若依托租约，租期结束时在田作物、成熟收获及迁移如何处理。

本轮按已明确的经营方向修订规划与理想图，上述未定项不转换为正式数值或游戏实现。

## 八 验收

- 选地后进入对应独立页面，只展示该地田面；页名、环境、植株和操作归属一致。
- 无需展开额外说明，即可在田面分辨空田、幼苗与成熟田；田里是成片作物。
- 种植、采收与实际改造具有可见结果；当前田面不显示待提交预览，未实施的拓展不伪装成可执行按钮。
- 环境检视、条件对比与操作信息不遮挡地块，查看不扣费、不改变环境或长势。
- 多田进度独立保存，离开、返回和读档不重置种植安排、不复制收获。
- 单击选田不扣费；执行成功才扣投入、推进相应操作时间。
- 满包失败不消费产物；田间植物继续按环境规则结算，已采收物品不因田地后来受灾被追回。
- 个人产物、宗门交付与贡献分账；候选物种和图中田数不当成已实装规则。
- 接入游戏后验证适生、持续不适、受损恢复、枯死、跨季长行动、采收、空间及存档；查看和读档不能重抽环境或清空不适历史。

本轮为方案和视觉方向修订，不代表多田经营已经接入或通过游戏内测试。
