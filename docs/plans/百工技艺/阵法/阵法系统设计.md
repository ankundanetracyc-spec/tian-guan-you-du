## 一、底层边界

阵法严格分为两条线路：

```text
战斗事件 → 输入感应枢 → 脉纹（阵脉信号）→ 逻辑元件 → 阵器控制端
阵源（阵能） ─────────────→ 灵络（供能） ─────────────→ 阵器
```

- **控制信号**不作能源或费用。旧事件脉冲保留来源标签、振幅和发生时刻；新状态控制按本轮改革分为事件、持续开关和有单位数值，接口不能混接，也不能把数值信号当阵能。
- **阵源**是可存储的阵能。阵器即使收到控制脉冲，也必须通过阵源余量、阵源峰值、灵络峰值和阵盘峰值负荷四项检查才能启动。
- 脉纹仅传信号；灵络仅供能。脉纹合流不会放大振幅，多个脉冲也不会合成为能量。
- 阵法只服务一个角色；局内按已保存阵图自动运行，首期不允许战斗中重新接线。
- 不增加阵刻或第二时间轴。事件只能来自已有的回合、出牌、受击、周天或行动条系统。

## 二、取得与成长

| 来源 | 决定内容 | 不决定内容 |
| --- | --- | --- |
| 阵法录 | 可感知的战斗事件（输入）与可调用阵器（输出） | 逻辑元件、直接伤害倍率 |
| 阵道造诣 | 可用元件与阵法图谱 | 火雷等输出种类 |
| 阵盘 | 格位、脉纹层数 | 免费启动阵器 |
| 阵源 / 灵络 / 灵容 | 储能、持续回复、瞬时峰值与爆发 | 信号数量 |

阵法录可以混搭：周天类阵录提供输入，离火类阵录提供阵器，二者通过玩家布置的脉纹连接。阵旗等持续实体遵循战斗总案的灵识占用；阵器自身的阵能不是第四种卡牌费用。

实现中阵法录使用 `FormationManualData` 与端口资源表达；角色快照只保存已解锁的阵法录 ID，阵图声明所需 ID。战斗载入时若缺少任一阵法录，整张阵图不会启动，避免只复制布线绕过接口门槛。

## 三、云息期的阵道成长

2026-11-09 机制审阅补充：用户要求逻辑复杂度来自真实需求，见[功能规格与交互验收稿r1](阵法逻辑元件功能规格与交互验收稿_20261109.md)及[需求与电路参考](阵法复杂逻辑需求与执行闭环提案_20261108.md)。单路基础护持推荐直连；候枢是选配控频，不增单次效果、不减单次费用，下方三候样例仅展示计次。r1观频记录本窗与上一窗，不拦即时补防；高阶记忆、状态判断与成功回执仍为待审扩展，不因已有独立演示便视作云息首期已开放。

云息不一次性交出全部基础元件，而是让玩家依次学会“触发、筛选、频率控制、多路组合、精炼布局”。每个节点只解锁一种新的思路；后续精炼版优化格位，不直接提高伤害、振幅或阵能。

| 阵道造诣 | 解锁 | 核心学习 |
| ---: | --- | --- |
| 5 | 感应枢、脉纹、单阵器 | 一个事件触发一个效果。 |
| 15 | 鉴脉门 | 按来源或振幅筛选信号。 |
| 30 | 候枢 | 每 N 次事件输出一次，抑制高频。 |
| 45 | 节律枢 | 固定频率放行，构成稳定自动阵。 |
| 60 | 分脉枢、合脉枢 | 分流多个效果，或汇集多类事件。 |
| 75 | 基础元件精炼 | 同功能但占用更少阵盘格位。 |
| 90 | 云息圆满阵图 | 混用多个阵法录，完成基础组合电路。 |

候枢的“每三次”记录的是元件状态，绝不是玩家持有三点阵脉。精炼版例如将普通候枢的“2 格位”压缩为“1 格位”；供能与效果完全不变。

暂不开放迟脉、锁机、翻机、同曜、扬脉、律枢、断脉、主动阵门、反馈与状态机；它们保留给云息后的时序、状态记忆与自动控制阶段，需在后续专题中分别定义。

首期运行时已接入 `turn_start`、`card_played`、`spell_played` 三类事件，并预留 `cycle_completed` 供公共炁资源的“完成周天”结算接入。`spell_played` 的当前实现以实际支付法力的出牌为准，避免先凭文本关键词猜测术法。

### 样例：云息·三候护持阵（计次教学）

```text
打出消耗法力的术法
 → 术法感应枢
 → 三候枢（每 3 个脉冲）
 → 护持阵器
 ↘ 阵源支付 2 阵能，且阵源/灵络/阵盘峰值均须至少为 2
 → 获得 2 点护持
```

其配置在 `resources/formations/云息周天护持阵.tres`。阵器每个自身行动最多启动一次，故高频出牌不会绕过候枢与供能约束。

## 四、硬件与材料词缀

物品词缀仍只描述性质；阵法组装阶段读取它们，产出固定的硬件参数，不能直接给材料绑定战斗效果。首期的确定性映射如下：

| 词缀 | 可影响的硬件字段 |
| --- | --- |
| `功用[通脉]` | 灵络峰值 +1 |
| `功用[蕴灵]` | 阵源容量 +1 |
| `功用[聚灵]` | 每自身行动阵源回复 +1 |
| `功用[纳气]` | 阵源瞬时峰值 +1 |
| `功用[坚韧]` / `功用[固本]` | 阵盘峰值负荷 +1 |
`护体`、`震雷`、`回春`等功用只作为相应阵器、阵枢或配方槽位的要求；它们不绕过阵法录的输出接口，也不自动产生效果。阵法配方不再使用阵眼槽位。

## 五、数据、校验与运行顺序

`FormationCircuitData` 保存阵图；`FormationHardwareData` 保存硬件；`FormationNodeData` 保存元件；`FormationWireData` 保存脉纹。进入战斗后才生成 `FormationCircuitRuntime`，其中保存阵源余量、候枢计数和本行动已触发阵器，战斗结束即丢弃。

载入前必须校验稳定 ID、元件 ID、脉纹端点、阵盘格位和阵道造诣。基础线路在执行前拒绝反馈环及非法分合连接；同一次发生每件只处理一次，分合不复制计数或费用。原128跳安全边界仍是上限，当前硬件最多64件且基础程序无环。阵器收到控制请求后仍须通过实际供能、资格和生效检查；首期仅允许护持、当前回合法力回复和法术伤害三类已有战斗效果。

## 六、百工入口

百工以法宝、丹药、符箓、阵法四个置于面板外沿的页签切换。四页共享入口与视觉框架，但不共享制作规则；法宝、丹药、符箓在各自专题定稿前只显示说明页。

阵法页固定为三栏：左栏展示阵法录端口和按造诣锁定/解锁的元件；中栏为阵盘与脉纹/灵络布线区；右栏实时显示格位、阵源、灵络、负荷及无法运行的具体原因。首期提供“三候护持阵”的装配示范，后续在同一区域加入拖放与自由接线。

后续实现顺序：先将阵法录、局外装备阵图与战斗快照连通，再制作完整的可视阵盘编辑器与布线交互，最后按境界逐步开放时序、状态和主动操阵元件。
