## 一、先回答为什么不全部触发

如果同一种输出每次都值得发动、能量足够、没有更优先的用途，**直接触发通常就是合适方案**。候枢不是升级必经件。

计次既不增大单次效果，也不降低单次费用；把六次输出减成两次，同时也少得到四次效果，不能只记节省的阵能。若阵源本来会回满，少触发还可能浪费回复。

已有执行限制也不能再包装成候枢的收益。例如同一限次窗口最多成功一次，连续收到六个合格事件：

| 接法 | 实际行为 |
| --- | --- |
| 直连 | 第一次符合资格时成功；其余因原有限次免费跳过 |
| 三候 | 第三次才尝试；第六次仍受同一限次约束 |

在资源足以支持该次输出、早护持有用等相同前提下，两者都只付一次成功费用，三候却推迟响应，还多占格位和复杂度。无能、峰值不足和限次失败本来也不扣阵能，候枢到N后失败还会归零，不会存着等补发。

因此本轮建议：**单路基础护持继续推荐直连；候枢保留为选配控频工具；三候图只作计次和摆法教学，不再作为“更强护持”的进阶示范。** 当前已定效果尚未证明一种必须计次才获得收益的需求，不为它补造蓄能、增伤或免费输出。

需要计次时，玩家必须能够说出“为什么愿意少触发或推迟”。单凭已有合格信号数量，不如真实状态判定精确；有实际条件接口时，应优先按条件控制。

另须区分两件事：候枢“每N次放行一次”是在降低输出频次；“统计当前窗口内是否连续受袭”是在识别输入模式。后者可以有真实战术需求，但不能把这种价值冒记在前者名下。详见第十节。

## 二、选一个真实的复杂需求

候选阵法：**受袭护持与余力反击**。玩家选择的是保守资源策略：

1. 一次敌方直接伤害动作结算完，本人仍能战斗，才处理本次响应。
2. 已有护盾时保留现有防护，不再补盾；无盾时先尝试护持。
3. 补防失败，本次结束；即使余能买得起较便宜的攻击，也先保留资源。
4. 记住这笔尚未满足的补防需求，之后遇到新的合法供能／可用机会再检查。
5. 已有护盾或本次护持实际成功后，只有当前阵能还允许“支付攻击，并留足下一次护持费用”时才尝试攻击。
6. 后来补防成功只补防，不补打一记旧反击；攻击目标、费用和效果沿相应图谱。

这个策略有取舍：少补无必要的护盾、避免攻击抢走补防资源，但可能放弃立即攻击。它不保证比持续叠盾或全力输出永远更强，也不能挽救已结算的致命伤。

设护持实际费用为`C护`，攻击实际费用为`C攻`。本例的转攻条件为：

```text
本次确有合格受击原因
且当前已有有效护盾
且当前阵能 >= C攻 + C护
```

`C护`、`C攻`读取真实成器与图谱，不在本案猜数值。源峰值、灵络、盘体负荷、合法目标、冷却和限次仍由执行器检查；这条预算条件只表达玩家额外希望留下的防护余量。

预算通过会把“本次攻击提交后至少剩C护”的约束绑定到本次实际执行请求，最终预留与提交时原子复核`实际余量－C攻 >= C护`。只扣C攻，C护不是新资源或另一笔费用。不能只在逻辑门里看一次余额，之后任其他支路消费，再用旧判定继续攻击；同源的其他进攻支路也须纳入同一保底约束，否则界面应提示此策略未覆盖该支路。原子复核属于执行协议，不增设一件“锁元件”。

## 三、复杂逻辑到底解决什么

| 能力 | 缺少时的具体问题 | 本例中的职责 |
| --- | --- | --- |
| 状态条件分路 | 有盾、无盾仍执行相同行为 | 无盾先补防，有盾进入转攻检查 |
| 执行结果依赖 | 发出护持命令就误当护盾已经得到 | 只有护持实际生效后，才开放后续转攻支路 |
| 一位需求记忆 | 无能时丢掉响应，后来有能也忘了补防 | 记住“曾遭袭、补防尚未完成” |
| 预算条件 | 攻击把下一次补防的钱花掉 | 攻击前按当前余量预留一次护持费用 |
| 原有筛选与合流 | 恢复机会被误当旧受击，或支路重复发动 | 只让本次受击响应链进入攻击；合并互斥支路并去重 |

不把已有费用检查、限次检查另做“扣能枢”“限次枢”。单纯规定先护后攻，也不足以证明还需要一堆优先门、与门或锁；它们不进入本例。

记忆是否必要，可以用两个历史检验：

- 甲：未遭袭，现在无盾，有可用阵能。轮初到来，应保留阵能。
- 乙：先前遭袭且补防失败，现在也无盾、有同样阵能。轮初到来，应重新检查补防。

两者当前外部数值相同，但目标行为不同，因此需要一位历史状态。若玩家选择“任何时候无盾就补”，只按当前状态检查即可，应去掉这位记忆。

## 四、最小新接口与元件职责

### 鉴态枢：一个条件的二路判断（候选）

一个请求入口、条件成立／不成立两个信号出口。每件只检查一个已授权判定，例如“本人护盾是否为0”，或本盘内部“余量是否满足本次预算”。它不接供能线，不凭逻辑资格读取所有人物、敌方意图或隐藏属性。

人物状态的观测范围由图谱授予。本盘源余量、真实阵器费用等自监数据也需要明确的接口白名单。判定在该请求真正处理到此节点时读取当前状态，不能拿护持提交前的旧快照冒充提交后的结果。

### 锁控枢：一位记忆与条件转发（候选）

存储一个布尔状态`P`，本例含义为“有一笔待补防需求”，初始为0。功能端口如下，暂不指定尚未批准的实体足迹与复杂度：

| 输入 | 处理 | 输出 |
| --- | --- | --- |
| 置1 | 先把P设为1 | 从“为1”出口转发本次新脉冲 |
| 置0 | 把P设为0 | 不转发；本次状态写入在此结束 |
| 查询 | 读取当前P | 从对应状态出口转发本次新脉冲 |

它保存节点状态，不保存受击脉冲、攻击目标、阵能或一份已付费效果；多个受击需求合并为一个P，不累计“欠了几次盾”。没有新输入时不会自己发信号，也不新增持续电平线或第二时间轴。本例查询为0的出口不接动作；置0是纯写入，不兼作攻击许可。

### 执行成功回执：阵器接口扩展（候选）

高阶执行接口需要把“请求已收到”和“效果已生效”分开。护持阵器仅在实际提交了正数护盾增量后，从真实成功口发一枚回执脉冲；检查失败没有成功脉冲。

本例不需要再摆一个独立“回执枢”，也不强制增加失败输出口：先记下需求，成功才清除，没有成功就自然保留。失败原因仍由执行记录展示。

现有护持件只有信号入口与供能入口，不能偷偷借金线返回结果。本扩展必须定义可用的新信号出口和硬件形态，之后再核验足迹、复杂度、造诣及布线。当前4×4模型通过的三候图不证明本例能装入基础盘。

### 复用已有逻辑

- 鉴脉门按保留的响应入口标签筛选：本次受击链可进入攻击，新的恢复机会不可补旧反击。新协议须明确这类可筛选标签白名单，不将鉴脉门变成任意状态查询器。
- 合脉枢汇集“已有盾”和“补盾成功”两条互斥后续支路，并保持同一原始事件身份。
- 分脉只在确需把同一输入送往不同职责时使用，不做分完立即原样合回的空转。

## 五、完整处理流程

输入需要三个来源：图谱许可的合格受击事件、真实源回复／原有限次更新等既有结算机会完成后的新通知，以及本人护盾实际增加的观测通知。可用机会只依附项目现有结算时钟，不另开阵法计时器。

护盾实际增加通知只撤销已满足的补防需求，不触发补盾或攻击；它读取实际提交的增量事实，不把“别人尝试给盾”当作已恢复。需要这一输入，是为了处理“别人已补盾，后来又失盾”的历史：旧需求应在真实补上时结束，不能拖到下一次轮初把旧需求复活。没有相应观测授权时，这个完整策略不能通过图谱校验。

```text
新的合格受击 ──置P=1──┐
                       ├→ P=1支路 → 检查当前护盾
新的合法机会 ──查询P───┘                  │
                               有盾 ─────┤
                               无盾 → 尝试护持
                                          │
                                  实际成功回执
                                          │
                  已有盾／护持成功 ──合流──┘
                              ↓
                            分流
                     ┌────────┴─────────┐
                   清除P             筛选响应入口
                                  非受击：本次结束
                                  本次受击：预算 → 攻击

护盾实际增加通知 ──只进入清除支路──→ 置P=0，结束
```

查询P为0时直接结束，不产生攻击。无盾分支没有护持成功回执时，当次传播结束，P继续为1。因恢复机会发起的新护持，即使成功，其响应入口仍是恢复机会，不会变成一次受击。

“已有盾／护持成功”的动作合流与“所有清除请求”的状态合流分开。后者可把外界补盾和本次完成写入同一置0口，并对重复清除去重；它只有清除出口。不能让补盾观测先占掉动作合流的去重位置，吞掉稍后的真实成功回执，也不能沿清除口进入攻击。

事件身份与响应链类型分开记录：原始事件ID用于去重、共享峰值与费用归属；响应链入口类型用于区分“本次受击”“机会重试”“只撤销需求”。实际护盾增加即使由本阵当前护持造成，也以“只撤销需求”入口处理，保留其原始预算归属，绝不因此开放攻击。原护持成功回执则继承其执行请求的入口类型。普通逻辑件不能伪造受击入口类型。

主动停用整个阵盘时，视为取消本策略的未完成补防目标，清P；停用期间不接收补盾观测或其他输入，重启本身不重试。之后只有新的合格受击才能重新建立需求。这样不会在观测中断后继续使用无法验证的旧历史；该取消不清阵源、候枢计数、输出费用账本或原有限次。正常启用且跨轮时，P继续保留。

置1口先完成该次写入，再转发该次脉冲；置0口只写不转发。查询口只按当时状态选择一条出口，不把所有输入同时广播至所有出口。同一次响应传播结束前完成它的状态写入，期间不插入下一个外部伤害动作。

## 六、资源与执行事务

1. 发送命令不扣阵能，不占成功次数，也不算效果已经得到。
2. 执行器检查真实资格、目标、费用、全部供能限制和原有限次，连同该请求的最低剩余阵能约束原子复核，随后预留本次额度；预留与提交之间不能让未计入账本的同源消费穿入。
3. 效果、费用和成功账本作为同一次提交完成；提交失败撤销预留，不留下“付了钱却当成功”的中间状态。
4. 提交完成后才发成功回执。护持成功特指实际增加了正数护盾；不能把动画播放或命令送达当作成功。
5. 回执及其后续攻击保留同一原始事件身份。**先护后攻仍累计使用同一事件的共享峰值**，不因串行执行或收到回执重开额度。
6. 若基准峰值只够一次护持，本事件便只能护持；不能把本例宣传为基础硬件必定同时反击。
7. 攻击在其自身条件下失败，本次结束，不保存待反击。合法攻击提交后被防御或免疫抵消，也不因此返费或循环重试。

有效成功回执至少关联原始事件、响应入口、实际请求、执行器实例和结果；派生消息可以有各自消息身份，但不能替换其原始事件或伪造受击入口。请求与回执各自防重复；同一实际请求的成功回执身份稳定，重发不是一条新回执。

现有执行入口尚未提供这套可接线的结果契约，旧实现的先扣能再调用效果也不能直接充当它。本例需要明确的执行接口改造，不能仅靠画出成功线宣称已经闭环。

锁控枢在同一原始事件内可能先接“置1”，后接成功导致的“置0”，因此不能仅用“整元件本事件访问过”把后者误删；逻辑转发防重复应识别操作口和稳定消息身份，执行回执另按实际请求防重复。普通信号环仍拒绝，结果只允许进入有定义的后续／状态写入，不将回执送回原始受击入口无限发动。

## 七、状态与失败处理

| 情况 | P与输出的处理 |
| --- | --- |
| 新受击后仍有盾 | 置P后立即复核并清P；进入本次转攻预算检查 |
| 新受击后无盾，护持成功 | 清P；按当下余量及全部限制尝试本次攻击 |
| 无盾但缺能／本次峰值不足／原有限次已用 | 无成功回执，不扣本次费用；保留P，本次不攻击 |
| P存在，新合法机会到来且仍无盾 | 按当前条件发一条新护持请求；失败也只试这一次 |
| 本人护盾实际增加的已授权通知 | 清P，不重复补盾；该通知仅撤销需求，不触发攻击，即使稍后又失盾也不复活旧需求 |
| P为0，只有新恢复机会 | 保持空闲，不因有余能便自动补盾或攻击 |
| 护持阵器暂不可用 | 无成功回执，结束当次支路并显示原因；不靠逻辑修复部件或免费输出 |
| 主动停用／重启同一件盘 | 取消本策略P；停用期间不观测或追补，重启无自动输出；原源余量、计数与费用限次不刷新 |
| 人物退出战斗、阵盘实际实例终止、战斗结束 | 清除P、处理中请求及本场去重记录；不恢复其他系统长期耐久 |
| 攻击目标已不合法或攻击失败 | 本次攻击结束，不留下未来补打的请求 |

“新的合法机会”必须是确实发生的已授权事件；没有此入口就不能得到自动重试。不得每帧轮询、原地重发直到成功，或把旧受击事件排成待释放队列。

## 八、受击、目标与连锁边界

- 本例按一次敌方原始直接伤害动作结算完后检查，要求该动作实际造成过本人的护盾或生命减少。多段属于同一动作时只输入一次；不按动画、通知次数或分支数重复触发。
- 本人已失去战斗资格就停止。本次之后生成的护盾只保护未来伤害，不倒改刚结完的伤害。
- 本例排除自身费用，以及阵器、反震等派生伤害重新触发本阵，避免双方阵器互相反击成环。其他伤害输入须由其图谱另外明文定义。
- 攻击阵器按其图谱选择合法目标。若要精确打回原攻击者，需要相应来源身份和目标授权，不能从旧普通伤害输出自动推导出这个能力。
- 人物护盾沿现有公共`shield`读取，不另存“本阵已经有盾”的替代标志；不新增第二条护盾资源。
- 处理这条同步控制链时不插入新的外部伤害动作；否则成功后还要重查保护状态，需另定义插入时序，本稿不混用两套规则。

## 九、验收问题与后续落地顺序

本稿按事件表核对以下结果：有盾少补、无盾先补、缺能不误攻、恢复不补旧反击、外界补盾即时撤销旧需求、多次受击合并一位状态、多段／回执不重复计费、共享峰值不因回执重开、并发消费不能穿过最低余额约束、停用取消目标而不刷新费用限次、致命伤不逆转、输出失效不免费修复。

落地顺序建议：先确认上述玩家策略，再确认状态观测和成功回执契约，随后定高阶锁控／鉴态部件的占格、复杂度与端口，最后才绘制铜纹图标并验算可搭建阵盘。现有基础盘、四件基础图和五件逻辑图继续保留；本轮没有新建战斗卡、改动效果数值或实现这些高阶接口。

补充审计：旧护持资源的材料补正会影响实际源容量、回复和峰值，不能把raw字段4／1与effective字段5／2混为一组正式成器。此前基础重排的无补正测试成器也不可冒称旧运行实值。本文用真实费用符号及实际可用量表达策略，避免用混算资源证明计次价值。

## 十、信号强度、真假与频次

2026-11-09补充。用户进一步提出信号的大小、高低频率，并要求借鉴实际电路。本节把原主案已有的“来源、振幅、发生时刻”细化为可用信息，仍为待审协议，不冒称旧运行已携带全部字段。

### 一次信号携带什么

| 信息 | 含义 | 在阵法中的用途 |
| --- | --- | --- |
| 来源与身份 | 谁的哪一次已授权事件；保留原始事件和响应入口 | 分清受击、施法、恢复；分流汇回时防重复 |
| 强度／幅值 | 这一次事件有多大，并带明确含义与单位 | 比较重击与轻伤，或比较已授权的实际施法用量 |
| 发生时点 | 现有战斗窗口ID、动作顺序和事件序号 | 统计同一规则窗口里的频次与先后关系 |

“条件成立／不成立”则是判断后的逻辑结果，不是另一份阵能。单个脉冲不直接拥有一个可信的“频率值”，频次需要统计多个真实事件。

普通发生型输入仍可表示“一件事发生了”。数值型输入只有图谱授予相应观测时，才携带真实数值。不同单位不直接比较：法力消耗与伤害量不是同一个尺度；类型不符不能默认为通过。

本例受击幅值候选采用“一次原始敌方直接伤害动作实际造成的护盾损失与生命损失”，按实际伤害结算记录累计，各段只记真实损失，不用动作前后净差代替，中间治疗也不抹去已经发生的伤害。完全无损、主动费用及不在授权范围的派生伤害不产生本例的合格受击幅值。其他输入的幅值含义由其图谱单独声明。

幅值保留被观测字段的实际精度，强弱阈值是图谱／构筑参数，不能用旧编辑器整数导出范围直接冒充所有事件的统一尺度。普通逻辑与合流不把观测数值改大；强信号不会自动增加盾量、伤害或供能，输出仍走实际图谱、成器和费用。

### 观频枢：记录密集事件（新候选）

2026-11-09 r1将统计与分路分开：观频一入一出，记录后继续传递受击；后续鉴态按统计值判断，不能把补防挡在计数阈值后。这与现有候枢、节律枢分别定义：

| 功能 | 行为 |
| --- | --- |
| 候枢 | 数够N次才放行一次，到N后重新计数；其他事件不继续输出 |
| 节律枢 | 按既有图谱频控规则调节已有信号的放行；本稿不补其间隔数值 |
| 观频枢 | 记录本窗截至当前的独立合格事件次数及上一实际结束窗报告，附快照后继续转发当前受击，不延迟第一击 |

首个频次范例使用项目已有的共同回合窗口，不换算现实Hz，不增加阵刻。入口须连接图谱授权的原始合格受击和真实窗口边界；没有隐藏免费时钟。每个新的受击观测先检查窗口、按原始动作及主体去重，再把当前计数加1并附统计快照。一个重击事件的次数仍是1；分成两根线、收到重复通知或执行回执，不会变成两次。回执保留原快照，不重新观频。

计数达到密集阈值后仍累计，不像候枢到N就清零。真实边界先封存旧窗次数与完整性为上一报告，再开新窗；边界不从受击出口转发，不清P、不产生补防或攻击、不刷新阵源和输出账本。若实际回复或资格变化同时发生，另由其真实结算发一个合法机会通知。

当前窗使用“从窗初到现在观测连续”的前缀可信标记；上一窗使用“整窗结束且观测完整”的报告标记。中途启用或停用造成缺口时，不补造事件，保留已观察次数并标不完整。已看到的次数达到阈值，可以确认密集；未达到且有缺口则未知，保守地不开放攻击。

上一报告必须是上一实际结束窗，不能跳过不完整窗引用更早低压窗。完整低压窗／空窗结束后可替换旧高压或未知报告；完整空窗次数为0。真正从开战首窗监听时，无前窗可作中性；重启不能洗成无历史。重复、迟到边界不能重置新计数。即使连续监听，当前低频也只代表截至现在，不能预测后面不会再受击。

同窗累计损失、最大单次幅值可以作为后续另明文定义的统计判定；它们是历史数据计算，不能由合脉枢直接相加，更不会合成阵能。本轮不强制增加这些统计类型。

### 大小与频次怎样产生实用判断

可以区分“单次很重”和“单次较轻但连续受袭”。两者分别由幅值比较和窗口统计识别；实际阈值待图谱、输出代价与平衡共同确定，不为正式规则强填3次或某个伤害数。交互演示的N只作可切换场景参数。

本稿保守策略可加一个可选条件：本次重击，或本窗／上一实际结束窗已密集时，保留护持与补防恢复支路，暂不开放可选攻击；无已知高压但统计不可信时，也不开放攻击。轻度、分散且观测可信的输入照常检查转攻预算。**强弱／密集判断只控制可选攻击，不把基础补盾延迟到第三次才发生。**

保留上一窗有实际用途：若攻击本来每窗限一次，仅拦本窗第三击可能毫无区别；上一密集窗还会影响下一窗首个合法攻击。完整低压窗结束后，下一份真实受击再恢复通常判断；报告本身不发动攻击。这是玩家选择的储备策略，不提高效果或降低费用。当次重击只停当次，不默认跨窗记住重击；当前与上一计数即可派生判断，不强加一位守备状态D。

这带来有需要的条件组合：“已有护盾且满足转攻预算”才能攻击；“本次重击或当前密集受袭”则保留防护支路。与／或针对同一请求中含义明确的判断结果，可以用有先后定义的分路组合表达；不能把两个独立事件恰好同时到达当作普通与条件。若条件包含“之前发生过”，先用记忆记录，再由当前新事件查询。

没有这个资源取舍需求时，继续用简单直连即可。丰富信号内容的价值，是让玩家表达不同条件下的不同决策，不是保证多装一件就更强。

### 保持两类线路与现有画风

朱砂线传事件及逻辑判断，赭金线供阵能；仍是两类线路。强度、统计值与0／1记忆都不作为可获得、储存和消耗的新战斗资源。状态记忆在元件内，条件口在收到新脉冲时判断，不把它偷换成未定义的持续电平或第三线路。

线宽继续帮助区分细信号与宽供能，避免拿“更粗的朱砂线”表示事件更强。强弱与频次宜在节点小标记、选中信息与悬停数值中说明；脉冲表现只对应真实事件，不为美术动画复制输入。元件外观继续以已选铜纹版为准。

2026-11-09后续：[基础五件实际实现](阵盘基础逻辑元件实装_20261109.md)已使用独立发生ID、事件类型、来源与整数幅值，并完成来源／门槛筛选、计数／分频及分合去重。带明确单位的观测、窗口统计、响应入口和成功信号口仍需本提案的新协议与元件定义；不能把基础去重已实现等同于完整高级频次策略已开放。

真实电路在某些同时置位／复位条件下可能有不确定输出，本项目不据此引入随机漏算。依赖明确的写入按因果顺序处理；无先后定义又相互矛盾的同一步置1／置0，以清除优先、抑制该步置1后的请求转发，并在构筑检查中指出冲突。它是结算规则，不是第二时间轴。

本轮优先完成“有含义的幅值、可验证的窗口频次、最小状态记忆、实际执行回执”四个接口。具体元件数量由构筑需求决定；不会照着芯片清单把电阻、电容、时钟、锁存、优先器全部变成必装格子。
