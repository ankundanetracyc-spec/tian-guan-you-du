## 构筑规格

- 保留4×4初阶草图和旧存档；增加可选5×5扩展草图。两种规格均不设复杂度上限；新规格为本次编辑与试演配置，不顺带制定境界、配方、材料消耗或造诣门槛。
- 盘心不再固定保留或承担统合作用。扩缩盘尽量保留现有部件和线路；部件越界、互相重叠或与线路冲突时原子拒绝，不静默丢失草图。
- 仍为单层：信号不免费分叉、供能只允许同源合法T，不允许穿件、叠线或十字跨线。没有因空间紧张加入隐形桥或第二层。
- 格线常显、盘内没有名称／状态签；Q为“信号线”、E为“供能线”，R转向、右键取下／擦除、Esc回移动及输入隔离沿用最新操作页。

## 部件与占格

旧件保持原定义，新件按现有同族图像落地，不拉伸图片冒充不同格形。

| 部件 | 占格 | 接口与用途 |
| --- | --- | --- |
| 阵源 | 2×1 | 提供阵能 |
| 术法感应 | 1×1 | 固定感应成功施法；事件及其强度由实际战斗事实提供 |
| 状态感应 | 1×1 | 气血、护盾、法力、阵能是四种明确部件；放入哪种就读取哪种真实状态 |
| 比较器 | 2×1 | 数值输入、开关输出；≥、≤或上下阈值区间保持 |
| 取反 | 1×1 | 开／关反转，未知仍未知 |
| 开关 | 1×1 | 事件与开关许可分口；可选“开时放行／关时放行”，未知均不放行 |
| 护持 | 1×2 | 事件触发的瞬发护盾，保留旧用途 |
| 护罩 | 1×2 | 开关控制的持续护罩，按段真实付款 |
| 火击 | 1×2 | 合格事件触发实际攻击，仍需阵能和承载 |
| 筛选器／计数器 | 1×1／2×1 | 筛选原事件、计次放行；计数两模式保持 |
| 分流器／合流器 | 1×1 | 分流显式复制同类型信息；合流首版只汇事件并去重 |

与／或可在纯模型保留必要接口，本轮没有相应正式图标时不投放进部件栏。基础、逻辑及守攻图像均复用已选B·墨绘铜纹；新护罩沿用同族护持外形，名称和接口类型区分功能。

状态感应器白名单及单位：气血为百分比，护盾为护盾数值，法力为法力，阵能为阵能。部件类别固定对应读数单位，避免玩家在部件检查页二次配置。比较器和数值分流必须选择同一单位；不能因都画朱砂而把事件、开关、数值混接。分流器显式设置传递类型，合流器不冒充与／或。

## 真正由草图运行

实际端口的物理连通编译为具名、有类型的控制图，所有节点ID来自当前部件ID。端口缺失、类型或单位错接、多源混接和组合回路必须拒绝；不得回退成固定守攻图继续表演。

右侧调试页使用隔离人物与明确试演配置，运行当前草图编译结果，实际扣试演阵能、建立本器护罩、吸收伤害和扣试验敌方生命。调试按钮产生具体的战斗事实（普通术法、强术、受击、治疗、状态变化、回合推进），不允许编辑事件名、来源标签或信号幅值。普通术法／强术是两种固定试演动作，用来覆盖强弱筛选路径；真实运行应由战斗中术法的结算结果生成对应信号强度。界面展示信号如何传导；这些字段仅供内部事件去重和结算，不作为布阵参数。草图实质改变后重建试演并说明，保存或仅切视图不洗账本。

首批真实试演使用物理图核定的一阵源，源余量与峰值由所有输出共享；多源或不支持的供能结构明确拒绝，不把多个源偷偷相加。每个护罩按节点单独记来源、段额与余量，关闭或重建只撤本实例来源，不动普通盾或其他器物。

持续护罩与火击沿已实现试演参数：源容量／初始12、每共同回合补3、源／线／盘峰值6；护罩每段2阵能、容量18、负荷2；火击3阵能、伤害9、负荷3、每共同回合限一次。旧护持瞬发试验明确为2阵能→2护盾、负荷2。全部为试演配置，未覆盖正式成器数值或旧资源文件。

事件输入不让玩家伪造：新编辑器的术法感应固定接收战斗系统确认成功的`spell_played`事实，重复通知仍靠发生ID去重。感应部件类型通过图谱习得；将来的受击、入阵、环境灵气等输入也应是明确习得的感应部件，而不是把内部事件名开放为文本或下拉项。强弱若参与逻辑，必须由真实术法属性推导，不能由调试面板手填。状态感应直接采样人物／阵源当前值；未知不当0，不补发以前被拦的施法。

此改动遵循修仙阵法叙事里的“布置阵器／阵位、注入灵力、以阵诀操控”分工：如《凡人修仙传》第二百三十一章描述依位置布置阵旗与阵盘、以灵石供能，法阵随即运行，阵主再用操纵手法变化阵势；第二百二十一章把阵旗、阵盘作为可携带布置的阵法器物。《诛仙》第二十二集第六章则把操催阵法与理解阵法图形／设置联系起来。由此推到本项目：玩家编辑的是阵图的响应逻辑，输入来源应由游戏里的真实对象与行为决定。小说只是设计灵感，不视作统一的史实规则。

## 可编辑示例与验证

提供真5×5守攻草图：气血感应、区间比较、明确分流、持续护罩、独立取反、事件开关、施法感应、火击及阵源，按实际占格和单层路线验算。共9个部件、13格部件足迹、7格信号线、3格供能线及2格空位。编译为8个控制节点和7条具名连接，护罩与火击共用一阵源；没有交叉、外置输出或隐藏中枢。

本例生命小于或等于30%开启护罩，大于或等于60%撤罩并允许新术法事件触发火击，中间保留原模式。用户可直接修改比较阈值、移动部件、改线及保存；改图后运行新图，不以固定生命分支代替实际线路。

必须验证：改节点ID不影响正确运行；改比较阈值后同一生命值行为改变；断开关键控制或供能不能继续用旧图；多输出按节点记额度但共用能量与峰值；旧4格草图可读取，5格及新参数严格往返。原生界面在1920和1280两档检查新增部件、规格切换、参数修改、实际试演及原Q／E操作。

本轮证据独立保存在[五格复杂阵盘自由构筑图集](../../../美术规范/五格复杂阵盘自由构筑_20261109/README.md)，不复用旧固定8×8试排或先前UI计数作为本次结论。

## 分类、传导与玩家提示（用户最新追加）

部件册分为四个页签，切换只改变浏览，不修改图、计数或试演账本：

| 分类 | 内容 |
| --- | --- |
| 输入 | 术法感应、状态输入 |
| 逻辑 | 比较器、取反、开关、筛选器、计数器、分流器、合流器 |
| 输出 | 护持、护罩、火击 |
| 阵源 | 可放置阵源 |

部件足迹与图标保持；逻辑件较多时只在逻辑分类内滚动。阵盘格位不再预留阵眼，复杂度不作为摆放或运行门槛。

每次实际试演后，沿当前真实连接播放朱砂信号与赭金供能。线路方向、转角、具名端口、图片槽口及同源T分支均来自实际图；不穿件、不越空位、不补画虚线或把所有线路一起闪烁。信号在上游到达后依次进入下游；数值0仍有传导，已知“关”用较暗空心脉点传递，未知无脉点，事件被拦就停在对应元件。供能只在该输出本次实际付款增加时从阵源抵达该输出；缺能、承载失败、重复通知或只有请求不显示假供能。

传导时长仅供观看，不推迟、重算或重复真实结算，不增加游戏时间轴。“回放传导”重看最近的计划，不再次触发或扣能。改图、重开或失败后清除不再适用的播放。显式载入示例／重新试演均作为重开动作，即使载入同一个示例也新建隔离实例；保存、分类浏览与同图读取不清账本。旧信号页只显示实际通过的事件线路，不展示没有发生的供能。

玩家报错采用“护罩未接信号线（4,1）”一类短句；定位在实际断口或端口所在格。坐标为**一基（列,行）**：左上角(1,1)，向右数列，向下数行。盘边标1—N，盘下常显同一说明；没有具体位置的“缺少阵源”等整体问题不编造坐标。内部节点ID、参数名、英文异常尾巴与完整排查链不显示给玩家。

原五格基线两档106项／12图属于本节追加之前；分类、实际付款与事件阻断的传导、多帧变化及回放不结算，另在图集“分类与传导”下验收。
