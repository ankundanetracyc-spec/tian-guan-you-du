# 阵法感应输入成熟方案

2026-11-10。**本稿是输入规则规划，供验收；不代表下述正式战斗接入已经完成。**本稿优先统一“感应什么、何时感应、传出什么”，再决定界面和部件图标。

## 一、先定原则

阵法输入不是玩家编写的一条消息，而是阵盘上已习得的感应部件，对战斗中真实发生的行为或人物状态作出反应。

- **图谱决定能装什么感应件。**未习得的感应件不出现在玩家的部件列表中。
- **感应件固定定义对象、作用范围、触发时点、输出类型和单位。**玩家不输入事件名、来源字符串或信号幅值。
- **逻辑元件决定阵法如何响应。**比较阈值、计数间隔、开关条件仍由玩家设定；这些是阵图规则，不是伪造输入。
- **所有输入归属于当前阵图主人。**首期只感应本人和本人阵源，不把“附近敌人”“进入阵区”当作已支持能力。场地阵旗或阵域玩法确定后，才增加空间感应。

小说灵感仅用于方向，不视为统一设定。《凡人修仙传》中，使用者按玉简所载位置布置阵旗、阵盘并放入灵石后，法阵即可运行；阵主再以主阵旗操控阵势，体现器件职责和操控方法由阵法传承预先定义。[第二百三十一章](https://www.yunshuzhai.com/book/5104/231.html)把这种“照图布置、供能、依既定法门运转”写得很具体。《诛仙》中修复八凶玄火阵需要了解阵图细节，也体现阵法知识决定如何运转，而不是任意填写底层触发字段。[第二十二集第六章](https://www.bidutuijian.com/books/zhuxian/221.html)

## 二、输入信号分三类

不再用一个“幅值”字段同时表示次数、威力、伤害和状态。

| 输入类别 | 代表什么 | 例子 | 传出的内容 |
| --- | --- | --- | --- |
| **事实感应** | 一件事刚刚发生 | 术法已起、回合开始、本人受损 | 一次事件脉冲 |
| **状态感应** | 当前状态是多少 | 气血、护盾、法力、阵源余量 | 有单位的数值读数 |
| **条件结果** | 状态是否满足阵图条件 | 气血≤30%、阵能不足 | 开／关状态，由比较器产生 |

事件脉冲携带的发生编号只用于系统内部去重；玩家看不到或编辑编号。数值信号必须带明确单位，例如百分比、点护盾、点法力、点阵能。缺少数据时输出“未知”，不伪装成0，也不把“没有新事件”当成“关”。

## 三、首期感应件

### A. 战斗事实

| 玩家看到的感应件 | 触发定义 | 首期用途 |
| --- | --- | --- |
| **术法感应** | 本人支付本次术法费用并进入招式执行时，触发一次。即使招式后来未命中，也表示术法已经起用，不表示造成了伤害。 | 计次、开关、触发护持或攻击阵器。 |
| **回合感应** | 本人回合开始时触发一次。 | 回合准备、每回合一次的阵法流程。 |

“出牌”不作为玩家可选感应件。它涵盖了太多不同含义；无消耗动作、消耗法力的术法和其他牌类行为，应该由各自有意义的感应件表达。旧存档中的内部事件可以暂时兼容，但新部件列表不再展示通用“出牌输入”。

### B. 人物与阵源状态

| 玩家看到的感应件 | 输出值 | 采样时机 |
| --- | --- | --- |
| **气血感应** | 当前气血百分比 `当前气血／最大气血` | 阵图启动时取一次基准；气血实际变化后更新；本人回合开始时校准。 |
| **护盾感应** | 当前公共护盾点数 | 护盾实际增加或吸收后更新；阵图启动和回合开始时校准。 |
| **法力感应** | 当前法力点数 | 支付、回复或上限变化后更新；阵图启动和回合开始时校准。 |
| **阵能感应** | 本阵共享阵源余量 | 阵能实际补入或扣除后更新；阵图启动和回合开始时校准。 |

这些是四种不同的部件种类，拖入哪一种就固定读取哪一种；部件信息页只说明读取对象与单位，不提供“改读哪个状态”的下拉框。状态感应输出的是当前值，不因每帧刷新而不停发脉冲。值变化后才重新求值比较器。

### C. 后续扩展，不混入首期

- **受损感应**：在防御、护盾吸收和减伤结算后，若本人气血确实下降，触发一次；可附带实际气血损失值。它不同于“受到攻击”：攻击被护盾完全挡下时不算受损。
- **护盾受击感应**：护盾实际吸收伤害时触发；与受损感应分开，避免“盾挡住了”却触发低血反击。
- **术法耗灵感应**：若玩法确实需要筛选强弱，再输出本次实际结算的消耗或明确的术法品阶。不能拿通用1—9幅值代替；费用可能受伤势、功法转换等影响，必须读取实际结算结果。
- **治疗感应、击中感应、敌人入阵、环境灵气感应**：分别等治疗结算、命中结算或空间阵域规则具备正式事件入口后再开放。没有场地阵域时不开放“敌人进入阵法”。

## 四、触发时序与防重复

每次处理按固定顺序发生：

1. 战斗系统完成该次费用、伤害、护盾或状态变化的权威结算。
2. 产生一个不可改写的战斗事实编号；同一动作被多个感应件观察时共享编号。
3. 事实感应输出事件脉冲；状态感应读取结算后的状态值。
4. 阵图按一次确定的快照求值。计数器只数新的事件编号，分支不能重复计数。
5. 阵器核实阵能、负荷、每回合次数和目标后执行。阵器自己的效果不会在同一求值中循环触发原阵图；若以后要做“成功回执”，需单独定义新的回执感应件。

比较器输出稳定的开／关状态。比较器从关变开时，瞬发阵器可触发一次；持续护罩则在开时维持、关时撤除自身剩余护盾。状态保持为开时，不因无关事件重复加盾。阈值区间可采用回差，例如气血≤30%开启、≥60%关闭，避免在临界值附近反复开关。

## 五、玩家实际能配置什么

| 玩家可以做 | 玩家不能手填 |
| --- | --- |
| 从已习得图谱中拖入感应件 | 内部事件名，如 `spell_played` |
| 连接事件线、数值线、供能线 | 来源标签，如 `spell`、`card` |
| 设置比较阈值、计数次数、开关放行条件 | 通用信号幅值、虚构事件或任意信号频率 |
| 选择具有实际含义的目标或作用范围（该能力解锁后） | 把敌方事件伪装成本人的事件 |

如果未来确实要筛选术法强弱，应把“强弱”落实到已定义的游戏属性上，例如实际消耗或有规则的术法品阶，再用带单位的比较器处理；在该属性和结算时点确定前，不开放“最小幅值”给玩家。

## 六、由易到难的解锁

- **入门图谱**：术法感应、回合感应；学会“发生一次，就让阵器响应一次”。
- **状态观照图谱**：逐项习得气血、护盾、法力、阵源感应；学会读取真实状态。
- **条件操阵图谱**：比较器、开关与持续护罩；将状态转为稳定许可。
- **应变图谱**：受损、护盾受击、治疗或命中感应；每一种必须对应正式结算事件。
- **阵域图谱**：只有以后出现旗位、阵域或战场位置机制，才解锁入阵、离阵、踏入节点等空间输入。

图谱解锁的是感应件及其固定语义，不是输入字段编辑权限。材料可以影响感应件耐久、感应范围或抗干扰能力，但不改变“它到底感应什么”；具体加成另由硬件规则决定。

## 七、适合本项目的两个验证阵图

**低血护罩**：气血感应 → 区间比较（≤30%开、≥60%关）→ 持续护罩。状态只在真实气血变化后更新；护罩开关受阵能和负荷约束。

**三次施法后火击**：术法感应 → 计数器（每3次放行）→ 火击。只统计进入执行阶段的新术法事实；不需要伪造幅值，也不把“出牌”混成施法。

## 八、对照现有实现的工作边界

当前旧手牌结算中，`BattleManager.SkillQueue.TryPlaySkill` 在费用支付后、招式效果执行前发出 `card_played` 与 `spell_played`；因此现有 `spell_played` 表示“已支付并起用术法”，不表示命中。该方法在实时招式队列分支会提前返回，而项目里目前没有另一处对应的施法事件发送，所以实时模式的正式施法事件覆盖也不完整。`FormationCircuitRuntime`另有本人回合开始输入。正式阵图仍把事件名、来源标签和最小幅值保存在元件数据里。

近轮编辑器中的气血、护盾、法力、阵能感应和比较器主要属于隔离试演控制图；正式战斗阵图运行时尚未接入这些状态变化回调。所以下一步不应继续增加输入列表，而应先统一正式事件时点、事件载荷、主人归属和状态更新入口，再把玩家可见感应件绑定到这些固定定义。

建议实施顺序：

1. 定义正式的战斗事实类型与稳定发生编号；明确术法起用、受损、护盾吸收、治疗的结算时点。
2. 先把术法感应与回合感应改为固定定义；移除玩家侧事件名、来源标签配置。
3. 将气血、护盾、法力、阵能采样接入正式运行时，并定义初始读数、变更刷新和未知值语义。
4. 以低血护罩和三次施法火击作为两张真实可运行阵图；用统一事件管线驱动调试页，不再提供手填输入。
5. 最后再决定受损/强度/空间感应是否有足够玩法价值，并按图谱逐项解锁。
