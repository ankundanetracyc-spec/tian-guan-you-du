## 一、已实现的元件

| 简单名称 | 实际功能 |
| --- | --- |
| 状态输入 | 读取明确提供的数值或开关状态；数值带单位，未知不当0 |
| 比较器 | 支持≥、≤和区间保持；区间≤L转守、≥U转攻、中间保留历史 |
| 取反／与／或 | 按真、假、未知求值，未知取反仍未知 |
| 分流 | 显式把同类型信息分送两个端口，不增加能量或事件次数 |
| 开关 | 一次事件与状态许可相配，只有明确许可才转发；不补发过去被挡的事件 |
| 护罩 | 按真实防护段付款、提供本器防护、锁定维持负荷，停用只撤本器剩余部分 |
| 火击 | 收到本次放行事件后核费、限次、承载及目标，实际扣敌方公共盾和生命 |
| 计数器 | 原计数与分频合成一件，选择“数满再发／先发一次” |

控制图使用具名端口校验：一个状态／数值输入不能由多源硬接，一个出口不能免费分叉，错误类型或单位、缺口及组合回路在运行前拒绝。数值、开关、事件保持不同类型；同色朱砂不能互相冒充。

现有旧筛选器实体和旧脉冲草图继续可用；新开关的数值／状态接口先在独立控制图实现，不给旧1×1图标偷偷增加物理端口。原基础盘仍为4×4、复杂度上限4、单层禁跨线。

## 二、守攻图是真正的运行定义

```text
生命输入 → 区间比较 → 分流 → 护罩许可
                           └→ 取反 → 开关许可
本人施法完成 ─────────────────────→ 开关事件 → 火击
```

节点、具名端口与连线由`FormationControlCircuit`实际校验和求值。原生阵盘及流程图读取同一份运行定义和当次结果，界面不另写一份生命if分支。

如额外设置攻击后保留阵能，控制图增加阵能输入、同单位预算比较和与门；真正提交仍原子核实保底，不能只凭旧读数消费。

首次有效生命位于L与U之间时，本例默认守备。后续生命回到中间不改变区间模式；观测未知保留内部历史，向外给未知，恢复后继续原历史。重启同一运行实例不重新初始化模式。

## 三、持续护罩与资源事务

- 护罩许可不等于已运行。实际开启须通过阵源余量、源／灵络／盘体承载及人物资格。
- 成功才保留费用与本段额度；缺能、承载不足和未生效均不扣该次费用。
- 同段只取得一次容量。运行中重复许可不叠加，关闭再开或正常耗尽后重开都不刷新。
- 新共同回合使旧段到期；有效源按本次参数真实补给一次，再尝试建立新段。新旧容量替换，不叠加；续费失败，旧段也不能免费延续。
- 等量续段也是真实服务成功：即使公共盾净增为0，也真实付款并登记新防护段，不将净增0当失败退款。
- 护罩正常耗尽自动停止实际防护，释放后续维持负荷；本段额度仍已使用。
- 关闭、本人死亡或供能实际失效，撤去本器剩余护罩。普通护盾与其他阵器来源保留，已花阵能不退。
- 观测未知时不攻击；仍在运行的护罩按原许可继续真实续费。未知时已停止者不新建，等有效许可与新的合法机会。

同一操作的峰值保留完整账本：已有维持负荷与新瞬发请求共同核验；同一波新开护罩的启动峰值不因转支路或停止而重开。攻击失败撤销预留和本次成功名额，合法提交后不因后续通知失败返费。

“阵法启用”停止控制输出，不等同于“供能来源失效”。本试验中，只要来源仍有效，它可按真实回合继续补给；来源实际失效期间不自动回复，恢复也不追补错过的轮次。启停、重复通知及改事件ID不能重新领取初始阵能。

每个运行实例有独立的稳定护罩来源标识，不能撤掉其他实例的防护。重新试运行会新建隔离人物和新实例；它是试验工具，正式局内启停只调用同一个实例的启用开关。

## 四、公共护盾的来源桥接

`Creature.shield`仍为同一公共数值，不增加第二条玩家护盾、不引入层数状态。新的`FormationShieldLedger`记录来源，按取得顺序吸收：

- 旧`shield += n`登记普通来源；`shield -= n`按FIFO吸收；`shield = 0`统一清理。
- 本器容量使用命名来源，替换或撤除只影响该来源。
- 普通来源使用保留域，器件不能冒充或定点撤普通来源。
- 计数溢出、负增量等拒绝在提交前，保留原账本。

一次控制操作把来源通知延迟到费用、容量、额度和模式全部提交后发布；等量替换也发布一次最终通知。单个显示监听器异常被记录，不中止其余监听或导致“退款但留下护罩”。同步回调不能重入另一次阵法操作，避免重置峰值或同段重复付款。

普通旧技能的单次shield赋值仍走原反馈入口。控制器的结果消息与总量通知分离，不能用公共盾净变化替代本器服务是否提交。

## 五、实际试运行入口

百工“阵法”设计台标题旁新增“守攻试运行”，打开独立原生页面并可返回。也可用[守攻独立启动器](../../../../tools/run_formation_guard_trial.cmd)。

页面的两个人物为未入场景树的隔离`Character`，有真实`HumanData`。守攻运行器经`FormationGuardActor`读取本人生命／法力和公共盾；火击沿现有魔法防御计算，先消耗敌方公共盾，再扣真实生命。

按钮提供试验事实：设置生命、受击、治疗、普通补盾、增加阵能、已完成一次施法、新共同回合及同次重发。受击先真实扣盾和生命，之后才处理控制；“完成施法”只是提供已成立的上游事实，不伪造一张新卡或另定其法力费。

默认L=30%、U=60%及费用、容量、回复、伤害等均明确标为试验值，可在试验参数页调整并重新开一轮。运行核心没有正式数值默认值，调用者必须给完整配置。参数重开重新建立隔离人物，不改正在使用的正式图谱、人物、库存或存档。

画面同时显示控制许可、实际运行、本器余量、普通合计盾、源余量、敌方生命、真实付款与攻击统计。重复通知不重复改变世界，控制被拦时不会因之后恢复许可补打一记旧火击。

## 六、计数合并与兼容

现用界面只投放“计数器”，同占格、同复杂度，增加首发设置：

| 设置 | N=3时的实际放行 |
| --- | --- |
| 数满再发 | 3、6、9…… |
| 先发一次 | 1、4、7…… |

`FirstImmediate`表达起步设置。旧Rhythm／Divider只保留数据编号与读取兼容，加载／编译统一成Counter＋先发一次；旧ID、N、原点和转向保持。新草图统一写Counter，并保存可选`first_immediate`布尔设置。

旧无参V1草图仍按默认N=2；已有显式N不丢失，不根据名称猜参数。旧DIVIDER资源编号3保持，现有计数护持资源继续原本每三次触发，不借合并重做效果与平衡。累计统计、延迟、储能不是本轮额外开放项目。
