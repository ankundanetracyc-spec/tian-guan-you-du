## 一、先定玩家要做什么

基础护持仍可直接接线。复杂版本表达一种**玩家主动选择的保守策略**：

> 遭袭后，没盾先补盾；有盾且有余力时，才尝试反击。遇到重击，或本回合／上回合受袭密集，就暂缓反击。补盾失败则记住需求，后来有条件再补，旧反击不补发。

这里的“有盾”读本人公共护盾；“反击”暂指相应攻击图谱许可的合法攻击，不保证打回原攻击者。定向攻击原攻击者还需要对应的来源身份和目标授权。

| 真实需求 | 所需能力 | 没有这个需求时 |
| --- | --- | --- |
| 不对有盾的人反复补盾 | 判断当前护盾，并分路 | 可直接触发护持 |
| 先补盾，实际补成才考虑攻击 | 护持成功回执 | 只有一个输出时不需要回执链 |
| 缺能时记住曾经没补成 | 一位待补防记忆P | 选择“每次机会无盾便补”的策略可去掉P |
| 识别受袭密集，并影响下一回合的支出 | 本窗计数及上一窗报告 | 不作这种策略时不装观频 |
| 攻击不能吃掉下一次补防的预算 | 当前余额判定及执行时最低余额约束 | 原费用与峰值检查仍必需 |

**不会为了使用计数器才给护盾增加等待条件。** 候枢每N次放行、观频记录N次、锁控记一件未完成的事，解决的是三个不同问题。

## 二、信号到底包含什么

朱砂线仍只传信息，赭金线仍只供阵能。信号不存成资源，不支付费用；数值更大的受击信号也不自动获得更大的输出。

| 字段类别 | 固定含义 |
| --- | --- |
| 原始事实身份 | 原始事件ID、主体、已授权来源；用于同源预算与去重，逻辑件不可改写 |
| 消息身份与类别 | 每份实际观测／请求／执行结果有稳定消息ID；执行回执不是一份新的受击观测 |
| 响应入口 | 本次受袭、合法机会重试、仅撤销需求；回执继承执行请求的入口，不能把恢复改成受袭 |
| 幅值 | 数值、单位和含义；只存在图谱许可的观测值，没有数值权限的发生型输入不凭空补数 |
| 时点 | 既有共同回合ID及动作／消息顺序，不另设阵刻或现实秒数 |
| 统计快照 | 本次受击计入后，本窗次数、当前前缀可信性、上一实际结束窗报告；本响应链内不可变 |
| 请求约束与实际结果 | 最低剩余阵能等属于请求；实际加盾量属于结果，不覆盖原始受击幅值 |

本例只对**一次敌方原始直接伤害动作完成后，本人仍可战斗且实际受损**产生受袭观测。多段属于同一动作则只记一次。幅值候选为该动作各段实际护盾损失与生命损失之和，取真实伤害记录，不用动作前后净差；中间治疗不抹除已经发生的损失。“生命”不等于公共气血费用。

重击是该幅值与图谱门槛比较后的结果。不同单位不能比较；分流、合流、成功回执均不能改大原始幅值。原型中的“轻击／重击”只指定比较结果，不填正式伤害值或门槛。

静态观测与当前状态要分清：本次受击大小和计数取该次快照；护盾与余额在对应判断节点读取当前值；攻击真正提交时再次核验预算。不能拿补盾前的余额或盾值冒充补盾后的情况。

去重键分开约定：观频按`原始动作事实ID＋主体＋该事实所属窗口`一次；成功结果按`实际请求ID＋阵器实例`一次；封窗按`观频实例＋被关闭窗口ID`一次，窗口只能向前。原始所属窗口不可改成通知抵达时的窗口；重发通知换了消息ID也不变成新受击，成功回执类别不能进入受击计数。异常的迟到／错窗观测不能追写成新窗输入；无法核实连续性时标记观测不可信。

## 三、元件职责与端口

### 1. 复用现有元件

| 元件 | 输入／输出 | 职责与边界 |
| --- | --- | --- |
| 感应枢 | 事件→信号 | 接图谱授予的事件，不是通用全知传感器 |
| 鉴脉门 | 一入一出 | 对已有来源、标签、同单位幅值作筛选；不通过就结束，不查询任意外部状态 |
| 候枢 | 一入一出 | 每N次放行一次，到N重新计数；失败不存着等补发，不增效、不减单次费用 |
| 节律枢 | 一入一出 | 按既有定义限制已有信号的放行；不自行造信号，也不兼作观频 |
| 分脉枢 | 一入两出 | 分给不同职责，保留原始身份和观测值；更多分路须另摆元件 |
| 合脉枢 | 两入一出 | 按规定身份去重汇入；不求和、不放大、不执行AND，更多合流须另摆元件 |

### 2. 新候选：鉴态枢

**一请求入口，成立／不成立两个出口；每件配置一个已授权的原子判定。** 例如当前护盾是否大于0、当前窗次数是否达到N、当前观测前缀是否可信、上一窗报告是否可信、上一窗次数是否达到N、当前余额是否满足指定预算。

同一请求只有一个分支继续。类型不符、未授权、接口失效或无法判定时停止并给出原因，不能冒充“不成立”而误走攻击支路。观察不完整是统计数据中的显式“未知”，也不得当作低压放行。

复杂策略由多个明确的判定串接／分路，不把“安全、可攻、所有费用通过”藏成万能条件。若只需要筛掉不合格信号，鉴脉门即可；鉴态的一个通过分支与其部分重叠，不要求同一条件连装两件。

### 3. 新候选：观频枢

**一个消息入口、一个受击信号出口。** 入口可经合脉接入：

- 图谱授权的原始合格受击观测；
- 图谱授权的真实共同回合边界通知。

受击消息去重后计数一次、附统计快照并转发，第一击也照常出去。边界只封存并更新内部统计，**不从受击出口转发**，不触发补防或反击。没有新消息便没有输出；不提供免费隐藏时钟。未接所需边界入口，完整窗口统计配置不能通过校验。

观频存本窗计数、去重集合、当前观测前缀可信标记，以及上一实际结束窗的报告。计数到N不清零；不储存受击请求，也不兼任任意记忆、伤害求和或能量生成。

### 4. 新候选：锁控枢

每件保存一位状态，本例为`P：有待补防需求`。

| 输入口 | 写入／读取 | 输出 |
| --- | --- | --- |
| 置1 | 先设P=1；原来就是1也按本次新请求处理 | 从1出口转发当前消息 |
| 置0 | 只设P=0 | 不转发，状态写入结束 |
| 查询 | 读当前P | 从对应的0／1出口转发当前消息 |

本例查询0出口不接动作。P不记欠几次盾、不记旧攻击者或已支付效果；多次补防失败仍只有一个需求。没有输入不自动重试。明确有先后的写入按因果顺序；同一步确有无序的矛盾写入则清除优先，且抑制该步置1后的转发，并提示构筑冲突。

### 5. 新候选：阵器实际成功出口

这是**高级阵器的物理信号出口**，不是必装一件“回执枢”。本例护持在正数护盾增量真正提交后，才发一份稳定成功结果；失败不发成功脉冲，不强制设置失败出口。

回执保留原请求的响应入口、原始事实身份、受击幅值和统计快照，另附实际加盾结果。同一次实际执行不能发多份有效成功回执。原基础护持图只有信号入与供能入，不能借金线偷偷回传，也不能把本功能视为已存在。

### 取得、品质与占格仍按各自来源

输入观测与输出能力仍来自图谱；造诣决定逻辑元件使用资格；材料影响实际硬件和成器，不授予观测权限、不修改真实事件值。普通逻辑同一功能应确定执行，品质不能变成“低品质随机漏算、误判、触发失败”；既有精炼路线优化占格与复杂度。

当前4×4及五件旧逻辑的占格、复杂度保持。上述新件的实体足迹、真实多端口位置、复杂度与解锁档尚未定数，本稿不宣称能塞入基础盘。等功能验收后再画同族铜玉元件并验线。

## 四、密集判断的完整口径

### 为什么保存上一窗

如果攻击本来每回合只允许一次，仅在本窗第三击才拦攻击，常常已经没有可拦的第二次攻击。不能据此证明观频有用。

本例可选策略改为：**本回合已密集，或上一个实际结束回合密集，就保留资源暂不攻击。** 因而下一回合第一次合法攻击也可能被主动放弃；等一个完整低压回合结束，后续新受击再恢复通常判断。这是以反击机会换取保守储能的选择，不提供额外盾量或减费，也不保证最优。

当次重击只停止当次攻击，**不承诺持续到下一回合**。若以后确需“重击后一直守备，直到某个指定事件解除”，才考虑第二件锁控。当前统计即可派生守备判断，不默认再存一位D。

### 三种判定

设密集阈值为`N`，只说明次数，不填正式数值：

1. 本次是重击，或本窗已观察次数≥N，或上一窗已观察次数≥N：确认高压，本次不攻击。
2. 没有已知高压，但本窗从窗初到现在观测不连续，或上一窗报告不完整／缺失：未知，本次不攻击。
3. 本次不是重击、本窗观测前缀可信且次数<N、上一窗完整且次数<N：低压，可以继续检查攻击预算及原资格。

真正开战且从首窗开始监听时，没有前窗的初始报告可作中性。普通停用、重启、转向或换位不能重新取得这个“无历史”状态。部分观测已达到N也足以证明密集；未达到则不能证明低压。

**这些条件只控制可选攻击，补防始终在它们之前处理。** 完整监听时的低压也只表示截至当前，不能预测后面不会再受击。

### 封窗、空窗与观测缺口

收到真实边界先封存旧窗`次数＋是否完整`，替换上一报告，再开始新窗，之后才接收新窗受击。上一报告必须是**上一实际结束窗口**，不能跳过不完整窗去引用更早的完整低窗。

完整空窗的次数就是0，可作为低压报告；不靠再受一次攻击才能解除旧高压。边界只改统计，不清P、不回能、不刷新原费用／冷却／次数。若同一轮初确有资源回复或资格变化，应由其真实结算另发一个合法机会通知。

停用造成的缺口不能补造事件。同窗保留已观察次数并标不可信；错过的已结束窗口记不完整／缺失，不能把旧报告冒充最新报告。下一个确实从窗初连续监听到窗末的完整低窗，才可替换未知报告。重复、迟到边界不能再次封窗或把新窗计数清零。

## 五、完整控制链

```text
原始合格受击 ─→ 观频（先计本次）─→ 置P=1 ───────┐
真实窗口边界 ─→ 观频（只更新统计，至此结束）       │
                                                   ↓
新的合法机会 ───────────────────→ 查询P ─1→ 检查当前盾
                                          0结束    │
                                有盾 ──────────────┤
                                无盾 → 请求护持    │
                                          实际成功回执
                                                   │
                                已有盾／成功 ─动作合流
                                                   ↓
                                                  分流
                          ┌────────────────────────┴─────────┐
                       清P支路                          本次后续支路
                          │                       筛选：受袭入口才继续
外界实际补盾通知 ─→ 状态合流 → 置P=0，结束          强度／本窗／上一窗判断
                                                  当前预算→攻击执行
```

动作合流和清除需求的状态合流是两个职责。护盾观测只清P，不取消正在处理的受袭响应；不能先占掉动作合流的去重记录，吞掉本阵随后发来的护持成功回执。机会重试即使成功也保留“机会”入口，不能补打一记旧反击。

同步响应链完整结束后才接下一个外部动作或停用；否则要额外定义异步生命周期与迟到回执取消，本稿不混用。本人失去战斗资格就停止，本次新增护盾不逆转已经结完的伤害。阵器及反震等派生伤害不重新作为本例的敌方原始受袭输入。

### 执行仍检查什么

`C护`、`C攻`为真实图谱与成器费用，不是本案新数值。攻击请求携带`提交后至少保留C护`约束，预留与真正提交时核验：

```text
实际可用阵能 − C攻 ≥ C护
```

只扣C攻，C护不是另一笔费用。所有同源进攻支路都必须受同一保底策略覆盖；未覆盖应指出，不能宣称已保证储备。

源余量、源峰值、灵络峰值、盘体负荷、合法目标、原费用、冷却与限次照常检查。护持与它的成功后攻击累计占用同一原始事件峰值，串行与回执不重开额度。原硬件若只够护持，结果就只有护持。

请求失败不扣该次阵能、不占成功账本、不留待攻击；效果、费用、账本作为一次实际事务提交，失败撤销预留。合法攻击已提交后被防御／免疫抵消，不据此返费或反复重试。旧运行尚无完整的成功结果、原子约束与协议支持，本轮不直接改它。

## 六、确定性验收表

下表是**场景给定条件**，不是新增战斗数值。`N=3`只用于可点演示；实际N、重击阈值、输出值待相应图谱与平衡确定。每行独立起算，跨窗序列除外。所谓“可攻击”仍以该次原资格、资源与共享峰值全部允许为前提。

| 情境与输入 | 统计／记忆 | 应得行为与费用 |
| --- | --- | --- |
| 首窗轻击后仍有盾，预算与全部资格通过 | 本窗1；P置1后清0 | 不请求护持；提交一次攻击，只付C攻 |
| 首窗轻击后无盾，护持及后续攻击均可真实提交 | 本窗只记1；P归0 | 先护持再攻，付C护＋C攻；回执不再计次 |
| 无盾轻击，但护持缺能 | 本窗1、P=1 | 无成功输出，零费用；不以“攻击较便宜”绕过补防 |
| 上项后来出现真实供能机会 | 本窗仍1；补防成功后P=0 | 只补防，付C护；不补发旧攻击 |
| 重击后无盾，护持可提交 | 本窗只加1，P归0 | 立即护持、付C护；本次不攻，不延迟补盾 |
| 护持成功，余额足但同源本次剩余峰值不足 | P已归0 | 只付C护，不能让回执开新峰值再攻 |
| 首窗轻击依次达到1／2／3次，均有盾 | 达N仍继续累计；P均归0 | 第三次起主动停止攻击；前两次也仅在各自原资格允许时才可提交 |
| 上项换到下一窗，再受第一记轻击且攻击资格确实允许 | 当前1、上一报告3且完整 | 保留护持；本次仍主动不攻，不因换窗洗掉策略 |
| 该低压窗完整结束，再下一窗受轻击 | 上一报告被完整低计数替换 | 可以重新检查攻击预算；封窗本身没有攻击 |
| 上一密集窗后出现完整空窗并结束 | 上一报告更新为0且完整 | 后续新受击可正常判断；空窗结束也不自行攻击 |
| P=1期间外界实际补盾，之后又失盾但无新合格受击 | 补盾时P立即清0；统计不变 | 后来的机会不复活旧补防，不攻击 |
| 刚才受击被重复通知、分流汇回或收到回执 | 该观测只计一次 | 不重复输出、扣费或更新原始幅值 |
| 主动停用再重启同盘 | P取消；次数与报告不洗白，观测记缺口 | 重启不输出；新的无盾受击仍先补防，未知统计只拦攻击 |
| 只有真实边界，没有回复或新受击 | 封报告、开新计数；P保持 | 不付费、不补盾、不攻击、不自行刷新源或阵器账本 |

对于“每个共同回合仅一次攻击”的合法阵器，第七行可能根本没有第二次可执行攻击；本例的实际区别由第八行的下一窗首个合法机会体现。演示可以手动指定执行资格，通过或不通过都不意味着游戏次数被修改。

## 七、演示和后续制作边界

独立演示可选择有盾、无盾、缺能、连续受袭四种情境，逐次点击轻击／重击、供能机会、实际补盾和换窗；显示次数、上一窗、P、实际走过的流程、失败原因及符号费用。调节给定条件只影响下次检查，不自行触发阵法；重置是演示工具，不是游戏内洗状态动作。

本稿功能收敛为：**鉴态分路、观频统计、锁控记需、高级阵器成功口**。未把电阻、电容、独立时钟、优先编码器、专用AND／OR、单独回执件统统做成必装元件。保存上一窗读数的灵感来自[TI计数器与读数寄存器](https://www.ti.com/product/SN74LV8154)，一位需求记忆借鉴[TI S-R锁存器](https://www.ti.com/product/SN74LS279A)；保守资源策略与事件协议是本项目设计推演。

功能获验收后的下一项才是新件物理设计：确定真实端口和足迹，按既有铜纹玉件风格出独立图，逐格检查双线绕行、复杂度、造诣和所需图谱。若装不进4×4，应展示真实空间需求，不缩图塞入、不免费跨线，也不擅自扩张初始盘。

本次验证只覆盖独立演示与策划一致性，未将方案装入战斗、扣真实资源或写入玩家存档；基础盘的既有模型通过记录不能充当新接口已实现的证据。
