# 阵旗感知执行端与可选外置候选

> 历史方向比较：按用户“直接规划成熟，然后我来验收”，本轮已收敛为[阵法系统完整策划提案](阵法系统完整策划提案_20261108.md)。新稿采用主控盘＋实际旗终端，首期不做纯内置战斗输出或任意部件移装；本页多方向仅供追溯，不作为并行默认。新稿尚待整体验收。

> **用户类比带来的新方向**：阵盘像控制柜，阵旗像路灯、传感器。盘负责控制与供能调度，旗作为盘外感知／执行端，将事件和效果对应到具体对象。外置腾空间降为附带收益。本页下文的全内置、移装和承载取舍仍为候选；类比不自动裁定所有阵器位置、旗数、覆盖、必需性或部件格形。

## 一 已确认与本轮新提议分开

已确认：盘与旗都是器物；盘手持、与手持剑互斥，普通手持本身不占御使灵识；旗放入招式盘采用御使，布置后在战场显示，只按阵图工作，不附送类别普攻。阵源给实际输出阵器供能，逻辑线传控制信号，部件可以被攻破。

本轮新提议：基础个人阵法可以全内置运行，阵旗作为可选的外置阵基。只有需要外置实际功能部件时才带旗，用招式盘空间、持续灵识与外露支路的风险，换取盘内装配空间。此前“所有阵法先有旗才可启动”没有获得确认，本候选不把它作为通则。

### 主控与终端的分工方向

- 阵盘保存程序和线路，决定在什么条件、何时调度哪一个合法端点；阵源经供能线路给真实执行阵器供能。
- 感应旗承载图谱允许的感应功能，向盘回报其明确对象的合格事件；执行旗承载相应执行阵器，在其合法对象上产生效果。两种职责可以由同一件获授权旗兼具，不强制一项职责就多占一面旗。
- 感知回报与控制命令均属信号线路，方向按端口定义；供能仍属灵络。不因此增加第三种走线、另一份免费输出或第二条行动时钟。
- 输入也可由盘内感应直接读取本人的既有事件，不为教终端而强制每种输入都外置。盘上输出接口标识实际执行对象，不再复制一份相同效果；接口实际足迹待审。
- 本项目的“点位”先落实为招式盘上明确的绑定对象或图谱允许的覆盖关系，战场自动显示旗。它不生成第二套地面落点、人物距离或前后排规则。不是任意贴邻就获得感知或强化，不能从摆放扩大原护持的角色目标。
- 首个护持例仍可保留盘内感应与三候枢，只用一面执行旗承载实际护持阵器；旗收到命令且供能合格，按原样例给予本人护盾。新感应对象或新执行对象必须由图谱、既有事件支持与独立能力方案授予，不能用类比绕过资格。

首要玩法问题由“多装多少部件”转为“监听哪个合法对象、调度哪个终端、效果落给谁”。下文空间取舍保留为一种装配收益，不单靠强制空旗开阵证明旗有用。

## 二 首期只解决一个明确需求

首期建议阵旗先承载图谱与器物形制明确允许外置的输出阵器；感应、逻辑与阵源留在盘内，不一次开放所有部件外装。

| 对象 | 本轮推荐职责 |
| --- | --- |
| 阵盘 | 保存阵图、感应与逻辑，统合内置和合法外置的部件。 |
| 阵源 | 经灵络给实际输出供能，不因旗数增加而复制容量、回复或峰值。 |
| 输出阵器 | 决定实际效果，安装在盘内或一面兼容旗上，同一件只在一处。 |
| 阵旗 | 承载并部署实际外置阵器，接受本盘调度；空旗不凭自身产生护盾或攻击。 |

旗的承载类型、可装规模、招式盘格形与持续占用由真实成器和图谱明确，数值待定。旗不再打开一张任意装件的小阵盘，也不默认拥有无限安装位。外置释放的是部件真实盘内足迹，不把内部格、招式盘格、行囊格按面积互换。

## 三 用同一件护持阵器比较

本例只用已掌握的合格输入、三候枢和一件真实护持阵器，前置资格沿主案满足；只沿旧示例三次有效施法、2阵能、额外2护盾，不重定这些值。

### 全内置配置

盘内感应→三候枢→护持阵器，阵源→护持阵器。来源有效且自身条件满足时，个人基础阵可以工作，无须为这条已完整内置的支路额外摆一面空旗。代价包括唯一手持槽、盘内足迹、复杂度与实际阵能。

### 旗载配置

局外把同一件护持阵器从盘内移装到兼容护持旗，盘内留下外接端口与预存连接。感应与三候枢仍在盘内；控制线和供能线分别接到旗上的真实阵器，不在招式盘再画一套线路。

阵器原先占用的盘内空间可用于合法筛选、护阵或其他构件，能否放下按真实格形验算。代价是旗占实际招式盘位置和持续灵识，其他招式或器物可用空间相应减少。旗的扫描展开时点仍待审；只有已合法展开的外置部件才能工作，不补发此前事件，也不因扫到旗额外赠送一次输出。

两种装法的这件阵器仍执行原效果、费用和限制。不能一面保留盘内护持，再用同一件阵器在旗上重复获得一份效果。

## 四 玩家真正选择什么

- 盘里装得下时，可以保留全内置，节省招式盘位置和持续灵识。
- 想在当前盘内加入更多合法部件时，可选择把兼容输出外置，将有限的两处空间重新分配。
- 已有多条合法支路时，可决定哪些功能留盘内，哪些放到可独立受击的旗上；旗被破只停止实际依赖它的外置部分，不自动使完整内置支路停转或传伤。

外置仍计全图复杂度，并接受实际供能、峰值和负荷检查；首期只增加承载位置，不顺带绕过阵眼、造诣或功率限制。精炼节省原部件的空间与复杂度，旗外置则消耗外部构筑资源，两者保留不同取舍。

## 五 安装、受击与本场状态

安装位置、兼容旗、端口与盘内连接在局外确定，本场不把旗载部件临时搬回盘内以躲过损坏或更换线路。整理招式盘只沿已有窗口处理旗的真实摆放，同件实物的阵能、次数、计数归属与损伤不因移动、取下重摆或换方案重置。

只有外置支路依赖其承载旗展开，内置支路不额外等旗。若旗被击破，载件暂失运行资格；不推导载件及盘内各节点同时受到同额伤害，也不推导永久销毁实物。合法攻击资格、保护与余伤仍按受击候选另审。

旗本体只记一份局内承伤，不同时叠加阵体与御使稳定度。所载阵器能否单独成为目标、与旗体的保护或余伤关系另定；不能对两者各扣一次完整来袭。共用逻辑节点的计数沿同一节点，不因旗数复制，也不储存可补发阵脉。

## 六 后续扩展与教学

首期先做输出外置。护阵件、真实阵源的外置，或多旗按图谱形成明确阵形，可以在各自兼容、目标、代价与受击规则完整后另议；本页不直接开放，也不把多插旗变成统一增伤、免费供能、免费复制或额外行动。

教学建议先让玩家理解全内置的输入、逻辑、输出及两套线，再在实际空间不足时展示外置；之后才介绍确有需要的旗组关系。旗的价值由玩家腾出了什么位置、为此付出了什么来体现。

盘形、输出部件足迹、旗承载与主盘足迹都还未定。[5×5旧试排](基础阵盘形制与双路走线占格候选_20261108.md)的8部件格＋8线路格＋9空格只是一种输出外置示例，不能当成全内置同样摆得下；须在安装关系选定后分别验算，再生成对应尺寸图标。
