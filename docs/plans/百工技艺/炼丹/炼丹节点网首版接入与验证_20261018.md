# 炼丹节点网首版接入与验证（2026-10-18）

状态：首版测试流程已可运行；构建通过，38项模型检查与7项场景交互／教学演示检查通过。不是完整节点网系统验收，不代表数值已平衡。正式角色、行囊、历法与存档事务未接入。

规则入口：[逻辑主案](炼丹系统逻辑主案_20261017.md)、[节点网方案](炼丹节点网生产线与闭环丹胚方案_20261018.md)、[初始数值表](炼丹节点网初始数值表_20261018.md)、[通行引修订](炼丹通行引节点网分工修订_20261018.md)。后者仍有未完成设计，以下按实际实现列明边界，不能把文档覆盖范围当成代码完成范围。

## 一、现可操作内容

- 确认投料只加入待投，支持0.1份；节点基本操作先选择目标，确认后进入本息安排，可撤回。添焰、敛焰、守炉提交整套计划，每次恰好推进一息。
- 整数火候与三种法力支付，10息一时辰；六类加工表现读取材料有效品阶，使用不同窗口、速度、得率、开结构、滞留与逸散。
- 功用按签线与本息安排作用于具体对象，来源投入变为实际残余或结构绑定；不再全炉自动触发所有功用。未投料、尚未可用或无真实目标时不能凭空产出效果。
- 通路付来源建设，下一息开始基础导流；九品完整路线基础4、容量20。行材料可点选其他材料已建通路供力增流，不要求供力材料自身具有通。
- 每条有效线占1灵识；本息投料、功用、基本操作与炉令负担相加。暂停通路会联动暂停依赖的行，撤线将绑定投入转为残余。点线菜单可安排本息施用、暂停、撤线及设置运输累计目标和开闭。
- 药性按实际起点到终点移动，每息最多一段；保留来源、能力、保存与损伤。运输有真实夹渣，不能通过画线自动提纯。
- 汇合位常显，只有实际送到且已满足时间边界的药性可分丹。支持混匀、分离、排渣、塑形、逐颗按三轴最低项评级及现有丹种药效曲线。
- 技巧由测试书架中的书籍研读并检查造诣；研读在开炉前进行，记录一时辰。测试书架不是已接入正式物品库存；副手不继承本人技巧。
- 教学演示已替换为新规则：青髓芽真实投料、适宜火候炼化、敛焰、牵药、混匀／分离／排渣／凝丹，最后出炉。

## 二、验证与结果

使用项目自带Godot 4.7.2 Spine 3.8 Mono运行器，运行炼丹测试场景的`--alchemy-check`入口；该入口失败时返回非零状态。

|验证|结果与范围|
|---|---|
|项目构建|通过，0错误、0警告|
|模型检查|38项通过；覆盖炉令与法力、时间、书籍、独立行来源、通路流量上限、灵识线位、暂停联动、夹渣、禁止同息串联、禁止远端自动分丹、来源守恒、超载炸炉，以及各功用有真实目标时的投入划账|
|场景检查|7项通过；包括拖入丹炉、确认只安排不推进、添焰按钮提交、结束后禁投、重开清理、真实材料教学演示|
|真实材料演示|初始造诣36、法力600；投入0.5份青髓芽，计划1颗；27息后成丹1颗，85分，法力剩496；此为单个基线样例，不是全部丹方平衡证明|

模型检查中的部分工序使用明确构造的炉况，目的在于核对工序及来源账；它们不能替代真实材料组合试玩。十二功用的投入检查不能单独证明各自全部语义、界面和极端情况已覆盖。

运行过程中材料资源加载触发一项既有UID失效警告，运行器按资源文本路径回退；此次未改该资源。另修正修炼界面一处SpinBox重复绑定不存在的ItemSelected事件，保留原ValueChanged绑定，使项目可正常构建。
