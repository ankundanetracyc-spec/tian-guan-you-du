# 行囊容量与物品体积

> **状态：当前主案｜2026-11-10**。物品在行囊与储物袋中按容量单位计量；容量不再按实物外形格数结算。物品图标仍按现有配置的真实显示格形、摆放与旋转样式呈现，图标几何仅用于展示布局。本文覆盖旧行囊方案中把图标占地用于容量准入的规则，以及丹药以单瓶实体占格、每瓶最多50颗的空间规则。普通行囊仍为200容量单位，五区视觉布局保持；战斗中的“战斗占格”与招式战斗格规则独立保留。

> **同日界面验收补充**：正式行囊与储物袋使用全屏暖色物品卡，左侧切换容器，顶部分类，卡片下方显示名称与数量。下文的五区、格形、摆放与旋转仅用于理解旧布局数据和兼容记录。丢弃选中的行囊物品立即生效。奖励整批能放入随身行囊时，直接入包并显示「获得物品」小窗；容量不足时打开同一个全屏行囊，在右侧透明浮窗列出待领取物品。悬停浮窗可滚动，点击对应物品时才尝试入包。关闭行囊即结束本次领取并放弃剩余奖励；坊市未支取的已结算所得仍记在账上。

## 一、物品体积

每个可收纳物品定义显式记录正整数 `storage_volume`，表示一件物品占用的容量单位。运行时读取该字段，不从图标像素、透明边界或图像宽高推导体积。

同一物品定义的堆叠数量记为 `quantity`，该堆叠占用的体积为：

```text
stack_volume = quantity × storage_volume
```

同一定义的物品可以堆叠；不同物品定义或不同丹药效果档不混为同一堆。所有容量校验以当前物品实际数量计算，不把一个堆叠项误算成一件。

| 物品 | 每件体积 |
| --- | ---: |
| 灵石 | 1 |
| 所有丹药 | 1 |
| 其余现有物品 | 按第二节逐项给出的实物形态定值 |

丹药直接按颗数堆叠，每颗占1容量。瓷瓶不代表一只独立库存容器；取消“每瓶最多50颗”、拆成多个瓷瓶及单瓶空间实例规则。丹药原有品种、丹效档、使用效果和数量结算不变。

2026-11-10后续图标裁定：所有丹药统一使用2×2丹丸图 `pill_2x2.png`，不再用瓷瓶图表示丹药。该图标形状只影响行囊与物品栏的显示布局；每颗丹药仍占1容量。空瓷瓶模板与炼丹演出继续保留各自的瓷瓶素材。

## 二、其余物品的实物体积定值

本节数值依据物品实际收纳时的厚薄、紧实程度和单件形态逐项设定。图标宽高、像素边界、显示占格数和原方案面积均不参与估算；图标仅负责行囊中的标准摆放显示。以下清单是当前所有静态物品定义的单件 `storage_volume`。

| 单件体积 | 材料 |
| ---: | --- |
| 1 | 乌羽片、凝霜叶、凝露松脂、回泉珠、山蚕长丝、山蝉蜕壳、斑甲壳片、断角骨片、月露苔、月露菌汁、朱阳花籽、沉云玉屑、清音玉片、灵泉藻、灵泉露、灵石、玄甲薄片、瘴泥珠、石蜂蜡、砂脉石片、紫砂灵土、褐铜砂、赤瓤木核、赤鳞蜕、雾心菌核、雾铃花、青羽翎、青髓芽、风窍晶屑 |
| 2 | 云雾菌、伏地兽筋、兽皮、地脉焰炭、松心炭、泥脉石团、溪纹藻丝、砾地菌伞、苦苔根、荒藤结节、裂甲石、盐纹石膏、赤纹燧石、霜叶枝、青岚藤心、风纹石英、风络藤丝 |
| 3 | 兽骨、玄铁、铜髓矿、青木芯 |

稀薄叶片、碎屑、小珠、线丝和小型药材按1；体积更厚或较蓬松的材料按2；块状金属、骨料和木芯按3。这里的分级只用于统一现有材料的实物收纳量，不读取或反推它们的图标尺寸。

| 物品类别 | 单件体积 | 规则 |
| --- | ---: | --- |
| 所有丹药 | 1 | 65种静态丹药与动态制成丹药均按颗计；不因统一丹丸图为2×2而增加体积 |
| 灵石 | 1 | 固定基准 |
| 折叠衣袍与常服 | 2 | 衣物摊开面积虽大，折叠后厚度较小 |
| 秘籍 | 2 | 单册按收拢后的书册体积计 |
| 储物袋本体 | 2 | 袋体折叠收纳；与袋内容量分开计算 |
| 空瓷瓶模板 | 1 | 单独空瓶物品；丹药不再占瓶或按瓶计量 |
| 布甲 | 3 | 叠放后的护具体积 |
| 含章剑、承露剑 | 4 | 宽展或较厚的剑器 |
| 清和剑、素行剑、铁剑、赤霄剑 | 3 | 修长或较薄的剑器 |

动态制符产物按实物形态设定：符纸、墨、成品符箓各1容量，符笔2容量。动态锻造剑器的成器快照保存整数体积；修长且薄脊剑为3，宽展或厚脊剑为4。现有剑器计算和旧快照读取均依其剑形重定该值，图标形状不参与计算。新增物品必须在进入正式物品清单前明确填写单件体积；之后修改图标不会自动改变该字段。

## 三、行囊容量与展示

普通行囊总容量保持200单位，既有五区、位置和36像素格距保持：胸前40、左袖20、右袖20、腰间40、背囊80。五区及其格子继续用于显示和定位库存条目，容量使用量按整只行囊汇总：

```text
used_volume = Σ(quantity × storage_volume)
```

只有 `used_volume ≤ 200` 时，物品才可进入行囊。每个堆叠项的图标继续按物品原配置使用真实显示格形、标准尺寸、摆放和旋转样式；图标格形用于显示和整理，不表示该堆叠的容量占用。物品是否能入包只看容量，不能因为没有足够的空形状位置而拒绝。图标位置冲突时尽量自动重排显示位置；若现有空位仍不能容纳全部图标，库存与容量事务仍成功，不得把显示布局退化为规则限制。自动整理只改变图标的展示位置，不改变物品定义、数量、单件体积或容量账。

## 四、储物袋容量

储物袋本体仍按现行2×2图标与本体展示规则呈现，收纳内容仍按各袋实例分别保存。每个储物袋内部矩形的宽×高表示该袋的容量单位总数：

```text
storage_bag_capacity = width × height
```

储物袋内物品图标继续使用原配置的真实显示格形、标准尺寸、摆放与旋转样式，图标碰撞只用于整理显示。容量占用独立按 `quantity × storage_volume` 计算；没有空的图标形状位置也不得拒绝转袋。图标冲突时尽量自动重排，无法完全铺开时仍以容量校验结果提交库存，不改变各堆叠数量及体积。袋内已用容量不得超过该袋宽×高的总容量。每袋独立核算容量，储物袋禁止互相装入的既有规则保持；没有正式宽、高配置的袋子继续视为未定义，不从测试夹具推定容量。

## 五、领取、交易与其他容量校验

所有将物品转入行囊或储物袋的操作，唯一按本次转入数量乘每件体积计算增量，并在提交前校验目标容器容量。不得以显示格是否空闲、原始图标格形是否可放下、是否能旋转或空间碰撞结果否决容量已足够的操作。交易、坊市、善功堂兑换、领取、奖励入包和容器间转移共用同一容量口径；移出或消耗物品则按实际移出数量释放容量。通过容量校验后，图标可尽量自动重排；图标布局不完整不撤销库存事务。原子提交、库存真实性、使用限制与操作确认规则保持。

各页仍显示物品名称、图标、数量和原有业务信息，但收纳信息改用体积或容量表达：悬停显示“单件体积”，并在有堆叠数量的上下文显示“当前堆叠容量”；容器显示“已用容量／总容量”。领取、交易与坊市的可用空间判断不得再使用原物品宽高、格数或旋转后的矩形。

## 六、悬停与战斗占格边界

物品悬停及行囊、储物袋、角色装备、交易、坊市、兑换、领取、换装、炼丹成品和战斗丹药栏中的物品详情，收纳相关字段统一显示单件体积；堆叠数量大于1时，紧接着显示堆叠总容量。悬停标题区保留物品图标在左、名称在右的并排排布，不再绘制表示容量的格子示意；属性正文第一项显示“单件体积”，堆叠时第二项显示“当前堆叠容量”，两项均排在品阶等物品属性之前。行囊／储物袋图层中的物品图标继续按原配置的真实显示格形绘制，不再把图标格形、占地尺寸或旋转后的面积作为容量文案或容量数据。

唯一保留的占格概念是战斗规则中的“战斗占格”及招式战斗格图。其战斗坐标、形状、范围、标签与结算保持原规则，不转换为库存体积，也不受本案影响。
