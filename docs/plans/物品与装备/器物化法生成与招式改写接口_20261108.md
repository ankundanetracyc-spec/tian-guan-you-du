# 器物化法生成与招式改写接口

> 2026-11-08，本轮器物化法的接口设计与独立契约原型。**首批只登记格剑化解完整包；普通剑招固定加伤已撤回，不在本轮化法生成或执行列表。**纯Python原型可以注册、校验、绑定和解析事件计划，尚未桥接Godot，不代表正式生成器、招式盘、战斗或存档已经接通。

依据：[战斗剑器字段规范](../战斗与构筑/战斗剑器基础字段规范_20261108.md)、[器物主案](器物系统现行主案_20261023.md)、[化法来源与旧绑定](../战斗与构筑/化法来源汇总与技能绑定_20261024.md)、[单格化法提案](../战斗与构筑/单格指向化法与旧绑定迁移提案_20261106.md)、[人类新盘实施](../战斗与构筑/人类招式盘实施与验收_20261107.md)、[显示规范](../界面与美术/信息展示与规则详解分层规范_20261026.md)。

本页不重做人物原20招与20项卷章化法。人物六项基础战斗属性及剑形硬属性池由器物属性专题规定；化法只使用目标招式明确提供的可改写项，不因器物属性池有或没有某项就扩大化法操作权限。御使普攻的物伤参数仍是器物默认动作性能，不是已撤回的普通人物剑招固定加伤。

## 一、先由招式声明可改写项

器物不能直接任意写入ActiveSkillData字段。全局启用技能库先提供经审核的技能接口，登记准确资源、基础身份、实际关键词、机制、可改写槽及原费用／次数／冷却；模板只能调用被登记的槽。

首批接口为：

| 项目 | 内容 |
| --- | --- |
| 基础技能身份 | `res://resources/activeskills/剑修基础/格剑.tres` |
| 实际关键词 | 剑、应对、化解；原技能另有剑意，不因化法新增 |
| 真实机制 | 接受物理来袭的应对；自身实际产生化解 |
| 可改写槽 | `response_defuse_flat_add` |
| 允许操作 | `add_response_defuse_flat` |
| 参数类型 | `int_flat`，非负整数化解加值 |
| 真实结算阶段 | `response_defuse_calculation`，实际物理应对时计算化解 |

关键词按权威技能字段解析：剑／化解来自已登记tags，应对来自真实keywords；`physical_response`还须核对counter_condition，`defuse`还须核对自身目标和实际化解status_effect。名字或description写了“格剑／化解”不构成适配证明。

兼容变体必须先显式登记其资源与准确基础身份，并仍具有真实机制和此改写槽。运行时副本可以保留基础身份，但不能只凭显示名字、伪填base_key或继承了某个标签就越过检查。

伤害、护盾、费用、冷却、次数、状态事件等分别作为将来可审的操作类别。本轮没有将它们登记为器物通用改写权限，也不因ActiveSkillData已有字段就自动开放。

## 二、模板与整包生成契约

首批模板：`artifact.gejian.defuse_flat.v1`，版本1。

| 模板字段 | 本轮定义 |
| --- | --- |
| 来源政策 | `held_active_only`，只在同一实物手持且已启用时生效 |
| 目标政策 | `one_placed_copy`，只选择盘中一份格剑 |
| 基础目标 | 上述准确格剑资源身份 |
| 必需关键词 | 剑、应对、化解全部满足 |
| 必需机制 | `physical_response`与`defuse`全部满足 |
| 整包操作 | 一项`add_response_defuse_flat`；以后多项也须对同一目标全部成立 |
| 数值 | `amount=floor(0.5×本包实际分配X)`，本次值来自成器，不硬编码清和值 |
| 最低有效量 | X≥2才能形成至少1点化解加值；不足则本包不生成 |
| 每X预算 | 来源固1、根性1、结构1、通0.35，沿本轮候选共同求解的真实分配 |
| 战斗代价 | 沿格剑原费用、次数、冷却与真实应对，不新增动作或统一费用 |

接口顺序：

```text
全局技能可改写槽登记
  → 模板注册与全局适配验证
  → 共同求解器给出本物件真实来源和X
  → 整包量化、验证预算并冻结Bundle
  → 人物选择盘中一份合法目标
  → 解析ModifierPlan
  → 真实事件重查来源并调用登记槽
```

模板注册时必须在**全局启用技能库**找到至少一个整包合法目标。检查不读取炼器者学了什么，不能因为炼器者尚未参悟格剑就改变成器；人物使用时仍须真实习得目标，器物不免费授予。

每个操作都必须是已注册ID、合法槽／阶段、合法数值类型和该模板版本的换算参数。任一操作不兼容，整包拒绝，不采用旧BindSingle的“只应用可用子项”。多项操作的预算要按完整包计价，不能让每项各领同一份满额效力。

冻结结果保存真实source_instance_id、bundle_id、template_id／version、matcher、全部量化operations、实际来源分配、预算扣除与当次生成版本。新物生成必须引用完整模板，不能只保存随意写字段的匿名效果；重复冻结同一物件包不得再次领取预算。量化损失留在记录中，不返成其他奖励。

## 三、可配置与当前生效分开

`CanConfigure`检查：本人拥有该真实物件、它的当前快照确实提供此包、器物可用、已选择合法手持用法、目标在所选布局中且为本人已学招式、准确身份／关键词／真实机制／整包操作均合格。**战前尚未启用也可以预绑定。**

`IsActiveNow`在上述条件之外，还须检查：当前实际手持的就是该实例、它已启用、来源及目标身份仍有效。御使用法、收藏、待启用或卸下均不生效。

器物化法是否另占格、目标选择UI和几何关系仍待定。本契约不强制新增1×1化法块；秘籍已经采用的方向化法保持自己的现行方式。

绑定身份至少包含：

```text
actor_id + source_instance_id + bundle_id + template_id/version
  + target_layout_id + target_placement_id + target_base_skill_key
```

其中摆放ID决定强化哪一份，基础技能key继续供原技能次数／冷却等共享账本使用。两份同名格剑A/B只选A，就不能让B因同名或同基础key自动取得该包。移动、旋转保留placement_id；移除、卸下或失去资格时暂停，保存原选择，不按同名寻找替代对象。

## 四、修正计划与真实事件

原型的`ResolveModifierPlan`输出来源、目标、当前生效状态、确定的操作、原技能费用／次数／冷却，以及缓存身份；不改共享技能资源。正式接线时应让悬停与真实执行读取同一修正计划。

缓存身份包括人物、布局及版本、目标份数、真实物件、来源状态版本、冻结包摘要及模板版本；还核对实际手持实例与启用状态。真实执行仍重查当前来源，不能仅因缓存曾经生效就继续使用。

真实事件上下文至少包含battle_id、cast_id、event_id、人物、共同回合、布局、目标份数、结算阶段、来袭伤害类型和是否真实应对。只有格剑实际应对物理攻击、进入化解计算时，才对已选份数增加本包的整数值；摆下、预览、扫描待命、普通打出或其他伤害类型不提前发放化解。

同一真实应对事件和同一包只记一次，防止多段或重复回调多加。来源失效只停止之后的修正，不倒扣已经形成的化解／护盾等结果，也不归还原技能机会、费用、次数或冷却。

原技能账本仍使用基础身份，目标单份机会仍使用placement_id。模板不能改写费用或次数以生成新动作。正式多来源排序应保留现行秘籍改写次序，再在明确登记的槽中合并器物加值；本轮只有一个手持来源及一个已登记加法操作，不开放任意覆盖或未知操作的最后写入优先。

## 五、复制与额外施放边界

上下文保留`copied_from_placement`与`borrowed_opportunity_placement`。当前复命会复制上一次成功的技能副本，并扣另一份尚未检查的原招机会；器物包如何继承及怎样重验目标仍待裁定。

原型遇到复制上下文会明确报告政策未定，不擅自让器物化法成为复命通用可复制项。这是契约的未决状态，**不是修改原20招复命的正式行为**。原技能已定次数／冷却和周天独立机会继续由原战斗系统管理，本页不因注册包增加免费施放。

## 六、旧代码真实已有与尚缺桥接

| 现有位置 | 已有能力与缺口 |
| --- | --- |
| `Character.SkillRewrites.get_skill_rewrite_choices` | 有秘籍和器物来源项；旧器物Available依装备判断，没有新手持启用条件 |
| `SkillRewriteChoice` | 有Matches和Apply；旧绑定按原技能key，没有一份摆放目标身份 |
| `ForgedEquipmentLoadout.CanBind/BindSingle` | 有旧化解／穿防算子；BindSingle允许挑子项，不能作为新整包规则 |
| `CombatBoardCatalog.FromCharacter` | 只收BoardDefinitionVersion>0；现器物来源没有此定义，尚未进新人类盘 |
| `CombatBoardRewriteSource/ResolvePlacement` | 当前仅传秘籍effect_ids与tags，不传器物化解数值或执行器物Apply |
| `CardRules.Block` | 已有artifact_block_bonus低层加值；还需要新来源政策、份数目标及真实事件桥接 |
| `GongfaCombatRuntime` | 有具体秘籍事件分支；不是未知effect_id或任意器物操作注册器 |
| `BoardOwner.Resolved` | 当前主要在布局提交时清缓存，还需要来源启停版本与事件重验 |

因此只给旧器物补board版本，或只往技能写一个未知effect_id，都不足以接通新接口。本轮未改上述生产代码、原卡资源、正式生成器或玩家存档。

## 七、契约原型与验证

[候选契约](器物化法接口契约候选_20261108.json)登记唯一首批模板、唯一操作及准确技能接口。[纯Python原型](../../../tools/forging/artifact_rewrite_contracts.py)提供`Registry.register_template`、`generate_bundle`、`freeze_existing`、`can_configure`、`bind`、`is_active_now`、`resolve_modifier_plan`和`settle_defuse_event`。

原型直接消费[清和属性池修订实算结果](清和剑属性池修订实算结果_20261108.json)中的transformation_bundle，验证真实X、floor量化值、来源、模板版本和预算；不是用固定示例值替代清和结果。

可运行：

```text
python -B tools/forging/artifact_rewrite_contracts.py --self-check --validate-result docs/plans/物品与装备/清和剑属性池修订实算结果_20261108.json
```

验证涵盖A/B份数隔离、准确基础身份、缺关键词／真实机制拒绝、兼容变体、未启用可配置、御使不生效、整包原子性、未知字段拒绝、原费用／次数／冷却继承、移动／移除／换物、来源失效不回滚、事件去重、预算不重复、复制未定及候选元数据。结果见[契约验收](器物化法接口契约验收_20261108.json)。这些只证明独立契约原型，不等同Godot编译、场景或实战验收。

本次35项检查通过。直接导入清和v2独立候选包，实际X为7.497278770855065，对应追加值3；用此包运行合成A/B应对事件，指定A增加3、同名B增加0。合成事件不读取或保存真实人物，验收不保存临时玩家数据；清和后续数值重算时应重新导入当前包验证，模板不固化这个3。

## 八、本轮验收边界

1. 首包效果为格剑真实物理应对的化解加值，参数随本次分配生成；未改原目标、费用、次数与冷却。
2. 不新增人物属性、状态、关键词、射程、位移、灵识费用或动作；未来操作仅列未开放类别。
3. 整包共享真实预算，未定义的返费、资源生成及额外施放不由接口产生。
4. JSON、本文与Python原型使用相同模板、操作、匹配条件和量化规则；清和结果由实算包导入，实际Godot桥接仍缺。
5. 执行独立self-check与清和包消费检查，保留正式运行未接状态，不借旧战斗验证宣称已完成器物新盘实施。
