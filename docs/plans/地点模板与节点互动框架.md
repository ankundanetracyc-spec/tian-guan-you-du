# 地点模板与节点互动框架

> 状态：当前主模式规划  
> 目标：保留大世界的地点数量与探索感，但避免“一个节点 = 一套专属 UI、脚本和玩法”。  
> 原则：节点多不是问题；互动规则碎片化才是问题。

## 一、结论

当前项目是单主角个人修仙。世界节点按大陆、区域、势力辖域与具体地点组织，交互服务行旅、探索、修行、交易和人物往来。

需要避免的是以下错误结构：

```text
白石镇 = 一套城镇系统
另一座城镇 = 另一套城镇系统
不夜港 = 第三套城镇系统
```

正确结构应为：

```text
地点类型模板 + 静态地点数据 + 动态地点状态 + 行动配置
```

地点只决定“有什么内容”，模板决定“如何交互和结算”。

## 二、四层拆分

### 1. 静态地点数据：这个地点是什么

沿用 `WorldNodeData` 已有字段：名称、类型、显示层级、地形、灵压、危险、势力与描述。稳定地点 ID 和地点内容继续由此表达；固定地图中的地点锚格与格网旅行以《百川固定方格世界地图设计》为准，不再把道路连接字段当作唯一寻路图。

静态数据不保存库存、人物停留、探索进度、资源剩余或临时事件。

### 2. 动态地点状态：这个地点现在怎样

每个地点在存档中只保存必要运行状态，例如：

- 是否已发现、已考察、已完成首次探索；
- 资源储量、恢复月份、探索进度；
- 当前驻留人物、在途人物及可交互状态；
- 市场库存、刷新时间、已知传闻、可用委托；
- 势力关系、封锁/开放状态；
- 当前临时异象及其剩余时间。

### 3. 地点模板：这个地点能做什么

模板不保存具体奖励和人物，只提供统一行动槽、页面布局与结果处理。

### 4. 行动配置：这一次行动如何结算

任何地点行动最终都应产出统一结果：

```text
耗时 + 主角状态 + 资源消耗 + 奖励事务 + 地点状态变化 + 消息
```

现行行动统一复用时间、主角状态、物品事务、地点状态与存档接口，各地点模板不重复建设底层流程。

### 大世界行动体力（现行裁定）

- 大世界及地点/副本活动共用角色的一种持久体力，不另设世界法力池；当前体力与上限保存在正式角色数据中，并与即时战斗精力字段分离。
- 首轮可调测试值：初始/上限 100 点；一次完整交谈 1 点；一次有效普通交互 1 点；修炼每游戏小时 0.5 点；研读每游戏小时 1 点。连续修炼一周按 168 小时计消耗 84 点，初始体力仍余 16 点，确保前期不会很快被修炼卡死。探索与大世界术法仍按行动单独配置费用。
- 交谈、产生结算的交互、探索行动和大世界术法按行动配置体力费用。一次完整交谈按一次行动结算，不按对白行数重复扣费；打开界面、查看情报、悬停、取消或无效操作不扣体力。首轮已将角色交谈和有效交易/采集结算接入测试费用。
- 普通方格行旅沿用《百川固定方格世界地图设计》的遁速、地形和游戏时间结算，不额外扣体力；若行动本身施放术法或执行特殊移动，再按其行动配置扣费。
- 休息仍由玩家选择时长，首轮按每游戏小时恢复 1 点体力，最多恢复至上限；休息界面预览本次恢复量，不因进出场景或打开界面回满。体力余额属于正式角色存档。
- 即时战斗继续使用战斗内精力、法力与灵识规则，不自动转换或扣除大世界体力。同一术法可分别配置世界行动体力费用和战斗费用，二者不按比例互算。

## 三、四个玩家可见模板

底层可保留既有 `NodeType` 以兼容数据；玩家层面按当前单人玩法收敛为四种可复用模板。底层类型名不改变玩家可见模板与实际玩法。

| 模板 | 对应现有类型 | 标准行动 | 地点差异由数据决定 |
|---|---|---|---|
| 聚集地 | `CITY`、`VILLAGE`、多数 `SECT` | 交易、消息、人物接触、暂住 | 货池、传闻池、委托与关系/势力门槛 |
| 资源地 | `RESOURCE` | 巡查、探索、按配置采集、撤离 | 已定义资源、储量、风险、恢复与开放条件 |
| 探索地 | `DUNGEON`、部分 `WAR` | 进入、继续探索、撤离、结算 | 探索图、敌群、事件、奖励、重复规则 |
| 势力与特殊地点 | `SECT`、部分 `WAR`、世界地标 | 造访、交涉、入门、试炼或专属委托 | 势力门规、身份条件与专属行动配置 |

“宗门”“渡口”“商港”“村庄”不需要各有一套完整 UI。它们先进入聚集地模板；例如渡口只是在该模板上额外配置“航路”行动，宗门只额外配置“拜访/贡献”行动。

## 四、统一地点场景与标签交互

所有可抵达地点统一采用两层交互，不因地点类型或专属玩法而改变入口逻辑：

```text
世界地图抵达地点
    ↓
第一层：全屏节点内子场景（地点环境图 + 场景标签）
    ↓ 点击具体标签
第二层：该标签对应的功能界面（大按钮等明确行动入口）或直接进入副本
```

第一层是地点的全屏内景/总览场景，参考玉虚仙宗内景与青溪里场景。可点击标签布置在对应地标或场景区域上，标签名称表达地点/设施/行动入口；点击后直接进入该处对应的功能界面，或在目标本身就是探索副本时直接进入副本。功能界面可以使用醒目的大按钮供玩家选择具体行动；不要求每个标签都再多套一层菜单。进入节点内景本身不得擅自自动开始探索、战斗或消耗行动。

第二层按功能复用已有模板：例如交易、修炼、休整使用相应功能界面；探索副本使用独立的副本场景与路线交互。可见的返回操作与 Esc 必须共用逐层返回逻辑，每次只退当前最内层：先关闭详情/弹窗，再退功能子场景，再回地点内景，最后才离开地点回地图；不能因外层场景仍可见就跳过内部层级。玩家通过返回操作回到地点内景，再按原入口离开地点；地图侧栏只负责节点情报和旅行，不替代地点内场景。

场景背景只绘制环境，不烘焙标签文字、按钮或 UI；标签由运行时界面绘制，且需遵守《UI视觉规范》的场景安全区，不遮挡主要地标或被固定 HUD/侧栏覆盖。标签数量按场景实际可用功能配置，保持清楚、可辨、可点击；未开放的功能可作为环境线索呈现，但不生成空白或伪可用按钮。

功能界面中的行动数量仍按内容密度控制，常规保持 2～4 项、最多四项；行动确认前按对应系统展示耗时、消耗、风险与预计结果。不同地点可有不同标签和功能内容，但共享上述两层入口模式与功能模板，不为每个地点另造整套 UI。

### 节点式副本、驻留 NPC 与同步行动

东林地等探索副本使用有向图表达单路、分支会合、环路或网状路线；节点 ID、连接、节点环境、可执行交互和 NPC 驻留状态分离。玩家进入节点时可查看该节点现存 NPC，并通过稳定角色 ID打开互动；NPC 不因打开面板、重进场景或刷新列表而重抽。

东林地首轮样板已接入：路线图为林缘→叶溪→（溪石径/盘根径）→深林会合处→静冠洼地，盘根径另可回到会合处。玩家和 NPC 共用 `遁速`，不另造副本速度属性；东林地暂定副本级节点基础耗时为遁速 100 时每跨越一条相连路线边 1 个游戏时辰，实际耗时统一按 `1 × 100 ÷ 当前遁速` 计算，不为各条边分别写固定时长。该基础值是东林地内部的短测尺度，不把副本节点等同大世界 40 公里格，也不重复叠加大世界地形系数；不是所有副本的最终平衡值。当前随机 NPC 直接使用存档内遁速字段，首轮默认 100；体魄/敏捷到遁速的权重仍按大世界地图主案留待后续定值。玩家每推进一个相连节点就按同一规则推进游戏时间；NPC 以自己的遁速累计该游戏时间，达到自己的节点耗时后沿登记路线前进；双方同时经过同一节点或相向交错时可形成遭遇。NPC 的副本位置、边内进度、遁速与个人携带物都随稳定 NPC ID 进入正式存档；副本内人物不参加会将其移出地点的月度行动，只保留既有年龄演算。

遭遇按稳定 ID、路线位置与本次行动时序判断，再独立计算是否出手。东林地原型的出手率为可调测试值：基准 8%、上限 55%；性格、`劫掠/好斗` 行为标签、目标所属势力态度、个人关系（NPC 个人关系字典/标签，或 NPC 对玩家关系）、百川声望与境界差分别影响结果，同一势力提供抑制而非绝对免战。已记录的既往副本冲突会让双方有效关系至少按 −10 档处理，但不改写独立保存的真实关系值。当前测试修正为：多疑/果决/机敏 +12/+8/+4 个百分点，温厚/圆融/随和 −4；劫掠/好斗 +24/+16；势力态度档 0–6 为 +18/+13/+7/0/−4/−8/−12；个人关系 ≤−30、≤−10、≥30、≥10 分别 +18/+10/−16/−8；百川声望 ≥300、≥100、<0 分别 −12/−7/+4；境界评分差达到 +8 或 −8 时 +8 或 −8；同势力 −6。最终夹在 1%–55%。这些是东林地短测系数，不是已定的世界平衡，也不应被其他地点直接照搬。区域声望、势力态度与私人关系仍是不同输入，禁止合并成单一好感值。

劫掠只转移败者 `carried_items` 中实际携带且可正常放入行囊的物品；NPC 商贸库存、抽象资源、宗门公库和场景资源都不是个人战利品。短测中，随机 NPC 生成时有 65% 概率带有一种现有物品、数量 1–2（当前候选为兽骨、兽皮、肉干、灵石）；败者存活时转移一件，死亡时尝试转移其全部随身物品。携带物与交易库存分开保存，以上携带率与候选配置均为原型值。遭遇使用现有即时战斗；NPC 战败死亡保留稳定 ID、死亡状态与死因，不会因刷新/重进副本复活。主角战败严格沿用既有规则：不永久死亡，战后以至少 1 点且约 10% 上限的生命、战斗精力和法力恢复；不由节点面板另造战败处理。战斗返回后在同一结算回调中落 NPC 快照、伤亡、物品转移与行动记录，并标记正式存档。当前原型由 NPC 主动触发冲突；玩家主动攻击与逃离/保护机制仍未接入，待单独规划。

巡查型委托仅核验标定路线、经过节点和耗时；常态可以没有任何异常，完成不要求采集物品，也不应把沿途采集伪装成巡查目标。若巡查中确实触发异常，必须由已定义事件独立处理，不将异常结果作为每次任务的必然内容。

场景/峰内行动入口统一复用青溪里 `SceneActionButton` 与 `SceneActionRope`。多个签牌按从左到右的横向顺序悬挂在一根贯穿画面的自然弧形主绳上：主绳两端从左右边缘较高处牵出，向中间平顺下垂，不在中间打结；签牌集中于画面中部安全区，保持可读和可点击。签中文字竖排。鼠标横向掠过签牌附近时，签牌产生受限摆动并以弹簧阻尼逐渐回稳；签底红绳穗有独立、略滞后的摆动与回稳，不是与牌面完全刚性同步。主绳、签牌和红绳穗均由运行时控件绘制，不烘焙进背景图。

场景行动组默认不再套一层大面积深色底板；标题与说明直接浮于场景，签牌复用公共纸面样式。仅在实际背景导致可读性不足时，才按《UI视觉规范》局部处理对比度。可见行动超过四项时，按功能语义分组或拆成下一层页面，不把签牌挤到难以辨认。此悬挂签菜单只用于地点/峰内行动入口，不替代世界地图或地点总览中锚定地标的热点标签。

### 青溪里原型与通用控件复用

青溪里是序章引入内容，不是一次性 UI 系统。序章中已经验证的角色列表、任务栏、全屏地点场景与行动控件，应作为后续世界内容的公共交互原型：后续场景优先复用同一场景结构、控件、脚本和数据接口，以配置决定标题、行动、可见状态与内容；不要因地点或宗门不同而复制一套外观和行为近似的 UI。行动控件的公共场景形态为弧绳悬挂的竖签，签牌和红绳穗分别响应鼠标并以阻尼回稳。

确有功能或可用性差异、现有控件无法承载时，才新增控件；新增前先判断能否将旧控件抽成可配置的公共组件，并在对应主案说明差异理由。玉虚仙宗峰内行动使用青溪里李宅“静室 / 休息”的同一悬挂签控件及物理反馈，不另做同功能的峰内按钮皮肤。

示例：

| 地点 | 初期可用行动 | 后续扩展边界 |
|---|---|---|
| 东林地 | 探索、撤离 | 仅在专题定义后扩展已存在物品的采集 |
| 白石镇 | 交易、打听、暂住 | 按现行聚集地/交易专题配置 |
| 灵草谷 | 考察、探索 | 只按灵草谷专题与有效物品配置扩展 |
| 青岚观 | 造访、人物接触 | 按宗门/势力专题逐项配置 |

## 五、内容密度分级

不是所有节点都在同一开发阶段开放同等内容。

| 内容等级 | 适用比例 | 制作方式 | 例子 |
|---|---:|---|---|
| 标准节点 | 约 70% | 完全数据驱动，复用模板 | 普通城镇、资源地、常规洞府 |
| 特色节点 | 约 25% | 模板 + 一项独特行动 | 渡口航路、药谷季节、矿脉深层 |
| 主线节点 | 不超过 5% | 模板 + 专属事件/场景 | 青溪里序章、镜月泽等已规划关键地点 |

一个地点只有在其独特行动无法由“交易、消息、委托、探索、已配置采集、关系”组合表达时，才允许新增专属系统。

## 六、旧数据兼容边界

当前首期只以百川固定方格地图中已确认的势力与具体地点为准。旧节点资源可暂保留稳定 ID 兼容；未列入现行地点配置的旧内容不构成功能承诺。

兼容旧 `HOME` 等枚举值时，只允许读取不会破坏当前流程的稳定地点身份，不由枚举值自动扩展玩法。青溪里只承担序章引入，离村后不可作为回返据点、委托来源或人物关系网络。临时异象必须遵守对应事件专题，不从旧节点目录自动生成。

## 七、百川首批场景验证

先用已确认的首批场景验证模板，而不是一次制作完整世界：

| 地点 | 模板 | 首轮要验证的能力 |
|---|---|---|
| 青溪里 | 序章引入地点 | 苏醒、修行启蒙、首次战斗与离村；离村后不作为可返回据点或关系网络 |
| 白石镇 | 聚集地 | 市场、消息、一般委托 |
| 东林地 | 林地探索地点 | 使用 `east_woods` 单格地点锚点 (70,113)，紧邻已标记林地格 (69,113) 并显示通用占位标记；与东林镇妖会 2×2 势力标记 (56,132) 分离，两个 ID 不互相冒用 |
| 灵草谷 | 资源/探索地点 | 仅按已有地点与物品配置逐步开放，不凭模板臆造资源或奖励 |
| 玉虚仙宗 | 势力地点 | 复用宗门内景与峰内行动控件，功能遵守宗门主案 |

新增地点优先复用上述模板与公共场景控件；功能和奖励必须先在对应专题定义，不因模板示例自动视为已经开放。

## 八、实现顺序

1. 保持稳定地点 ID、固定格锚点、所属辖域和场景入口一致；地图素材缺失时仅用通用占位标记，不新增虚构地点。
2. 地点抵达后进入全屏节点内景，再通过场景标签进入已存在的功能界面或探索副本。
3. 以东林地验证单人探索入口与地图—地点往返；仅接入已有配置的遭遇、耗时、奖励和退出结算。
4. 以白石镇验证聚集地模板和已有交易/消息接口；功能未接通时不展示伪可用标签。
5. 后续地点通过配置复用模板；只有现行策划定义且确有必要时才添加专属功能。

## 九、验收标准

- 新增一个普通资源地时，不新建重复地点 UI；只新增经策划确认的地点/资源配置。
- 新增一个普通集市时，不新建交易系统，只替换市场、传闻和委托数据。
- 玩家从地图格网抵达正式地点锚格后，先进入全屏节点内子场景，通过场景标签进入对应功能界面或副本；地图情报不替代该流程。
- 一个行动的奖励只通过对应系统已存在的物品/数值事务结算。
- 主线专属内容可以挂在地点模板上，但不会破坏该地点的普通交易、探索或采集功能。

## 十、东林地节点扩充（现行实现更新）

东林地路线图扩展为 14 个逻辑节点：林缘、断叶溪沟、深林会合、静冠洼地四处保留地点名；另外十个只是普通林间路段，不给每处另造专名。溪沟、盘根、蕨草三条支路汇入深林会合处；会合处可直达静冠洼地，也可选上侧林径或下侧浅沟绕行，洼地与会合处保留环路。普通路段以小型无名节点标识，悬停和到达后仍显示对应环境说明。

玩家可见路线图和 NPC 演算共用同一组邻接关系；保留既有路线 ID `forest_edge`、`leaf_creek`、`creek_path`、`root_path`、`deep_meet`、`quiet_grove`，旧存档停留在原节点时可继续游玩，其中沿溪近路与盘根路段现改为无名普通节点。巡查事务至少推进四次相连节点并抵达静冠洼地才结算，节点耗时仍按既有遁速规则逐步推进。
