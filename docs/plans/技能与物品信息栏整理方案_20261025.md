# 技能与物品信息栏整理方案

状态：2026-10-25，规划稿，尚未实施。行囊单击的语义已向用户提问，待确认；本文不覆盖现行交互规则。

## 一、范围与现行依据

整理战斗技能、行动队列技能、物品悬停和行囊单击操作，后续让人物技能库、百科、交易、兑换与成品展示复用共同结构。

- [统一悬停与输入规范](../美术规范/悬停信息统一与游玩输入优化_20261014.md)：所有悬停完整展开，无内部滚动条；普通操作按钮不添加重复操作提示。
- [技能动态数值展示规范](技能动态数值展示规范.md)：先结果、紧接代入公式；伤害是当前预估，目标防御等在命中时结算；费用、目标、触发、次数、冷却等不能丢失。牌面已要求撤下攻伐／守御／术诀分类。
- [UI视觉规范](../UI视觉规范.md)：沿用纸墨风格与正式界面层级。

保留现有字体、鼠标延迟、边缘避让及输入透传。物品属性、药效、丹毒、器蕴和技能规则继续以各自现行专题为准；本案不新增或调整规则与数值。

## 二、当前问题与代码证据

| 现象 | 当前实现 | 整理方向 |
|---|---|---|
| 外框统一，内容仍像整篇正文 | `HoverInfoContent` 只有标题、正文、图标、副标题，各入口自行拼接 | 共用结构化段落与字段 |
| 技能重点难扫读 | `CombatSkillBar.BuildSkillHoverInfo` 将费用、目标、次数、冷却逐段空行，再接效果及公式 | 短字段集中，效果按条件分组 |
| 仍有旧技能分类 | 同一构建方法仍输出技能类型 | 展示层撤下旧三分类，保留关键词 |
| 物品栏目不适合类别 | `StoragePanel.build_hover_content` 给材料、装备等统一拼接“词缀与功用／使用效果” | 按类别选择栏目 |
| 单击和悬停重复 | `on_slot_info_requested` 点击后仍填充完整详情，不可操作物品也会展示 | 确认点击语义后拆分信息与操作 |
| 内部字段与玩家信息混杂 | 部分旧法宝显示实例 ID、绑定资源路径；部分器物有空栏目 | 内部字段留开发诊断；去掉空栏目，保留必要限制 |
| 长信息变宽、字变小 | 展示器扩宽后可将正文从18逐步缩到12 | 优先优化分组、换行与分栏，不能靠删除信息解决 |

以上来自文档与代码检查，本轮尚未进行实机目视验收。

## 三、共用视觉层次

1. **名称与身份**：图标、名称；下方简短显示类别、品阶。关键词独立成行。
2. **关键内容**：直接说明做什么、获得什么；数值与单位作为完整短语，效果正文使用主要文字色。
3. **条件与限制**：目标、费用、触发、使用条件、次数及冷却使用明确标签。代价和受限状态用克制的颜色提示，同时保留文字。
4. **计算说明**：紧接对应动态效果，通过次一级字号、缩进和较淡文字区分，保留代入值、公式和结果，不折叠、不移到另一个页面。

沿用深墨底、浅纸字、灰金边线。名称、正文、说明形成三级字级，具体字号与宽度通过实际窗口验证后确定。栏目仅通过间距、细线分组，不为每行加框或铺底色；相同字段不在副标题和正文重复。

空栏目不占位；未知且影响决策的信息明确为未知，不用0冒充。零费用、无限次等有规则意义的值仍需显示，不能当成空内容删除。

## 四、技能信息栏

| 位置 | 内容 |
|---|---|
| 标题区 | 图标、名称、关键词；撤下旧三分类 |
| 第一组短字段 | 费用、目标；长字段自然换行 |
| 效果区 | 按发动条件与结算顺序分段；动态效果后紧接对应计算说明 |
| 限制区 | 剩余次数、冷却、队列补充；不限次数也明确展示，无冷却时不设空栏目 |

特殊技能不能硬塞进普通模板：

- 应对技能分“应对触发／未触发应对”两组，各自展示条件、费用和效果。
- 复命等依赖另一技能的情况，展示当前复制对象、本技能费用、复制费用、合计及双方必要限制；没有可复制对象时明确说明。
- 多段伤害保留段数和每段数值；目标防御未知时继续标为当前预估。
- 化法追加按来源分组并紧接被追加效果，不重复整份基础技能。
- 技能栏和行动队列共用格式化内容；动态刷新保留现有角色、状态、费用和次数来源。

在现有格式化阶段生成结构化段落，不用正则从成品文案猜测触发条件和公式。保留旧正文接口，逐项迁移。

## 五、物品信息栏

| 类别 | 栏目与顺序 |
|---|---|
| 材料 | 名称、类别、品阶、数量 → 五行／质地／相性 → 功用与各自品级 → 简短用途和边界；不套“使用效果” |
| 丹药 | 名称、丹阶、丹效、颗数 → 实际药效 → 丹毒代价及使用条件；受丹毒影响时保留实际量与必要基础值 |
| 装备／器物 | 名称、品阶、器类 → 装备收益 → 化法／主动效能 → 相关灵识占用、器体及器蕴贡献；按实际存在内容生成栏目 |
| 秘籍 | 名称、类别 → 功法简介 → 境界／灵根等真实要求 → 研读需求；操作入口由真实接口决定 |
| 衣着 | 名称、适用人物 → 立绘变化及适用限制，明确是否具备战斗属性收益 |
| 其他 | 读取真实用途与效果；配置缺失时诚实说明，不推测效果 |

器物的“本件贡献”和“角色已激活收益”必须区分；化法、在场占用和施法临时占用遵循现行规则，分别标注，不合并成一个含义不清的灵识数字。

普通行囊不反复解释堆叠和瓷瓶外观的通用规则，将其收录对应帮助／百科；本次使用的条件、后果及代价仍保留。炼丹结果页的单颗丹效分、本炉装入记录等，仅在具备该上下文时展示。

## 六、行囊单击（待用户确认）

用户原话可能是新交互要求，也可能是在反馈单击看不到信息，已提问，确认前不改运行逻辑。

若用户希望“悬停看详情、单击只操作”，建议：

- 悬停显示完整物品信息。
- 单击可操作物品，只在格子附近显示装备／卸下／穿上／使用等真实操作按钮，不复刻名称、图标、属性与说明。
- 没有操作的物品不因单击新弹出内容，并关闭上一件物品的菜单；原悬停信息仍遵循悬停规则。
- 当前不可用的操作仍遵循现有可用性判断，不放开入口或增加动作；禁用操作项是否保留，需与用户的“无互动不显示”要求一致。
- 再次单击同格、单击空处、右键返回、关闭行囊时收起菜单；换物品只保留一个菜单。
- 菜单出现时收起当前悬停卡，避免挡住按钮；关闭后恢复正常悬停触发。拖动物品不误开菜单。
- 操作完成后同步库存、数量和装备状态；物品耗尽时关闭菜单；失败沿用真实结果反馈。

若用户希望修复“单击看不到信息”，应另采用可固定的完整详情方案，与纯操作菜单二选一，不同时作为默认规则。

## 七、实施顺序与验收

1. 确认单击语义；用真实普通技能、应对技能、复杂技能、材料、丹药和器物先做界面预览。
2. 共用展示器增加结构化字段／段落，保留旧正文入口兼容；先迁移战斗技能和行囊。
3. 统一技能栏与行动队列，再统一物品在行囊、交易、兑换、炼丹与炼器结果中的共同字段，各入口只提供上下文差异。
4. 若确认纯操作菜单，再拆除单击完整详情，沿用真实操作和库存更新逻辑。

验收要求：

- 逐项核对费用、目标、关键词、触发、效果、公式、次数、冷却和特殊分支，不能遗漏规则。
- 材料、凡器、法器、丹药、秘籍、衣着分别检查有内容／空栏目、可操作／不可操作情况。
- 角色属性、状态、丹毒、库存和装备改变后及时更新；同物品在不同入口的共同字段一致。
- 覆盖长技能、多段伤害、复命、应对两分支，以及长材料、器蕴和化法说明。
- 在1672×941及1280×720画布、四角锚点和窗口缩放下目视验收：无裁切、无出屏、无内部滚动条；底层滚轮、拖动、右键返回正常，操作按钮可达。
- 如长内容无法在完整显示与清晰可读的约束下容纳，记录具体样本并向用户说明冲突，再确定调整方式，不默默删内容或无限缩字。
- 运行编译、相关悬停／滚轮回归及行囊操作检查，保留实际截图；历史验证不计为本轮通过。
