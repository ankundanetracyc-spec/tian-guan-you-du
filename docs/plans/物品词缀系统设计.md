# 物品词缀系统设计

> 状态：词缀底座与首批资源已实现，配方系统待实现；功用以《通用物品词缀与材料生态设计》新版基础功用表为准
> 日期：2026-09-11
> 目标：用一套简单、稳定、可校验的词缀语言，支撑材料、炼丹、画符、炼器与阵法。

## 一、最终结论

物品词缀采用原策划的五个维度：

1. 五行
2. 质地
3. 功用
4. 相性
5. 品阶

技术实现上分成两类：

- 离散词缀：五行、质地、功用、相性，继续使用 `维度[值]` 格式。
- 数值条件：品阶，使用固定整数 `grade_value`，不写入 `tags`。

系统明确取消以下实例差异：

- 年份
- 纯度
- 耐久
- 绑定
- 随机词缀

因此同一个物品定义的所有副本完全一致，可以只按 `definition_id` 或资源路径合并数量。

## 二、系统边界

词缀系统只负责三件事：

1. 描述物品具有什么性质。
2. 判断物品是否满足配方或槽位要求。
3. 为配方、筛选、提示和后续数值公式提供统一输入。

词缀本身不直接执行战斗效果。例如 `功用[生]` 只表达生长、修复语义；回春丹实际恢复多少生命，仍由其绑定的技能或效果资源决定。

物品分类、词缀和玩法行为相互独立：

- 分类回答“它是什么”：材料、装备、秘籍、阵盘、器具、符箓、丹药。
- 词缀回答“它具有什么性质”。
- 行为资源回答“使用后发生什么”。

## 三、五个维度

### 1. 五行

格式：`五行[金]`

可选值：

- 金
- 木
- 水
- 火
- 土

规则：

- 允许没有五行。
- 允许多选，普通材料建议最多两个。
- 第一版不设置全局五行生克；具体配方显式要求需要的五行。

### 2. 质地

格式：`质地[石]`

| 值 | 含义 |
|---|---|
| 石 | 岩石、矿石 |
| 木 | 灵草、植物组织 |
| 金 | 金属与冶炼产物 |
| 玉 | 玉石类材料 |
| 晶 | 灵石、结晶类材料 |
| 砂 | 粉末、颗粒、骨粉 |
| 液 | 灵水、药液、墨液 |
| 气 | 灵雾、丹气、气态材料 |
| 甲 | 甲壳、鳞甲 |
| 骨 | 骨骼、角、牙 |
| 布 | 织物、符纸、灵丝布 |

规则：

- 允许多选，普通材料建议一至两个。
- 质地表示物理形态，不代替物品分类。
- 同一材料可同时属于两个质地，例如玄武壳可有 `质地[甲]` 与 `质地[骨]`。

### 3. 功用

格式：`功用[破]`

功用是炼器、符箓、阵法、丹药四个制作系统之间共用的抽象动作语言。五行、相性和质地决定同一功用在不同材料与工艺中的具体表现；功用本身不直接执行成品效果。

| 功用 | 抽象语义 | 跨工艺表现示例 |
|---|---|---|
| 固 | 稳定、承载 | 耐久/器胚稳定；符纹稳定；阵基稳固；固本/稳药性 |
| 聚 | 汇集、蓄积 | 蓄能/聚灵；聚灵符；聚灵阵；聚药力/聚气 |
| 通 | 连通、导流 | 导灵/灵路；术式传导；阵路连通；通脉/行气 |
| 化 | 转换、炼化 | 属性转化；化煞/化形；转换阵；化毒/炼药 |
| 引 | 牵引、导向 | 锁敌/牵引；引雷/引火；引灵/牵阵；药引/引气 |
| 破 | 穿透、瓦解 | 破甲/破盾；破禁/破邪；破阵；破瘀/破毒 |
| 护 | 保护、隔绝 | 护主/护器；护体；护阵；护脉/护心 |
| 镇 | 压制、固定 | 压制器灵；镇煞/镇魂；镇压阵眼；镇痛/镇魂 |
| 生 | 生长、修复 | 修复器物；生机符；生长阵；回春/养血 |
| 明 | 显化、辨识 | 照见/鉴物；破幻/明目；观测阵；明心/醒神 |
| 藏 | 封存、收敛 | 储灵/纳物；封物/藏息；藏气阵；缓释/藏药性 |
| 行 | 运行、位移 | 御器/加速；遁行/御风；传送/移阵；行血/行气 |

规则：

- 功用数量允许为 0 至 4 个；常见材料通常只有 1 个，高品材料可以是单一但纯粹，也可以拥有多个组合方向。
- 材料功用数量达到 4 个时已经是复合材料；超过 4 个不进入合法词典，避免出现万能材料。
- 同一功用在不同五行、相性或质地下可以表现为不同结果，例如 `破 + 金` 偏破甲，`破 + 阴` 偏破邪。
- 配方决定哪些功用能写入成品；材料带有的其他功用不会自动继承。

### 4. 相性

格式：`相性[和]`

| 值 | 含义 |
|---|---|
| 阴 | 偏寒、内敛、沉静 |
| 阳 | 偏热、外放、活跃 |
| 和 | 平衡、中和、稳定 |

规则：

- 制作材料必须且只能有一个相性。
- 第一版不做隐式阴阳冲突计算。
- 配方需要阴、阳或和时显式声明；没有声明则相性不限。

### 5. 品阶

品阶不放入 `tags`。非材料物品可配置固定整数；材料品阶从其功用材评派生：

```gdscript
@export_range(0, 27) var grade_value: int = 0
```

| 数值 | 显示 |
|---|---|
| 0 | 无品 |
| 1 / 2 / 3 | 九品下 / 九品中 / 九品上 |
| 4 / 5 / 6 | 八品下 / 八品中 / 八品上 |
| ... | ... |
| 25 / 26 / 27 | 一品下 / 一品中 / 一品上 |

材料功用使用跨炼丹、制符、炼器、阵法共用的基础词汇。单条功用等级为九品至一品，不分下、中、上。材料材评与品阶按以下规则计算：

```text
材评 = 最高功用等级 × 2 + 次高功用等级 × 0.5 + 其余功用等级之和 × 0.25
材料品阶值 = 材评向上取整，限制在 1～27；没有功用时为 0
```

材料品阶值按九品下、中、上，八品下、中、上，依次映射至一品上；例如材评 2.75 对应九品上，3.25 对应八品下。材料系统不使用“凡、灵、玄、宝、道”分档；法宝品级由法宝系统单独定义，材料材评和材料品阶不决定法宝品级。

规则：

- 每个物品定义只有一个固定品阶。
- 同名但不同品阶的物品，应建立不同物品定义，例如“回春丹”和“上品回春丹”。
- 配方通常使用最低品阶限制，不要求玩家处理小数品质。
- 品阶与修炼境界的显示映射单独配置，不写死在物品词缀逻辑中。

## 四、物品数据结构

继续以 `ItemData` 作为物品静态定义，不新增复杂的物品实例层。

推荐字段：

```gdscript
extends EntityData
class_name ItemData

@export var definition_id: StringName

@export_enum("材料", "装备", "秘籍", "阵盘", "器具", "符箓", "丹药")
var item_category: String = "材料"

@export var item_subcategory: String = ""
@export var tags: Array[String] = []
@export_range(0, 27) var grade_value: int = 0

@export var usage_type: UsageType = UsageType.WORLD_ONLY
@export_file("*.tres") var battle_skill_path: String = ""
@export var craft_data: Resource
```

说明：

- `definition_id` 是物品种类的稳定 ID，与世界实体实例 ID 分开。
- 迁移期间允许资源路径作为兼容 ID。
- `stack_count` 只保存数量；合并条件为物品定义相同。
- `base_score`、`year_multiplier`、`purity` 从新模型中移除。
- 装备继续使用现有 `EquipmentData extends ItemData`。

不建议第一阶段新增 `MaterialData`、`ConsumableData`、`StorageData` 等大量子类。字段变复杂时，优先增加可组合的用途子资源。

## 五、词缀目录与校验

新增统一词典 `ItemAffixCatalog`，集中保存：

- 合法维度。
- 每个维度的合法值。
- 单选或多选规则。
- 功用的合法值、抽象语义与跨工艺表现。
- 标签格式化与解析函数。

每个物品资源应通过以下校验：

1. 标签必须符合 `维度[值]` 格式。
2. 维度和值必须存在于词典。
3. 同一个标签不能重复。
4. 相性必须且只能出现一个。
5. 品阶不得写入 `tags`。
6. 功用超过四个时判定为非法；常见材料拥有三个以上功用时给出策划警告。
7. `grade_value` 必须处于 0 至 27。

校验失败应返回具体原因，例如：

- `未知词缀：功用[回血]，新版功用词典使用功用[生]`
- `石材配置了两个相性：相性[阴]、相性[和]`
- `品阶必须使用 grade_value，不能写成品阶[一品下]`

## 六、配方条件模型

### 1. 通用槽位

四种制作系统共用 `RecipeSlotData`：

```gdscript
extends Resource
class_name RecipeSlotData

@export var role_id: StringName
@export var role_name: String
@export_range(1, 99) var count: int = 1
@export var allowed_categories: Array[String] = ["材料"]
@export var required_all: Array[String] = []
@export var required_any: Array[String] = []
@export var excluded_tags: Array[String] = []
@export_range(0, 27) var min_grade: int = 0
@export_range(0, 27) var max_grade: int = 27
```

匹配语义：

- `required_all`：全部满足。
- `required_any`：数组非空时，至少满足一个。
- `excluded_tags`：满足任意一个即拒绝。
- `min_grade / max_grade`：检查固定品阶。
- 同一个配方的多个槽位分别匹配，避免复杂的嵌套条件。

### 2. 通用配方

```gdscript
extends Resource
class_name CraftRecipeData

enum CraftType { ALCHEMY, TALISMAN, FORGING, FORMATION }

@export var recipe_id: StringName
@export var craft_type: CraftType
@export var slots: Array[RecipeSlotData] = []
@export_file("*.tres") var output_item_path: String
@export_range(1, 99) var output_count: int = 1
@export var required_proficiency: float = 0.0
@export var craft_time: float = 1.0
```

第一版采用确定性结果：

- 满足材料条件与熟练度条件即可制作。
- 产物和数量固定。
- 熟练度先用于解锁配方或缩短制作时间。
- 暂不做随机成功率、随机品质和随机词缀。

## 七、四个系统如何复用

| 系统 | 典型槽位 | 主要维度 | 产物行为 |
|---|---|---|---|
| 炼丹 | 主药、辅药、药引 | 五行、相性、功用、品阶 | 绑定丹药技能或世界使用效果 |
| 画符 | 符纸、符墨、符胆 | 质地、五行、功用、品阶 | 绑定符箓战斗技能 |
| 炼器 | 胚体、主材、辅材 | 质地、五行、功用、品阶 | 产出固定装备定义 |
| 阵法 | 胚体、纹料、阵眼、阵枢、阵基 | 质地、功用、五行、相性、品阶 | 产出阵盘或配置阵盘 |

系统只共享材料匹配，不强行共享产物公式。每种产物的实际效果仍由对应数据资源决定。

## 八、配方示例

### 1. 回春丹

主药：

- `required_all = ["功用[生]"]`
- `required_any = ["质地[木]", "质地[液]"]`
- `min_grade = 1`

可继承功用：`引`、`通`、`护`、`化`；具体回春、行血、护脉或净化效果由丹药资源决定。

产物：固定数量的回春丹。回春丹恢复数值由其战斗技能资源配置，不由投入材料临时生成。

### 2. 破禁符

符纸：

- `required_any = ["质地[布]", "质地[砂]", "质地[晶]"]`

主材：

- `required_all = ["功用[破]"]`

可继承功用：`引`、`通`、`明`；破禁、破邪或破幻的具体效果由符箓资源决定。

产物：固定的破禁符物品，使用后调用破禁符战斗技能。

### 3. 聚灵阵

胚体：

- `required_all = ["功用[聚]"]`
- `required_any = ["质地[晶]", "质地[石]", "质地[玉]"]`

可继承功用：`固`、`通`、`藏`；聚灵、稳定或储存的具体能力由阵法资源决定。

## 九、材料配置准则

一个常规材料的推荐结构：

- 五行：零至一个。
- 质地：一个。
- 功用：零至四个，常见材料通常只有一个。
- 相性：一个。
- 品阶：固定值。

高品或稀有材料可以拥有多个功用，但仍不得超过四个。材料数量增加时，应优先通过“不同词缀组合”形成替代关系，而不是让高阶材料简单覆盖低阶材料的全部功用。

当前材料图鉴中的基础与进阶材料口径：

| 材料 | 五行 | 质地 | 功用 | 相性 |
|---|---|---|---|---|
| 裂甲石 | 金 | 石 | 破 | 阳 |
| 玄铁 | 金 | 金 | 固 | 阳 |
| 裂甲玄铁 | 金 | 金 | 破、固 | 阳 |
| 地脉玄晶 | 土 | 晶 | 固、聚 | 和 |
| 青木芯 | 木 | 木 | 生、通 | 和 |
| 凝血草 | 木 | 木 | 生、引 | 阳 |
| 灵泉露 | 水 | 液 | 聚、化 | 和 |
| 魂玉 | 水 | 玉 | 镇、明、藏 | 阴 |
| 雷髓晶 | 金 | 晶 | 破、聚、引 | 阳 |
| 月华玉髓 | 水 | 玉 | 明、镇、藏 | 阴 |
| 玄甲髓 | 土 | 甲 | 固、护、镇 | 阳 |
| 云纹灵髓 | 水 | 液 | 聚、通、藏 | 和 |

具体材料的词缀保存在各自 `ItemData` 中，不在词缀目录底层硬编码。

## 十、UI 与反馈

物品详情按固定顺序展示：

1. 分类与子类
2. 品阶
3. 五行
4. 质地
5. 相性
6. 功用
7. 使用效果

配方槽位应直接显示条件与当前匹配状态，例如：

```text
聚灵阵胚体
需要：聚；石/玉/晶之一
当前石材：缺少“聚”
```

失败提示必须来自统一匹配结果，制作 UI 不自行重复判断。

## 十一、暂不进入第一版的内容

- 年份与纯度
- 耐久与绑定
- 随机词缀
- 随机制作成功率
- 随机产物品质
- 自动五行生克
- 额外词缀倍率与复杂加成
- 同名物品的不同实例属性

这些内容未来如确有玩法价值，可以作为独立扩展加入，不预先污染当前堆叠与存档模型。

## 十二、实施顺序

### 第一阶段：词缀底座

- 新增 `ItemAffixCatalog`。
- 新增统一标签解析、校验与匹配工具。
- 将 `item_category` 收敛为字符串枚举。
- 用固定 `grade_value` 替换基础分、年份和纯度公式。
- 保持当前行囊的“资源路径 + 数量”结构。

验收：所有现有物品资源能被扫描并给出清晰的合法性报告。

### 第二阶段：通用配方

- 新增 `RecipeSlotData` 与 `CraftRecipeData`。
- 完成 AND、OR、排除、品阶和数量匹配。
- 返回可供 UI 使用的缺失条件列表。
- 配置回春丹、破禁符两个最小配方。

验收：炼丹与画符使用同一个匹配器，但生成各自固定产物。

### 第三阶段：阵法与炼器验证

- 用新配方结构重建金刚阵盘配置，不直接恢复已删除的旧阵法脚本。
- 配置一个基础武器炼制配方。
- 接入角色对应熟练度和制作时间。

验收：四个制作系统均只依赖统一的物品词缀与配方槽位接口。

### 第四阶段：内容与平衡

- 补齐基础材料组合。
- 逐步启用 12 项基础功用。
- 检查是否存在万能材料、无解配方和长期无用途词缀。
- 再决定是否需要额外词缀加成，第一版不预留复杂公式。

## 十三、最终原则

1. 同一种物品永远同质，天然可堆叠。
   可堆叠物品的统一单格上限为 `999`；装备、秘籍等不可堆叠物品上限为 `1`。
2. 词缀描述性质，不直接承载战斗脚本。
3. 品阶固定配置，不做实例随机。
4. 配方匹配只认统一词缀与品阶条件，不认具体材料名称。
5. 各制作系统共享输入规则，保留各自的产物与玩法逻辑。
6. 先做确定性制作，再根据真实玩法需求增加复杂度。
