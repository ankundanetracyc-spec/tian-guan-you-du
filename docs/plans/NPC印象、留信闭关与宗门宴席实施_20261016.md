# NPC 印象、留信闭关与宗门宴席实施

> 状态：首版已接入，2026-10-16；宴席表现于 2026-10-16 修订为窗外隔窗望入室内，并细化为“多人闲谈气泡为主、少量点名回应”。2026-10-16 补充关系／性情适配对白、无玩家提问时隐藏发言姓名、气泡集中在画面中部并留出边缘安全区；修复 NPC 交互失效时无提示的问题并显示闭关状态。最近一次 .NET 构建 0 警告、0 错误；NPC 侧栏交谈按钮烟测通过，关系／拜帖数据检查通过，视觉预览已更新。正式存档格式为 v9。2026-10-26 更新：所有日期界面隐藏具体钟点；宴席日期全天可赴，错过后结束；多场待办可并存，场地容量调整为雅集堂12人、水榭6人。窗纸后的室内保持大幅虚化，不出现可辨识的人物、席面或摆设；不用具体时辰、天气或强泛光。席间对白气泡不生成关系证据，面向玩家的回应只记给实际听见者。

## 一、NPC 对玩家的印象

关系面板在玩家对 NPC 的私交之外，显示 NPC 对玩家的定性印象。内容只从该 NPC 实际听到或参与的交谈、交易、切磋、宴席回应等行动记录归纳，列出可核验的行为线索和近期来源。没有足够记录时显示“尚未形成明确印象”。

印象只描述 NPC 能观察到的言行，不展示 NPC 的关系值或阶段，也不从性格、势力态度、声望、姓名认知、未参与的事件推断。人物关系、交往印象、姓名认知、地区声望、业力和心境继续分开保存和判定。

## 二、问候信与五年结识窗口

- 个人问候信只有明确表示愿意日后结识时，才标记为开启结识窗口；窗口从成功投递时起算五个游戏年，每年 360 日。
- 收信、读信和写信本身不增加关系、不交换姓名，也不强迫玩家回访。
- 窗口内发生真实关系事件时，玩家与 NPC 按各自行为分别结算；交谈、公平成交、完成切磋的对应关系证据各增加 1，再进入原有同类经历递减。除此之外，来访候选权重乘 1.5。
- 合格新信刷新截止时间，不叠加时长；同一来源事件重复投递不重复刷新。窗口状态随 NPC 正式存档保存。

## 三、闭关与结识拜帖

NPC 月度修行行动显示为“闭关修行”，持续到下一次月结；在场人物名单同步标明“闭关中”。闭关中仍可查看人物资料，普通交谈、交易、求购和切磋不可用；交互菜单只提供“留下结识拜帖”。菜单随人物所在位置和活动状态刷新；目标已离开时显示不可交互状态，若点击前刚好失去接触资格，则给出离开地点、正在旅途等原因，不再静默关闭菜单。

拜帖保存唯一 ID、收到时刻与处理状态。NPC 出关后的月结按既有交际接受规则处理一次。接受后开启五年窗口，但不自动交换姓名、增加关系、保证回信或来访；拒绝与不回应均不形成怨结。拜帖、闭关区间、处理游标和窗口状态均随 NPC 存档保存。直接打开人物详情或交易／切磋入口时也执行闭关校验，避免绕过菜单限制。

当前实现的是结构化的“结识拜帖”，不是自由输入内容的留言，也不提供其他泛用留言类型；玩家可明确表达想结识，对方仍按月结规则决定是否接受。

每月主动来访按百川声望限制为 1、2、3 人；同一 NPC 当月至多处理一次。玩家闭关期间未能会面的来访可以留信，窗口从信件实际投递时开始。

## 四、宗门宴席

### 场地与安排

在和光峰既有场景加入“同门雅集堂”和“临水水榭”，不创建新人口子场景。玩家与 NPC 均可主持。玩家选择来宾、场地与举办日期；界面不提供具体钟点选择，内部仍以精确游戏小时排期。NPC 主持的邀请通过现有信件系统送达，每三个月最多生成一次。

| 场地 | 原型费用 | 席位上限（含主持） |
| --- | ---: | ---: |
| 同门雅集堂 | 5 点贡献 | 12 人 |
| 临水水榭 | 2 枚灵石 | 6 人 |

费用仅在宴席开始时结算。无法承担费用或没有合格宾客时不扣费、不推进时间。NPC 邀约应答截止日期当天均可应答，并在所示举办日期全天有效；跨过该日仍未赴约则结束。赴约时仍须处于和光峰。宴席开始后推进四个游戏时辰。

多场宴席可以同时处于待办状态，场地不再被全宗唯一的待办事件锁住。玩家不能同时打开多个席间流程；自己主持的重叠待办场次会被拒绝，NPC 邀约在举办日期结束后标记过期。若 NPC 主持者已离开和光峰，尝试赴约时会说明原因，并将该邀约结为未能成行。

### 席间表现

- 使用 `textures/ui/banquet/banquet_outside_window_v2.png` 作为统一活动背景：镜头在窗外朝室内看，木格窗和半透明窗纸占据主体；窗后的室内用低对比虚影表现，不能辨认人物、桌席、食物、陈设或房间布局。采用柔和哑光的中性环境光，不呈现太阳、月亮、天空、雨雪、季节或具体时辰，不使用强泛光。席间不需宴席或人物素材；活动标题显示主持者与宾客人数。闲谈气泡只显示对白、不显示发言姓名，少数直接问玩家的气泡显示提问者；发言者 ID 仍保存在段落中以便稳定恢复。气泡散布在窗口中部的上下左右区域，保留明显的左右和上下安全边距，避免贴近屏幕边缘；同一人物随对白轮换位置，最近数句保留并渐隐，营造多人在室内不同位置交谈的感觉。气泡宽高按对白长度自适应，短句紧凑、长句换行，并限制最大尺寸以免遮住窗口；回应选项集中在窗口下沿，不挡住气泡分布区。
- 闲谈根据发言者对听者的单向关系记事及双方已设定的性情选取：怨结较深时保持戒备，熟识者可有亲近话题，信任或敬重较高时自然请教或称赞，关系互相熟悉且性情合适时才出现轻微打趣；陌生或性情内敛者以客气、低压力的日常话题为主。对白不得编造具体共同经历；过场对白不计作角色交往、关系或印象证据。
- 活动推进四个游戏时辰。每场从多人闲谈库中按活动 ID 稳定选出 5–8 组双句对话，通常形成 10–16 个交替发言气泡；宾客较少时减少相同人物的连续接话，若只有一位 NPC 来宾则每组只播一句，不让同一人自问自答。话题覆盖功课、差事、行路、交友、切磋与日常小事，不附带奖励或改变角色属性。过场对白不计作角色交往、关系或印象证据。
- 声望与宾客人数决定 1–3 次直接向玩家发问的短互动：基础一问，宾客不少于三人时增加一问，声望达到 200 时再增加一问。互动穿插在闲谈中，其他时间只播放气泡与安静间隔。NPC 只使用自己已认知的玩家姓名或身份称呼；真传专属问题只由确知该身份的来宾提出。
- 每次玩家回应限时 12 秒。每题提供四种措辞，其中常规选项始终可用；条件选项可按现有魅力、交际、悟性、治事、灵慧阈值或席面人数解锁，例如“邀每位同门分享”要求至少三位 NPC 来宾。锁定项显示具体门槛及当前值／人数。条件只决定可选措辞，不增加或削减属性、道具或奖励；超时从当前可选项中按活动和段落稳定 ID 选择，并保存结果。
- 只有直接互动的回应才记给实际听到的 NPC。关系与印象只记录真实在席听众；普通过场对白不记录，重复回应不会重复登记。
- 提前离席保留已有回应与行动记录；宴席一经开始，已结算的场地费用与四个时辰均不返还，后续段落停止。

## 五、存档

正式存档由 v8 升至 v9。v8→v9 只初始化空宴席活动表；既有信件、关系、NPC、东林地与动态副本状态保持原样。宴席活动记录主持者、场地、时间、名单、费用／时间结算标记、段落、选项、实际听众、回应和完成状态。NPC 快照保存闭关、拜帖、印象、结识窗口和每月来访记录；场景进度保存来访去重月份与 NPC ID 集合。

载入正在进行的宴席时，从已保存的段落和回应继续，不重新收费、不重新推进时间、不重复写入关系或印象记录。已作出的超时选择按回应记录恢复。

## 六、验收范围

- 验证印象只展示可观察事实，关系面板不泄漏 NPC 关系数值；宴席后只有实际听众获得行为记录。
- 验证合格问候信在投递时开窗，读信与拜帖本身不改关系；窗口内互动额外增加 1，重复投递和回调不重复结算，NPC 来访月度去重与状态可存读。
- 验证闭关期间所有直接交谈／交易／求购／切磋入口均受限，拜帖只处理一次，接受、拒绝、到期和存读档状态一致。
- 验证交互菜单真实按钮点击能进入对话；目标离开后显示不可交互原因，闭关状态在名单与菜单中一致，拜帖出关后只处理一次。验证邀约按日期显示并在整日有效、多场待办不互相全局封锁、同一玩家主持重叠排期受限、主持者缺席有说明、宴席费用／时长、多人双句气泡数量及保存恢复、闲谈隐藏姓名且按关系／性情选取、画面边缘安全区、玩家直问频率、姓名／身份称呼、属性条件解锁、12 秒超时稳定选择、实际听众、提前离席和 v8→v9 迁移。
- 按项目既定约定进行 .NET 构建、静态检查和自动化场景检查；不安排人工试玩。

## 七、原型边界

此处的宴席费用、人数、间隔和对话节奏为可调原型参数。当前 NPC 主持宴席以水榭、灵石费用及每三个月至多一封邀请为首轮实现。首期不新增人物、关系维度、专用奖励、制作规则或外景副本，也不将宴席作为修炼进度前置。
