# 法宝系统实装规格（云息—玄基，首批双剑）

> 2026-10-16 用户修订：战斗参与方式改为**内炼提供化法；外祭提供占一个技能栏位的临时技能，须排入行动队列，首次使用召唤、后续使用发挥效果**。外祭已确定在场占灵识，崩解或离场释放，内炼灵识另定。已认可的配套及待决项见[制作闭环设计第七节](炼器制作闭环与战斗接入设计_20261016.md#七内炼化法与外祭御使本轮修订)。本篇旧装备常驻计入外祭灵识、“命中/受伤自动响应”、手牌/六角格与相应事件映射不再作为实施依据；具体费用效果与器体目标等仍待定案。

> 本文是《法宝与炼器系统初步规划》的开发落地版。前者说明设计取舍；本文只规定数据、运行时边界、开发顺序和验收条件。

## 1. 本期边界与不变量

本期只实现云息—玄基材料、`鸣锋剑`与`守锋剑`两种器形，以及内炼、外祭两种祭炼法。钟、印、镜、旗、鼎、傀等只预留数据结构，不在首批代码中出现。

以下规则不得由实现过程改写：

| 规则 | 实装口径 |
| --- | --- |
| 槽位与灵识 | 装备时同时校验法宝槽位与**灵识**；所有已装备法宝都计入灵识，不随是否外祭、是否崩解而临时释放。 |
| 灵识 | 仅是局外绑定容量。它不是卡牌费用，也不会在回合开始回复。外祭的`御·`牌灵识费用固定为 0。 |
| 一器一功 | 每个法宝只记录一个`主功用 ID`及其品级；体材、质材、和材均不得写入第二个战斗触发。 |
| 内炼 | 不生成场上单位；改写一张基础牌的结算；每场战斗稳定损耗 2 耐久。 |
| 外祭 | 向基础技能库加入一张`御·法宝名`；打出后才占格、生成器体；它不行动、无独立技能库。器体崩解后，本场不可再祭。 |
| 外祭损耗 | 未祭出 0；祭出且器体未受损 1；约损半数 3；器体崩解 5。 |
| 铭文 | 可为空；仅调整既有数值（耐久、器体、灵识、祭出费用等），不得添加主功用或触发器。 |

## 2. 数据模型

### 2.1 材料定义：静态资源

保留 `ItemData` 作为世界物品定义；材料使用 `MaterialCraftData : Resource`，由 `ItemData.craft_data` 引用。不能只靠现有字符串词缀，因为同一种材料可带多个共用功用，且每个功用有不同完整品级。

```csharp
public partial class MaterialUtilityGrade : Resource
{
    [Export] public string utility_id = ""; // 固、聚、通、化、引、破、护、镇、生、明、藏、行
    [Export(PropertyHint.Range, "1,9,1")] public int grade = 1; // 九品=1，一品=9
}

public partial class MaterialCraftData : Resource
{
    [Export] public string element = "";     // 金木水火土
    [Export(PropertyHint.Range, "-3,3,1")] public int polarity; // 至阴…至阳
    [Export] public string texture = "";     // 纤维、致密、颗粒、黏胶、液体、气体
    [Export] public string legacy_texture = ""; // 旧材类筛选/测试兼容，不作为百科分类
    [Export] public Array<MaterialUtilityGrade> utilities = [];
}
```

`ItemAffixCatalog` 同步把相性扩为`至阴、阴、偏阴、和、偏阳、阳、至阳`。功用词汇统一采用基础功用表中的`固、聚、通、化、引、破、护、镇、生、明、藏、行`，供炼丹、制符、炼器、阵法共用。功用等级为九品至一品，不分下、中、上。材料品阶由材评计算，不转换成“凡、灵、玄、宝、道”等法宝品级；法宝品级独立定义。当前法宝品级字段中的名称仅作暂行值，具体分级规则待单独规划，不得依赖材料材评或材料品阶。

### 2.2 器形定义：静态资源

新增 `ArtifactFormData : Resource`。它描述“如何贡献战斗”，不决定法宝这次炼出的主功用。

| 字段 | 用途 |
| --- | --- |
| `form_id`、名称、图标 | 稳定标识与显示。 |
| `allowed_material_forms`、`accepted_utilities` | 配方校验；材类条件读取兼容字段 `legacy_texture`，首批剑接受金，第二材类为金/木/玉。 |
| `inner_spirit_base`、`outer_spirit_base` | 鸣锋 1/2；守锋 2/3。 |
| `outer_energy_cost`、`outer_mana_cost` | 鸣锋 1/0；守锋 2/0。 |
| `outer_body_base`、`durability_base` | 鸣锋 12/80；守锋 18/100。是基值，不是写死的成品数值。 |
| `inner_trigger_id`、`outer_trigger_id` | 内炼与外祭各自的明确触发点。 |
| `response_limit` | 首批均为每回合一次。 |

首批映射固定为：

| 器形 | 内炼绑定基础牌 | 内炼触发 | 外祭触发 | 可承接主功用 |
| --- | --- | --- | --- |
| 鸣锋剑 | 一张基础攻伐牌 | 该牌造成伤害后 | 主人本回合首次命中后 | 破障、疏通、昭明 |
| 守锋剑 | 一张基础护持牌 | 该牌结算后 | 主人本回合首次受到实际生命伤害后 | 固结、镇摄、纳藏、生发 |

### 2.3 法宝实例：持久资源，不进入普通材料堆叠背包

新增 `ArtifactInstanceData : Resource`。它代表一次炼制产物，必须有唯一 `instance_id`，不能以静态 `.tres` 路径或物品堆叠数量代替。

```csharp
public partial class ArtifactInstanceData : Resource
{
    [Export] public string instance_id = "";
    [Export] public string artifact_name = "";
    [Export] public ArtifactFormData? form;
    [Export(PropertyHint.Enum, "内炼,外祭")] public string ritual_mode = "内炼";
    [Export] public string bound_basic_card_path = ""; // 内炼必填
    [Export] public string utility_id = "";
    [Export(PropertyHint.Range, "1,9,1")] public int utility_grade;
    [Export(PropertyHint.Enum, "凡器,灵器,玄器,宝器,道器")] public string artifact_tier = "凡器";
    [Export] public string element = "";
    [Export(PropertyHint.Range, "-3,3,1")] public int polarity;
    [Export] public int spirit_cost;
    [Export] public int max_durability;
    [Export] public int current_durability;
    [Export] public int outer_body;
    [Export] public int deploy_energy_cost;
    [Export] public int deploy_mana_cost;
    [Export] public Array<ArtifactInscriptionData> inscriptions = [];
    [Export] public ArtifactRecipeRecord recipe = new();
}
```

`ArtifactRecipeRecord` 仅记录这次投入的物品定义 ID、材料岗位、燃料 ID、计算结果与时间；用于详情、修复和追溯，不能在战后重新掷词条。

在 `HumanData` 增加：

```csharp
[Export] public Array<ArtifactInstanceData> artifact_inventory = [];
[Export] public Array<string> equipped_artifact_ids = [];
```

法宝不占普通 `pack_items` 格；炼制时消耗普通材料，产物进入 `artifact_inventory`。一个角色的法宝槽数复用/新增为明确字段 `artifact_slot_count`，默认值在配置中给出，不借用功法副槽。

### 2.4 灵识迁移

`LivingData`、`BattleEntityData` 使用 `used_spirit_perception` 记录占用值；`max_spirit_perception` 即灵识容量上限。

装备、卸下、读取旧档后均调用同一个纯函数：

```text
已占灵识 = sum(所有已装备法宝.spirit_cost)
装备合法 = 已装备数 < 法宝槽数 && 已占灵识 + 新法宝灵识 <= 灵识容量
```

`SkillCard`、手牌资源栏和角色面板移除“灵识为出牌费用”的校验与文案，统一显示`灵识：已占用/容量`。

### 2.5 战斗快照与回传

在 `BattleEntityData` 增加已装备法宝的深拷贝：`Array<ArtifactInstanceData> equipped_artifacts`。`Character.get_snapshot_data()` 负责填充；`BattleTransitionManager` 的结算包新增 `ArtifactBattleReport` 数组。

报告至少含：`instance_id`、`was_deployed`、`max_body`、`remaining_body`、`collapsed`。世界场景的 `CombatTrigger` 用报告一次性扣除耐久；不要让战斗场景直接改角色持久资源，避免中途退出或重复结算。

## 3. 炼制服务与配方校验

新增纯 C# 服务 `ArtifactForgingService`，不依赖面板或场景。面板只提交选择并显示服务返回的预览。建议接口：

```csharp
ForgePreview Preview(ForgeRequest request);
ForgeResult TryForge(ForgeRequest request, HumanData owner);
```

`ForgeRequest` 必有器形、祭炼法、体材、质材、性材、和材、燃料；`inscriptions` 可为空。一个输入物品只能占一个岗位。

校验顺序固定，返回第一项失败原因及完整预览：

1. 体材质地满足器形，且可承载该器形。
2. 质材给出五行根本与阴阳；性材恰好选定一个主功用。
3. 性材主功用在器形允许列表中。
4. 五行关系为同调、养器、导用，或存在“质材→桥材→性材”的制炼通路。
5. 阴阳总值：内炼只能落在 `-1..0`；外祭只能落在 `0..1`。和材只负责调候。
6. 内炼燃料投入中至少有`疏通`；外祭至少有`凝聚 + 纳藏`；外祭若另有`固结`则获得稳定加成。
7. 计算材料材评与材料品阶、成器阶、有效主功用品级、灵识、耐久、器体和祭出费用，所有项都在预览中列式。材料材评与材料品阶不转换成法宝品级。
8. 确认后才扣材料并创建唯一法宝实例；扣除与创建必须在同一事务式方法内完成。

公式（首批）：

```text
材料材评 = 最高功用品级×2 + 次高×0.5 + 其余合计×0.25
材料品阶值 = 材料材评向上取整，限制在 1～27；无功用时为 0
材料品阶映射 = 九品下/中/上、八品下/中/上……一品下/中/上
有效主功用品级 = min(性材该功用品级, 成器阶上限, 器形上限)
耐久上限 = 器形耐久基值 × 体材承载系数 × 质材安定系数 × 合炼系数 + 铭文修正
器体 = 器形器体基值 ×（体材 70% + 其余承载 30%）× 成器阶系数
灵识 = 器形灵识基值 + 成器阶修正 + 构型修正 − 导用/铭文减免，最低为器形内炼基值
```

成器阶及其修正属于法宝自身规则，与材料品阶相互独立。法宝等级如何确定由法宝系统单独维护。质生性形成导用时可减 1 灵识；纳纹最多再减 1，但不得低于器形内炼基值。

## 4. 战斗运行时结构

新增 `ArtifactBattleController : Node`，由每个 `BattleManager` 创建且只服务该场战斗。它保存 `ArtifactRuntime` 字典；运行态与 `ArtifactInstanceData` 分离，禁止修改共享 `ActiveSkillData` 资源。

### 4.1 技能库生成

调整 `CultivationDeckBuilder.collect_cards`，使它接收可选的法宝上下文：

- 先得到基础技能库及既有功法牌。
- 对每件内炼法宝，复制其 `bound_basic_card_path` 对应的 `ActiveSkillData`，在副本写入 `artifact_runtime_id` 元数据；原始资源不修改。
- 对每件外祭法宝，运行时生成一张 `ActiveSkillData`：名称为`御·{法宝名}`，类型为辅助/部署，体力和法力取实例值，并带`artifact_deploy_id`元数据；灵识占用由器体在场状态统一维护，不作为卡牌即时费用。
- 外祭牌进入基础技能库路径，和其他基础牌一样洗入抽牌堆；它不是可装备功法牌，也不写进 `loaded_skill_paths`。

### 4.2 外祭部署与器体

`BattleManager.TryPlaySkill` 先识别 `artifact_deploy_id`：

1. 检查该法宝未部署、未崩解、当前玩家拥有相邻空六角格。
2. 扣体力/法力，从手牌移除；若无格则不扣费、不出牌。
3. 由 `ArtifactBattleController` 创建 `FabaoBattleEntity`，写入`current_body/max_body`、阵营和来源法宝 ID，注册至 `BattleMap`。
4. 该实体可被选为敌对目标；但绝不加入 `all_units`、`action_gauges`、`_decks`、`battle_units`，故无回合、无手牌、无自动行为。
5. 器体归零时调用 `Collapse`：移除占格与显示，外祭牌移入本场移除区，记录 `collapsed=true`。

先期目标规则：敌方自动战斗选择“最近可攻击敌方实体”；玩家可拖牌选中器体。这样外祭不是无敌的场上触发器。器体受伤的承伤/护盾流程沿用 `SkillExecutor` 的通用伤害流程，仅把生命字段适配为`器体`。

### 4.3 明确事件，而非散落的关键词判断

新增以下控制器入口，并在对应既有点调用：

| 事件 | 调用位置 | 首批用途 |
| --- | --- | --- |
| `OnCardResolved(owner, card)` | `BattleManager` 技能结算完成后 | 内炼守锋剑。 |
| `OnDamageDealt(owner, target, card, actualHealthDamage)` | `SkillExecutor.ApplyToTarget` 伤害结算后 | 内炼/外祭鸣锋剑。 |
| `OnOwnerActualHealthDamaged(owner, attacker, amount)` | 同上，且 `amount > 0` | 外祭守锋剑。 |
| `OnTurnStarted(owner, serial)` | `BattleManager.BeginTurn` | 清空本回合一次响应标记。 |
| `OnArtifactCollapsed(id)` | 器体归零 | 移除外祭牌、生成结算报告。 |

控制器根据“器形触发 ID + 主功用 ID”调用 `ArtifactUtilityResolver`。首批只实现下面四条可测效果；其余功用可以做成数据占位但不能出现在可炼配方中：

| 主功用 | 首批效果 | 需要的状态/字段 |
| --- | --- | --- |
| 破障 | 本次触发的伤害忽略目标一定物理防御，数值按有效品级表。 | 在 `BattleActionResolver` 增加一次性物理防御穿透参数。 |
| 疏通 | 给主人施加“气行”一层：下一张基础牌体力 -1，打出后消耗。 | 新状态或 `BattleUnit` 临时费用修正。 |
| 固结 | 给主人施加“固守”：下一次获得的护盾提高，随后消耗。 | 新状态；不直接增添第二触发。 |
| 镇摄 | 给目标施加“震慑”：其下一行动体力 -1，随后消耗。 | 新状态或行动费用修正。 |

`昭明、纳藏、生发`先保留规范 ID、材料数据与器形准入，不开放首批炼制，直到各自状态语义完成。这样不会产生“炼得出但没有效果”的法宝。

### 4.4 战后耐久

战斗结束前 `ArtifactBattleController.BuildReports()` 为每件装备外祭法宝产生一条报告；内炼不用报告，直接按固定规则结算。

`CombatTrigger.check_and_restore_battle_results()` 在角色快照回写后执行：

```text
内炼：当前耐久 -= 2
外祭未部署：-= 0
外祭已部署且剩余器体 == 最大器体：-= 1
外祭已部署且剩余器体 > 0：-= 3
外祭崩解：-= 5
耐久最小为 0；0 耐久不能装备或出战，需修复。
```

结算只发生一次。`BattleTransitionManager.consume_results()` 取走报告后立即清空；回到世界场景重复 `_Ready` 不得再次扣耐久。

## 5. UI、存档与调试

首批需要四个入口，不应先做复杂锻造动画：

1. **法宝页**：实例列表、槽位、`已占灵识/灵识容量`、装备/卸下、耐久和内炼/外祭标记。
2. **炼制页**：八个选择位（器形、祭炼法、体/质/性/和/燃料、可选铭文）及即时预览；确认按钮只在 `ForgePreview.IsValid` 时可点。
3. **战斗手牌**：外祭`御·`牌显示体力/法力，不显示灵识费用；场上器体名称、当前/最大器体、崩解提示。
4. **详情页**：材料岗位、五行、七档阴阳、主功用及有效品级、灵识、耐久、器体、公式明细和铭文。

保存测试必须覆盖旧档：没有 `artifact_inventory` 字段的 `HumanData` 可加载，自动补空数组、`used_spirit_perception=0`；已有材料和功法数据不变。

开发期加入 `ArtifactDebugPanel` 或 Godot 测试辅助：允许用固定材料一键生成四个标准样本，禁止将该入口编入正式生产菜单。

## 6. 实施顺序（每步可独立合入）

1. **数据底座**：新增四类资源、扩充词缀枚举、迁移灵识字段和存档兼容测试。
2. **炼制纯服务**：材料岗位、五行阴阳、燃料校验、公式预览、创建实例；写单元测试，不接 UI。
3. **装备与法宝页**：槽位/灵识重算、耐久为零拦截、法宝实例存取。
4. **技能库与内炼**：复制基础牌、注入运行时 ID、鸣锋/守锋的两种内炼触发及两条主功用效果。
5. **外祭实体**：生成御牌、部署格、器体受击/崩解、目标选择、鸣锋/守锋外祭触发。
6. **战后结算**：报告跨场景传递、耐久一次性扣除、修复入口。
7. **炼制 UI 与完整验收**：接服务预览、展示公式、战斗 UI；再开放首批四种可炼主功用。

## 7. 必过验收用例

| 用例 | 结果 |
| --- | --- |
| 灵识 3/3 时装备灵识 1 的剑 | 拒绝，数据与 UI 都保持 3/3。 |
| 外祭剑装备后未进战斗 | 已占灵识仍计入；不会因未祭出释放。 |
| 内炼鸣锋剑绑定基础攻伐牌 | 只该张基础牌的运行时副本带法宝效果；同名非基础功法牌不被改写。 |
| 打出外祭御牌 | 消耗体力、占一个相邻空格、产生器体；不产生行动条或技能库。 |
| 无相邻空格打外祭 | 牌和资源均不变。 |
| 器体被打至零 | 显示器体崩解，御牌本战移除，不可再次部署。 |
| 内炼一整场未打出绑定牌 | 战后仍扣 2 耐久。 |
| 外祭未打出 / 完好 / 受损 / 崩解 | 战后分别扣 0 / 1 / 3 / 5，且只扣一次。 |
| 初始与无装备角色 | 灵识已占用为 0；不会因未装备持续实体而被占用容量。 |
| 任意成品预览 | 能逐项看到体、质、性、和、燃料对耐久、器体、灵识、主功用有效品级的影响。 |
