# 鬼谷整体步态骨骼复核

2026-11-04，按用户“走路姿势、骨骼也可以看鬼谷”的补充，继续使用本次从原安装只读重读的10002人物及6段AnimationClip原始流。未再次导整包，未修改原导出、运行时、人物素材或当前动作。

来源与衣摆复核见[衣摆结构复核](鬼谷衣摆结构复核.md)。本次把已解析的动态曲线、常量曲线和原骨骼父子变换共同求值，每段取240个相位，再计算关节点相对位移；没有只比较各自坐标系中的局部角度。原始分析位于 `output/guigu_cloth_readback_20261104/`。

## 可迁移的骨链关系

| 部位 | 原层级 | 对本项目的意义 |
| --- | --- | --- |
| 上身 | `yifu → yifu → shenti1 → tou` | 衣服挂点的位移、整体旋转与胸骨倾斜共同形成前压，不能只转颈或肩部 |
| 双臂 | `shenti1 → zuobi/youbi → 同名渲染根 → 上臂1 → 前臂2 → 手3` | 肩、肘、腕独立成链，肩根在胸部局部也有小位移 |
| 双腿 | `Body/Foot → zuotui/youtui → 同名渲染根 → tui1 → tui2 → tui3` | 髋、膝、踝成链，两腿父根独立，运动并非把直腿整体前后旋转 |
| 衣摆 | `yifu/yifu → shenti2 → shenti2_1 → shenti2_2` | 基形受动作驱动，中末段另有DynamicBone，不把末端钉死在某个腿相位 |

`Foot2`支链的父节点默认不显示，当前可见腿来自`Body/Foot`。研究时排除了这套隐藏副腿，避免重复腿链干扰相位判断。

## 前进与另一段移动的区别

Run_New1时长约0.583秒，腰点到颈点的实际轴线前倾约**17.8–22.8°**；Run_New2约0.45秒，同一轴线约**后倾7.2°**。两段的躯干方向、腿回收和手臂状态明显不同，不能把名字中的1/2理解成纯粹的慢／快档。仅凭切片也不能断言原游戏状态机何时采用某段。

Run_New1左右踝最前伸的相位约0.296、0.771，间隔约0.475周期，显示交替步序；腿部有后推、屈膝回收、前送。膝屈范围约左20–109°、右8–117°，回收不能由整根直腿来回打摆代替。Run_New2的膝屈较小，约左4–65°、右10–57°。上身挂点的上下行程在Run_New1约为平均腿链长的4.9%，Run_New2约1.2%，有重心变化但没有必要把身体做成夸张弹跳。

按每段平均髋→膝→踝总长L归一化，已解析Run_New1的踝点前后行程约为1.16–1.21L，Run_New2约0.71–0.83L。当前玉虚v3在114样例同段记录中约0.79–0.81L，膝屈峰约74°；因此当前腿幅更接近第二段的范围，而躯干倾身接近第一段。源Run_New1更猛烈的回收不宜不经适配就整体复制到玉虚长袍。

## 原作双臂并不是对称跑姿

Run_New1有一侧手腕持续在肩前约0.48–0.63倍平均臂链长A，主要保持举手；另一侧才有明显大幅反摆，约-0.76A至+0.38A。二者手腕前后运动总体反向，但幅度十分不对称。Run_New2也有一侧持手，只是另一侧的摆幅更小。

**用户已明确要求双臂正常自然摆动，所以原作的单手持架不应重新覆盖当前v3。** 当前v3两侧手腕行程都约1.08–1.10A，双臂交替、屈肘与对侧腿协调，符合用户本轮要求。应学习原作的肩肘连续性和手脚配合，保留自有动作设计。

## 衣摆与动作的时序

在不求解DynamicBone、只观察原Clip基形时，Run_New1下摆骨链末点的后展最强约在0.229相位，略早于左踝最前伸的约0.296相位；上身挂点最低约0.371相位。可确认的是衣摆根部、腰身和脚步属于同一套动作节奏，而不是彼此无关的贴图。

下端实际的滞后、飘动和停步回垂还受DynamicBone及状态混合影响，这些运行时相位不能从Clip关键帧直接断言。因此本项目适合采用：明确的跑动后展基形、腰身带动、分段惯性与停步重力回落，再在实际镜头验收。

## 本轮结论

当前v3已形成可用的前倾与交替腿关系，用户要求的双臂自然摆动也应保留。本轮主要应继续修后摆持续后飘和停步回落，不因研究原作而推倒已调好的手脚动作。

原动画还会改变部分骨骼的局部位移，Run_New1单侧腿链有效长度有约4–10%的变化；它的网格和绑定与玉虚不同。迁移时应保留我们自己的比例及骨长，把时序、关节方向和归一化目标交给当前腿链求解。

## 导出绑定中的一处问题

旧解码记录中Run_New1、Run_New2有未解析路径（`path=None`，例如hash `569651382`）。旧导出器把None按空路径处理，`targetRigPath`落到`Body`；如果照着该字段原样求值，会错误地让整个角色旋转约40–60°。

本次分析明确排除这些无节点对应的曲线，并补入`rawConstantClip`中的常量位置／旋转；当前原轨道加载器主要读取有samples的轨道，也不能直接当作完整原作播放。以上统计是**已定位骨链的源曲线分析**，不声称复现了原游戏完整状态机、脚底接触或DynamicBone求解。原导出与运行时均未修改；以后若做整段动作迁移，应先修路径解析及常量轨道支持。
