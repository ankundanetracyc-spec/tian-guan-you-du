## 可以直接验证的结构

1. **完整脸底。** `Head` 是不带眉、眼、鼻、嘴的完整头脸与双耳皮肤，五官位置没有镂空。其他部件在上方覆盖。
2. **成对五官。** 示例的左右眼共用一张 `Eyes`，左右眉共用一张 `Eyebrows`；鼻、嘴各有一张独立图片。
3. **连续透明度。** 这一示例的各部件 RGB 为灰度。眼睛图包含眼球、睫毛、眼睑线及半透明眼周明暗；眼睛 2,765 个非透明像素中，354 个 Alpha 大于 240。其余过渡依靠真实 Alpha，并非不透明肤色底片。眉毛也大量使用半透明毛发笔触。
4. **固定位置。** 图片尺寸各不相同，但部件预制体为 sprite 记录相对共同角色根节点的坐标。PNG 导入中心点是 `(0.5, 0.5)`，每单位 100 像素。更换部件须遵守该定位关系，不能按透明内容边界重新居中。
5. **可微调。** `PortraitModelData` 有 `eyebrowsOffsetY`、`eyesOffsetY`、`noseOffsetY`、`mouthOffsetY`；静态、动态立绘接口均提供对应的四项纵向偏移方法。

## 对本轮修订的约束

- 用户要求眼睛不带周围皮肤：去掉不透明肤色底片、肤色残岛和鬓发，保留眼球、睫毛、眼缘细线及必要的半透明笔触；不要把清理变成生硬的眼球剪影。
- 皮肤底色、脸部整体体积和大范围眼窝肤色过渡属于脸型。五官自己的笔触和局部明暗可采用连续 Alpha，不能携带另一块皮肤去覆盖脸底。
- 本项目仍使用 1024×1536 同原点九层。独立五官的位置和比例依据本轮男女原图，既不直接套游戏示例坐标，也不重新按不透明包围盒居中。
- 前发、后发、脸型、衣服各自归属依用户要求处理。后发完整绘制隐藏区域；前发包含正视可见普通颅顶及身前发束。
- 用户最新裁定明确：脸型、双耳、五官与画风保留本项目自己的风格，指定本次双人附件为母版。官方示例的灰度配色不能成为改变五官色彩的理由；本轮坐标与导入控制架按选定图独立确定。v4/v5 修稿仅作历史记录。入口、实测与仍待修整的拆件范围见[男女立绘统一风格基准](男女立绘统一风格基准_20261003.md)。

## 2026-10-04 补充：眼形与颅顶修订的外部经验

用户指出男修眼形僵硬、高束前发过扁且两侧过宽。本轮另查以下直接来源；技术与绘画经验用于本项目自己的重绘，不导入示例素材：

- [Live2D 官方 Hiyori 插画处理教程](https://docs.live2d.com/en/cubism-editor-tutorials/psd/)：示例将睫毛、眼球和眼白分别制作，并补画遮挡部分；前／侧／后发也按运动与遮挡拆分。应用到本项目时，先保留眼白、虹膜与眼睑的完整关系，最后合并为成对眼睛这一槽；外部眼周去除不透明肤色，保留必要半透明笔触。九部位数量不变。
- [Unity 2D Animation 换件示例](https://docs.unity3d.com/Packages/com.unity.2d.animation@10.0/manual/CharacterParts.html)：换件时共同参照位置和 pivot 影响对齐。本项目继续整幅同原点导出，成对眼睛共用一次等比变换，不按可见边界重新居中。
- [CLIP STUDIO 官方网站刊载的发型绘画教程](https://www.clipstudio.net/how-to-draw/archives/159719)：先明确发际线、分区与三维发量，再绘制发束。针对本轮的判断是：上轮只追求低颅顶，侧面仍偏宽，导致横向铺开的帽状轮廓；本轮重绘较窄的圆弧体积，发际线保持较低位置，不通过非等比压缩发丝来补救。

上述来源没有规定本项目的像素数值或审美结论。现行成图和配准见锚点规范最新“眼形与圆弧发顶修订”一节，用户视觉验收仍独立于程序检查。
