## 本轮结果

- dotnet build：0警告、0错误。
- 原生Windows窗口：1280与1920分别360项通过，每档8组完整窗口＋裁切图，共32张PNG；本轮使用原生运行覆盖同套无头断言。
- [1280验收记录](验收_1280x720.json)、[1920验收记录](验收_1920x1080.json)保存最终用例、渲染器与卡片尺寸。

独立验收场景退出时有两名离树测试角色的释放告警，来自测试中使用Dispose的既有清理方式；正式悬停未创建这些角色。两档运行退出0且无ERROR；此项不作为运行零告警的声明。

本次“稳定”字段改名验收中，1280首轮停在已有Provider延迟打开断言；未修改判定，独立重跑两档各360项通过。字段仅改显示名称，稳定公式、原数值含义与实际数据均保持。

角色甲神魂10／剑道10：原始物伤9、稳定上限28；角色乙20／20：物伤15、稳定39。灵识只显示本器占用2。另有有效属性20／30及当前自身物伤＋50%的用例，预估27、稳定42；验证现行CardRules属性读取与BattleActionResolver预估，而非只核对固定样例。详细公式的系数、属性代入和倍率最多两位小数并去尾零，用“≈”连接实际结果；计算仍使用完整四位系数，未用显示缩写反算。

Provider验证重新进入时9→15、切换显示档位时读取当前修正得到14；无角色显示待选择角色，缺参数显示未记录。未调用有ensure副作用的角色快照导出，不加载／修改真实角色存档。逐器元数据保存往返不改原数值JSON；坏展示元数据不影响丹药实际资格与药效。

格图验证名称下真实行囊12格、底部仅一行战斗本体2格与范围3格、合图5格；内部范围锚点和四方向几何保持，悬停不标剑尖或剑柄。验证96×96主图标不会被高行囊图拉长、唯一“战斗占格：”标签、底部分割线及无尺寸／格数旁注。完整正文不丢段、不重复、两档公式、独立F1规则、关闭／清空、鼠标透传和非物品恢复原单列继续验收。
