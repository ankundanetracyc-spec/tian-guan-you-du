## 数据

`EntityData` 保存稳定种子、脸型、五官、眉型、妆容、前后发型、服装与胡须 ID；不保存脸宽、脸长、眼睛大小或眼位偏移。立绘由各款同画布素材按固定坐标拼接，不做单部件缩放或位移；头像显示时只适配／裁切整幅组合图。衣服不进入遗传；家族遗传只涉及既有外观款式字段。

`PortraitCatalog` 以稳定种子从素材池选择部件。每个素材可声明 `gender`、`tags`、`weight`、`min_age`、`max_age`、`realm_min`。`only_faction:<门派>` 与 `only_realm:<境界前缀>` 会形成硬限制；未限定素材可作为通用池。

## 身份、年龄与境界

- 门派/身份通过标签提高或限制服饰、饰品、眉眼素材的出现概率。
- 年龄通过 `min_age`/`max_age` 控制成熟脸、白发、胡须、皱纹素材；角色年龄由 `HumanData.current_age` 提供。
- 境界通过 `realm_min` 与 `realm_effect` 控制灵光、虚影、异象等视觉层；境界只影响可用池，不改写先天脸部。

## Godot 使用

局外人物使用 `PortraitRenderer`：调用 `show_character(character)` 即按 `EntityData.appearance_*` 组合正面半身像。开局可预览、随机或打开 `AppearanceEditor` 逐项调整；档案编辑器也提供实时预览、离散部件切换、轻量脸型调整、取消与应用。男性基础包的眉眼仍共用一组素材，女性测试包的眉与眼独立；没有可用素材的选项会从编辑器隐藏。

开局保存的玩家外观会复制到实际主角数据。`WorldNpcData` 可指定 `gender` 和 `appearance_seed`；未指定时按 NPC 身份稳定派生性别与随机部件，同一人物不会在每次对话时换脸。剧情固定人物使用各自固定身份种子。NPC 对话、主角说话与心声在底部对话栏上方显示人物半身像，旁白不显示人物像。

对话栏显示与开始界面外观测试台共用当前单套素材与图层合成器：男女分别读取各自的 `test_assets_green_reference_v1/`。这项仅供对话立绘测试，不改变全局外观素材包启用状态，也不把测试台组合写入角色或存档；测试期间所有候选编号均映射到单套 0 号素材。立绘贴在对话栏上沿，显示原图顶部约 76%，裁去下方余段，避免全身比例拉得过高；旁白仍不显示立绘。

外观参数写回当前角色的 `HumanData`；正式进度存档会随完整角色数据持久化外观。开局设定模板仍单独保存建档选项，不代替旅程进度存档。
