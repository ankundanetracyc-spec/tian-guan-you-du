# 全项悬停补查与覆盖边界

2026-11-09，用户追问“所有的信息悬停栏，都看了吗”。上一轮1784项主要验证20招、20化法、人物属性及少数物品样本，不能等同全部正式页面均已现场查看。本轮补查正式入口与自建浮层，修补实际遗漏，并明确区分入口审查、内容样本与实际控件验证。

## 补查发现与修补

| 问题 | 修补 |
| --- | --- |
| 正式炼丹使用独立 `AlchemyHerbHoverCard`，直接显示原文，未经过共用格式器 | 保留原卡片美术及所有来源控件，统一调用Display与长段排版；来源、档位、视口或锚点变化时刷新，按实际字形测量换行高度并扩宽避边。药材／本炉灵识明细使用原SpiritLoads的结果与来源，不再裸写取整实现说明 |
| 林地狼事件按生成时的模式拼提示，详细来源混在一整段括号里 | Hint始终保留完整详细源，人物评分、凶狼评分和成功率分项显示；共用阅读器控制两档。保留Chance、Resolve、观察修正、费用与原百分比取整，不进行新的判定 |
| 正式穿戴页仍写“主动施法另需临时占用” | 改为已经确认的御使持续占用、跨回合保持、收回或停用释放；技能体力／法力另算，不修改实际资源或支付逻辑 |
| 穿戴说明挂在MouseFilter.Ignore的文字上，发信号能显示而真实指针无法命中 | CharacterHover仅将原Ignore来源改为Pass，保留其他已有策略；实际指针已核对，不以手工发信号代称入口可用 |
| 材料旧来源把“向上取整并限定小阶”混入等号前的结果 | 显示为“材评：实际分数 = 原加权式”，保留材评、品阶及全部权重；只移除玩家计算区中的底层旁注 |
| 正式炼器逐材预算仍用裸倍率／取整旁注，两个文字来源也未启用鼠标接收 | 改为原Total与四项负担／倍率的末尾计算来源，两个独立用度标签设Pass；保留SpiritLoads与SpiritDemand。该项为最后的源码补修及完整编译确认，未计入下述820项实际入口证据 |

## 正式入口审查

[入口清点JSON](入口审查.json)记录70个匹配文件、150处共用API或原生Tooltip写入点。这个数字是源码出现次数，不是150个已经现场操作过的页面。共用管理器已在project.godot注册为Autoload；它收编原生TooltipText，再由PlayerInfoText处理计算来源及长段排版。

| 类别 | 已核实的正式显示通路 |
| --- | --- |
| 招式盘、来源清册、组合与方案 | BattleBoardView／BattleBoardHud → CombatBoardPresentation → 共用悬停 |
| 技能栏、行动队列、战备丹药 | CombatSkillBar／BattlePlanHud／BattleSupplyHud → 共用悬停 |
| 战斗人物、状态、资源 | BattleUnitOverlay的真实徽标／资源读数 → 共用悬停 |
| 人物属性、心境、装备、技能库、秘籍、卷章与化法 | CharacterAttributePresentation／InfoPanel及其分部 → 共用悬停；当前穿戴页旧灵识文字另行修正 |
| 凝核手牌、长按、起手牌与状态 | CondensationCardGamePanel的对应分部 → 共用悬停；不因格式修改重做凝核玩法 |
| 行囊、交易、坊市、兑换、领取及穿戴选择 | 实际入口使用共用物品生成器、Provider或SetInfo；数据样本通过不代称每处业务入口都已逐项实操 |
| 修炼节点、灵感记录、普通按钮说明 | 原生TooltipText由共用管理器自动收编；没有公式的短提示不增加计算区 |
| 符工、阵法、炼器及林地采集／事件 | 共用入口；林地Hint内容来源另作修补，不能仅凭最终走共用管理器就认定原数据格式必然正确 |
| 正式炼丹材料、药位、灵识明细 | 独立浮层，已补接相同格式与动态刷新；没有把带Preview的类误判为未实装样稿 |

## 独立短提示与排除项

- 正式玉虚公事吊牌的 `HoverPreview`：任务标题独立，境界／贡献／地点为短摘要，正文已有自动折行；当前没有计算式或长效果字段，不强行加空行。
- 旧地图 `WorldMapViewport` 的地点提示：只显示“地点：名称”。远城导航hint同样是短导航文字，不虚构计算区。
- 未使用的 `BattleBoardTooltip` 类、一直隐藏的旧AttributeTooltip节点不是正式漏口。当前人物点击阅读区也不冒充鼠标悬停。
- “按钮hover颜色”“灵舟悬停停航”不是信息栏验收。网页隔离样稿、历史截图与旧静态卡图不计为本轮正式游戏已经通过；它们若被重新采用，仍须遵循现行展示规范。

## 原生验证的口径

本轮新增证据按实际来源标明“内容样本”或“实际控件”。内容样本使用正式生成器及真实资源；实际控件测试触发其生产显示入口，不手工拼接一个假标签冒充页面覆盖。测试只使用隔离角色和内存夹具，不执行成交、服药、开炼、林地判定或真实存档操作。

### 本轮结果

- 最终完整构建0警告、0错误；包括最后的炼器预算源码修补。
- [1280记录](1280x720/verification.json)与[1920记录](1920x1080/verification.json)各410项通过、0失败。各50张悬停样本全部完整落屏，另有2张普通资料页证据，共204张PNG。
- 每个窗口的50张悬停分为：15组分类内容生成器样本×简略／详细＝30张，10个正式来源情境×两档＝20张。两个阵法落点共用同一Canvas，不能称为10个不同控件或10个业务页面。
- 物品样本覆盖材料、衣着、储物袋、秘籍、普通剑器、清和商品、突破丹、符纸／墨／笔、成符、行旅字段等。储物袋使用既有隔离定义、行旅为真实接引舟参数组合，均已在JSON中说明，不冒充玩家实际持有物。
- 实际来源包括状态徽标、人物属性行、穿戴说明、阵法Canvas、林地事件按钮，以及正式炼丹君药和本炉灵识控件。炼丹八味详细卡在1280为约559×596，31行全部可见；简略缩回约252×210，再切详细可恢复，逻辑字号仍为17，九项来源未删减。
