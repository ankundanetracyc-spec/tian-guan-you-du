## 建议先试这三件事

1. 选“无盾、供能足”，点轻击：立刻补防，实际补成且预算等条件都通过，才继续攻击。第一击就补，不等计数凑满。
2. 选“无盾、暂缺能”，点轻击：P变1、零费用。再点“新的供能机会”：只补防、P归0，不补发旧攻击，受击次数也不增加。
3. 选“已有盾、连续受袭”，依次点轻击达到演示阈值，再换窗点轻击：上一密集窗仍挡住本次攻击。一个完整低压窗结束后，后续新受击才可重新判断攻击。

轻击／重击是图谱门槛比较结果。次数阈值可改为2、3、4，仅用于看清策略，不是正式平衡值。`C护／C攻`是费用符号，本演示不猜攻击伤害、阵源成器参数或输出次数。

展开执行条件可指定该次预算、资格、共享峰值、提交是否成功。它们是情境给定结果；调整控件本身不触发阵法，也不代表游戏内可以刷新次数。换窗只封存统计报告，不自动回能或刷新执行资格。

展开边界可重复通知、停用重启或将外部盾值设为空。重复通知不重复计数；停用取消P，保留统计历史并标记缺口；外界真实补盾只清P，不触发攻击。观察不可信时，防护支路继续，攻击支路停止。

## 验证范围

已在1920与1280两档窗口点验，均无横向溢出，四张整页图已目视核对，浏览器无错误或警告。核对内容包括有盾直接转攻、无盾先补防、缺能记需与恢复只补防、重击不拦护持，以及“密集窗→下一窗首击停攻→完整低压窗结束后恢复”的三窗流程。

停用边界也已点验：真实新受击仍改变人物外部盾值，阵盘不观测、不记需、不输出；重启后的机会不补旧事；重复旧通知不能把人物盾值回滚或重复计数／扣费。演示使用的临时查看服务与浏览器均已关闭。

验证范围为独立页面及策划契约；未运行或修改战斗运行时，旧4×4连通验算不作新逻辑已经接入的证据。
