# 地图美术与区域蒙版制作规范

> 现行裁定（2026-09-23）：5×5 只表示资源分块；世界空间按大陆—区域—势力辖域—地点组织，当前只制作百川区域。旧九州节点命名、底稿和蒙版只保留兼容说明，新地图资源独立接入，不覆盖旧蒙版。

## 目标

旧稿曾要求以 [世界地图九域功能底稿.drawio](世界地图九域功能底稿.drawio) 为唯一布局母版；当前大陆与百川布局以现行策划案和运行时节点数据为准，draw.io 只作历史参考。地图工具负责山海、道路与节点的精修，游戏内底图负责真实地形，区域几何只作为交互命中与高亮层。**不以运行时几何线条替代地貌底图。**

## 四层输出

| 层 | 文件／格式 | 用途 | 是否对玩家可见 |
|---|---|---|
| A. 地形底图 | `zhaoming_vast_nine_states_runtime_8000_native.png`（或同坐标 5×5 高清切片，旧文件名兼容） | 山脉、河流、海岸、道路、云雾、地名底纹 | 是 |
| B. 区域编号蒙版 | `territory_masks_vast_nine_states_5x5_8000/zhaoming_territory_id_r00~r44.png`（旧目录兼容） | 纯色 ID，与当前区域和地形底图严格对应 | 否 |
| C. 高亮边缘蒙版 | 由同一套 5×5 ID 蒙版派生 | 仅保留当前区域的真实边缘，用于悬停描边 | 否 |
| D. 节点层 | Godot `WorldNodeData` | L1–L4 节点、标签、图标、道路与事件 | 是 |

## 当前大陆与百川高清底图（5×5）

- 游戏逻辑坐标为 `8000 × 8000`，每格对应 `1600 × 1600` 世界坐标；运行时 ID 蒙版当前按每格 `1600 × 1600` 输出。
- 可编辑交换母版为 `8000 × 8000` 视口的 SVG；其中 `2400 × 1800` 源稿以 `scale=3、offset=(400,1300)` 放入逻辑画布。
- 若后续拆分地形美术，建议每格导出 **2048 × 2048**，并保留 64px 出血区；源稿、切片、蒙版和节点必须先使用同一套逻辑坐标，再分别导出，禁止把小尺寸总图放大后切片。
- 相邻两格保留 64 px 出血区：山脉、河流、道路必须跨格连续，再裁出正式区域，不能各自独立生成。
- 当前完整运行时底图采用原生高分辨率确定性绘制，`runtime_v1` 与旧蒙版保留为回退资料。

## 历史 4×4 高清底图（兼容资料）

- 旧稿的游戏逻辑坐标为 `6400 × 6400`，每格对应 `1600 × 1600` 世界坐标。
- 旧稿美术导出每格 **2048 × 2048**，整体视觉分辨率为 `8192 × 8192`；这套数字不适用于当前大陆运行时资源。
- `tiles_16regions`、旧 `world_terrain_r00~r33` 与旧节点命名只用于历史位置验证，不得作为当前大陆与百川的坐标来源。

## 当前区域编号（首期）

| 色值（仅蒙版） | 区域 | 主地形／视觉重点 |
|---|---|---|
| `#6D913E` | 百川区域 | 河湖、山口、古道、荒域与近海 |

青溪湖、白石镇、东林地等是百川区域内的地点或地理区域，不另立大陆或州级层。旧色表和旧蒙版文件名仅用于迁移时定位。

## 悬停表现

1. 将鼠标映射到蒙版像素，读取纯色 ID，得到当前区域；无需以 UI 方框判定。
2. 用对应区域的边缘蒙版绘制金色半透明光边，同时复制该区域遮罩内的地形，围绕区域中心放大 `1.02–1.04`。
3. 镜头向区域中心平移不超过屏幕宽度的 2%，禁止突然跳镜头。
4. 浮出简短信息：区域名、主宰势力、已发现地点数、当前异象数。
5. 高倍率下仅保留悬停的边缘特效，L2/L3 节点始终在其上方。

## draw.io 工作顺序

1. 在大陆与百川总览中先确认不规则自然边界，边界必须沿山脉、河流、海峡或荒漠过渡走。
2. 在当前 5×5 逻辑底稿中调整山海与道路，确保节点落在合理的地形留白。
3. 导出当前区域蒙版，再以同一自然边界绘制底图；蒙版和底图绝不分别设计。
4. 最后从 draw.io 节点清单同步 L1–L3 到 `WorldNodeData`，L4 只保留模板与刷新条件。
