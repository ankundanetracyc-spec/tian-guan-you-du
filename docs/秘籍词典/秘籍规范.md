# 秘籍规范（草案，待补充）

> 本文同时遵循已确认的三资源战斗设计；实现尚未迁移的旧字段必须标为迁移中，不得继续作为新卡规范。
> 若本文与秘籍图谱冲突，以该秘籍的 .drawio 图谱为准；若图谱与运行时不一致，应明确提出按图同步资源。

> 2026-10-25 字段统一：技能与心法图稿、文字稿不再设置“类型”字段，不标注攻伐、守御、术诀等分类。伤害类型直接在效果中表述，不再单列“伤害类型”字段；保留近身／远程出手方式和应对关键词；移除分类不改变费用、目标、触发条件或效果。此次已同步已确认五本及玉髓、抱虚、敛锋三本提案，其他旧稿仍待迁移。

> 2026-10-26：没有独有机制的普通招式优先放入公共造诣图谱，秘籍可精确指定这些技能给予化法。静态公式只写技能基础公式与本技能专属修正，不额外展开通用物理伤害加成倍率。

## 1. 文件与职责

每本秘籍固定使用同名的三份内容：

| 文件 | 职责 | 是否为设计主依据 |
| --- | --- | --- |
| docs/秘籍词典/drawio/<秘籍名>.drawio | 总览、卷章主链、修持、化法、习得、状态与数值关系 | 是 |
| docs/秘籍词典/md/<秘籍名>.md | 对图谱的文字展开：逐卷、逐牌、联动与边界 | 否，辅助说明 |
| resources/gongfa/<秘籍名>.tres | Godot 运行时功法资源与卡牌引用 | 否，实现结果 |

流程应为：先改图谱 → 确认图谱 → 同步文字稿和 .tres → 校验引用与字段。不得反过来根据 .tres 臆造设计。

## 2. 图谱的固定结构

图谱沿用 _秘籍模板.drawio 的结构：自上而下为卷章主链；每卷向两侧或下方连接本卷的效果。

每本图至少包含：

- 秘籍总览：名称、五行、定位、主修/辅修、适用境界或可修至的境界。
- 卷章主链：卷章名、稳定的英文 ID、顺序、定位、条件。
- 每卷的 修持、化法、习得。
- 若秘籍使用状态、姿态、层数、技能库替换或跨卷联动，必须在图中画出来源、上限、消耗/移除和结束条件。

图中统一：矩形表示实体，箭头表示关系，注释框表示数值、条件与规则。图中文字足以直接作为描述时，只做语句润色，不改变原意。

## 3. 秘籍总览必须说明的事

- 五行兼容性：用于学习、卷章参悟与主修资格校验；灵根权重仅用于主修修炼匹配：
  - NONE：无灵根要求。
  - ALL：通用功法；有灵根即可，不挑五行。
  - 其余值：只读取灵根类型中明确拥有的有效属性；权重数组中的散余亲和无效，不参与判定或效率。
  - 多属性功法必须标注 `OR` 或 `AND`：OR 具备任一要求属性即可，AND 必须具备全部要求属性。
  - `OR` 的原始匹配权重取所有有效匹配属性中的最高值；`AND` 取全部要求属性的有效权重平均值；通用功法固定为 100%。
- 槽位：可主修、可辅修或仅研读。
- 主修的起止境界；仅辅修秘籍不写可修至某境界。
- 核心战斗循环或日常修炼方向。

剧情来源不属于功法本体规范。例如某本秘籍由玄镜传下，应写在剧情节点、事件或引导中，不写进功法的学习条件、卷章条件和通常简介。

## 4. 卷章的固定信息

### 卷章框的分行与空行

卷章名、卷章ID、顺序、定位、研读值、学成可修至的境界，以及学习条件下的灵根、境界、前置、研读属性，均须各自另起一行；不得把多个字段用空格连成一段，再依赖文本框自动折行。定位、学习条件、学会永久属性三个信息组前各留一行空行；卷章框含习得字段时，其前也留一行空行。采用左对齐、顶部对齐和一致的内边距。文字超出时增加框高并下移后续卷章，保留卷间间距，不缩小字号挤入原框。此要求适用于现行图谱、待审提案和模板。

每一卷至少写：

1. 卷章名与 chapter_id：ID 只使用稳定的英文小写下划线形式；资源、前置条件与卡牌引用均以它为准。
2. 顺序与一句话定位：说明本卷解决什么问题，不用剧情代替机制。
3. 研读值：required_study_progress。它是累计研读进度门槛，不是体力，不会在解锁时扣除。
4. 学习条件：灵根条件、前置卷章、境界、基础属性或对应造诣门槛、是否仅主修可学。
5. 学会即得：基础属性或对应造诣的永久固定加成或永久倍率加成。
6. 修持：装备后生效的固定/倍率加成；主修额外效果需单列。
7. 化法：只写“适用范围”和“化法追加”。适用范围直接列出目标技能名；多个目标以顿号列名。不写“仅可绑定已装配”等资格解释句，也不重复目标技能的类型、关键词、费用、目标、伤害类型、次数、冷却或原效果。关键词范围只有在匹配配置和运行时确实支持时才能使用。追加效果另起一行，只写本卷新增或改变的内容，必要时另列追加公式。目标技能原有次数和冷却沿用技能自身配置；追加效果自身的触发次数限制写入追加效果。主修额外效果只列在心法，不列入化法。
8. 习得：本卷新增的主动技能按名称列出，不写卡牌复制数量；秘籍心法由主修/辅修槽位自动提供，不进入习得列表。

化法不得写在习得、修持框或招式原始效果中。习得框只展示本卷技能、心法版本与大世界术法；不复述“本卷化法改写某技能”等说明。应对空放、通用支付与无合法目标处理集中引用战斗总案，不逐框复述。完整字段顺序与示例以[现行秘籍技能与费用规范·四、化法](../plans/云息现行秘籍战斗技能与费用规范.md#四化法)为准，适用于八本现行图谱和七本待审提案。

### 心法版本固定写法（2026-10-19）

- 首卷完整写心法被动名称、类型、关键词、效果和主修额外效果。
- 后续心法的效果、主修额外效果或关键词有变化时，完整写该卷版本，包含仍然保留的规则。
- 心法没有变化时，仅写“心法被动：心法名（沿用第X卷，无新增效果）”。X引用最近一次完整书写心法的卷章，不串联引用其他沿用卷；不重复类型、关键词、效果和主修额外效果。
- 沿用行与本卷习得之间留一空行；新技能继续完整写自身字段。只有修持、化法或习得变化时，心法仍按未变化处理。
- 例如首卷完整、第三卷升级：第二卷写“沿用第一卷”，第四卷写“沿用第三卷”。
- 图谱与文字稿可用沿用行；运行时配置和游戏内心法详情仍提供当前已学的完整版本。

### 4.1 条件的语义

- 研读值：角色执行研读日程时，按学习效率累计；与体力的关系仅是研读日程可能消耗体力，不是卷章条件本身。
- 灵根条件：开始学习与继续参悟前均校验；只读取有效灵根类型和 OR/AND 条件，不读取灵根权重。
- 卷章境界：首卷为凡人及以上；第二卷须云息三层；第三卷须云息六层；第四卷须云息九层。后续卷章继续按每卷递增三层配置。
- 构筑主题：可记录秘籍围绕哪些公共状态、资源或战斗属性构筑；不得将构筑主题用作未配置的准入条件。
- 研读属性：每一卷必须配置与该卷主题相符的基础属性与造诣门槛，并随卷章递进；该条件只校验，不会扣除属性。
- required_attributes：只作数值门槛，不会扣除属性。新秘籍可使用体魄、灵慧、神魂三项基础属性、派生值身心协调值，以及对应的武学／术法造诣；不以生命、体力、心境、法力、回复速度等资源或战斗面板属性作为学习门槛。
- required_chapter_ids：必须已学会的前置卷章 ID。
- required_realm：当前代码按境界名称精确匹配；写入前必须确认是否希望未来改为达到该境界及以上。
- requires_main_slot：仅主修槽位可学习。

## 5. 秘籍允许使用的属性

所有资源键仍须存在于 `csharp/gongfa/AttrKeySets.cs`；未登记字段会被过滤，不能写入资源。除该技术限制外，新秘籍按以下分类使用属性。

### 5.1 学习条件与学会永久加成

可使用三项基础属性、身心协调值与对应造诣：

- physique 体魄、intelligence 灵慧、soul 神魂、coordination 身心协调值（派生值，不存档、不成长）。
- sword_proficiency 剑道造诣、blade_proficiency 刀道造诣、spear_proficiency 枪道造诣、body_proficiency 体道造诣、magic_proficiency 术法造诣。

不将以下属性作为新秘籍的学习门槛或学会后的永久属性加成：

- fortune 机缘、comprehension 悟性、charisma 魅力。
- spirit_strands 灵力（缕）、core_count 灵核数。
- 生命、体力、心境、法力、灵识及其上限或回复速度。

### 5.2 修持属性

修持只从战斗与生存属性或成长与专长属性中选择；不直接提供上述三项基础属性，也不提供机缘、悟性、魅力与灵力体系属性。

常用战斗与生存属性：

- max_health 生命上限、max_stamina 体力上限、max_mind 心境上限、max_mana 法力上限。
- physical_defense 物理防御、precision 精准、dodge 闪避、critical 暴击、crit_resist 抗暴、initiative_speed 行动速度。
- health_regen_rate 生命回复、stamina_regen_rate 体力回复、mind_regen_rate 心境回复、mana_regen_rate 法力回复。

常用成长与专长属性：

- learning_rate 学习速率、cultivation_rate 修炼速率。
- sword_proficiency 剑道造诣、blade_proficiency 刀道造诣、spear_proficiency 枪道造诣、body_proficiency 体道造诣、magic_proficiency 术法造诣。

物理防御只可由护具、功法、锻体成果或状态等明确来源提供，基础属性不自动换算物理防御。不存在神魂防御或法术防御；神魂伤害必须写明攻击方与受击方神魂如何参与该招式的计算。凡人法力与灵识为 0，涉及法力、灵识的修持或卡牌效果须标注云息后才有实际作用。

## 6. 数值层级不得混写

| 层级 | 含义 | 资源字段 |
| --- | --- | --- |
| 学会永久加成 | 学会后永久保留，不依赖是否装备 | learn_permanent_bonuses / learn_permanent_multipliers |
| 装备被动 | 作为辅修装备时生效，卸下即失效 | passive_bonuses / passive_multipliers |
| 修持 | 仅在当前秘籍条目明确配置时生效；不按角色路径启用 | naqi_* / main_naqi_* |
| 化法 | 改写公共基础技能、公共造诣图谱技能，或改写/加入本秘籍授予的技能 | GongfaDeckRewriteConfig |
| 习得 | 学会卷章后授予或解锁的主动技能 | learned_active_skills / main_learned_active_skills |

倍率字段以小数存储：0.10 表示 +10%。固定加成按实际数值写入。不得把获得卡牌技能库加入永久属性写成同一类收益。

### 6.1 化法的强制规则

每条化法配置必须明确目标范围：公共基础技能池中的指定技能、公共造诣图谱授予的技能，或这本秘籍授予的主动技能。不得改写其他秘籍授予的技能或战斗中临时生成的技能。追加效果保留目标技能的基础效果；运行时只改写本角色的技能数据，不修改共享技能资源。图谱与文字稿只显示适用范围和化法追加；适用范围直接写技能名，不附加绑定资格句。技能资源仍保存运行时所需的目标、加入／替换方式和完整效果字段。图谱技能先按个人节点条件参悟，秘籍不会因提供化法而自动授予该技能。

- **加入**：将结果技能加入指定范围；即时战斗中按一个可装配技能显示，不写 `×1` 或卡牌复制数量。
- **替换**：将指定范围内匹配的技能改为结果技能；写明原技能名与结果技能名。若目标是本秘籍授予的技能，只能匹配同一本秘籍的授予技能。
- **习得**记录学会卷章后新增或解锁的技能。它可以成为同一本秘籍化法的目标；化法结果作为该技能的当前版本显示，不重复列出原版与改写版。
- 图谱与文字稿按实际匹配配置展示适用范围和追加效果；范围直接写技能名，或在实际匹配支持时写关键词范围。`.tres` 保留运行时所需的目标范围、加入／替换方式和结果技能数据。心法不列为化法目标，仍由主修／辅修秘籍槽位自动提供。

公共技能池目标以 `docs/基础牌库词典/` 为准：

- 公共基础技能池：应敌、架招、痛击。
- 剑修：斩剑、点锋、养锋、敛息观剑、基础步法、格剑、藏锋。

## 7. 卡牌与状态的写法

图谱和文字稿中，每项新主动技能至少写明：

- 来源卷章。
- 类型：攻伐、遁身、术诀、守御、业障。应对触发、单场次数、乘势条件等属于机制规则，不放入分类字段。现行秘籍用构筑关键词表达检索方向。
- 耗费：体力与法力是战斗施放成本，不能写成学习条件；灵识是祭出持续法宝时的占用容量。
- 伤害类型：物理或神魂；公式中使用的属性。
- 目标与射程、触发时机、持续时间、移除条件。

心法是秘籍提供的被动效果，不是主动牌。心法随秘籍主修或辅修槽位自动提供，并在战斗开始时由战斗快照生效；不得单独习得、装配或占用心法槽。主修秘籍可以提供心法的追加效果，辅修提供基础效果。心法可标注与主动技能相同的构筑关键词；关键词只作检索，不带来额外规则。心法不得写耗费、灵识占用、目标与射程或独立生效方式。

### 7.1 牌头与机制字段的强制格式

图谱和文字稿中的每项主动技能都必须在技能名之后、效果之前先写技能信息；不得只在正文或数值公式里零散提及。

类型：<攻伐/遁身/术诀/守御/业障>；关键词：<实际机制或状态，可多选；无则写“无”>；耗费：体力 <X>、法力 <Y>；灵识占用：<X>；目标与射程：<目标>；<最小—最大格数或由触发对象决定>

- 体力与法力必须全部写出，未耗费的项目明确写 0，例如：耗费：体力 0、法力 0；灵识占用：0。
- 灵识占用只对祭出后持续留场的法宝、傀儡、阵旗或召唤物有意义；普通牌必须写灵识占用：0。
- 每张牌都必须独占一行写出目标与射程；目标可以是自身、单体敌人、友方单体、指定格、指定格范围、自身范围，或应对牌的明确触发对象。自身牌写自身；0格，应对牌写攻击者；由应对触发对象决定。
- draw.io 图中，牌名、类型、关键词、耗费、目标与射程必须各占一行，顺序固定为牌名 → 类型 → 关键词 → 耗费 → 目标与射程 → 其余字段。
- 关键词只标注效果实际涉及的具体机制或状态，用于检索；不把体力、法力等费用资源或“防御”等笼统方向列为关键词。可直接写“念”“心隙”“护盾”“化解”“应对”“周天”“散血”“穿盾”等实际机制；没有合适标签时写“无”。目前暂不限制每项关键词数量。关键词不产生额外规则。

- 应对等机制的触发条件须写入效果、触发条件或相应机制字段；“应对”也可作为检索关键词，但关键词本身不触发规则。单场限次、心法自动生效、乘势条件等仍写入效果、触发条件或相应机制字段。有限使用次数须在效果之后独占一行，统一写作“使用次数：每轮1次”或“使用次数：本场1次”；不限次字段可省略，若保留也须独占一行。首次触发、每第二次受击等效果触发计数继续写在效果或触发条件中，不移入使用次数行。
- 灵识占用、牌类型、伤害类型、目标和行动方式都不是构筑关键词，分别留在各自字段或效果说明中。
- 禁止使用零消耗无消耗等模糊词描述资源。应直接写明体力和法力均为 0，并写灵识占用：0。
- 心法被动不参照主动牌牌头书写：写类型：心法、关键词与被动效果；不得写资源耗费、灵识占用、目标与射程或独立生效方式。心法不进入技能槽或行动队列。
- 新 `.tres` 中未显式写出的 energy_cost、mana_cost、spirit_occupy 均按 0 处理。
- 神魂伤害不得写最终伤害 = 基础伤害 × 神魂对抗系数这类统一模板。每张神魂攻击牌必须在伤害公式行写明其自身的神魂差值、总神魂、缓冲值、权重与倍率上下限；应对牌需明确施术者与攻击者的对应关系。
- 战斗为行动条制。不得使用本回合、同一回合、轮到对方后、目标已经行动等无法由当前状态直接判定的描述；持续时间和触发时机必须写成自身行动开始、自身行动结束、目标下一次行动开始或目标下一次行动结束等可验证节点。
- 牌型判定以直接效果为准：只要牌结算时直接造成任何伤害，无论伤害是否附带控制、恢复、状态或追击，该牌一律为攻伐牌。术诀牌不得直接造成伤害，只能施加状态、控制、恢复、资源变化、牌序变化或其他非伤害效果。

### 7.2 术语白名单与防误用
