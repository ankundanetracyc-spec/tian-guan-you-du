# 秘籍规范（草案，待补充）

> 本文同时遵循已确认的三资源战斗设计；实现尚未迁移的旧字段必须标为迁移中，不得继续作为新卡规范。
> 若本文与秘籍图谱冲突，以该秘籍的 .drawio 图谱为准；若图谱与运行时不一致，应明确提出按图同步资源。

## 1. 文件与职责

每本秘籍固定使用同名的三份内容：

| 文件 | 职责 | 是否为设计主依据 |
| --- | --- | --- |
| docs/秘籍词典/drawio/<秘籍名>.drawio | 总览、卷章主链、纳气、化法、习得、状态与数值关系 | 是 |
| docs/秘籍词典/md/<秘籍名>.md | 对图谱的文字展开：逐卷、逐牌、联动与边界 | 否，辅助说明 |
| resources/gongfa/<秘籍名>.tres | Godot 运行时功法资源与卡牌引用 | 否，实现结果 |

流程应为：先改图谱 → 确认图谱 → 同步文字稿和 .tres → 校验引用与字段。不得反过来根据 .tres 臆造设计。

## 2. 图谱的固定结构

图谱沿用 _秘籍模板.drawio 的结构：自上而下为卷章主链；每卷向两侧或下方连接本卷的效果。

每本图至少包含：

- 秘籍总览：名称、五行、定位、主修/辅修、适用境界或可修至的境界。
- 卷章主链：卷章名、稳定的英文 ID、顺序、定位、条件。
- 每卷的 纳气、化法、习得。
- 若秘籍使用状态、姿态、层数、技能库替换或跨卷联动，必须在图中画出来源、上限、消耗/移除和结束条件。

图中统一：矩形表示实体，箭头表示关系，注释框表示数值、条件与规则。图中文字足以直接作为描述时，只做语句润色，不改变原意。

## 3. 秘籍总览必须说明的事

- 五行兼容性：用于学习、卷章参悟与主修资格校验；灵根权重仅用于主修修炼匹配：
  - NONE：无灵根要求。
  - ALL：通用功法；有灵根即可，不挑五行。
  - 其余值：只读取灵根类型中明确拥有的有效属性；权重数组中的散余亲和无效，不参与判定或效率。
  - 多属性功法必须标注 `OR` 或 `AND`：OR 具备任一要求属性即可，AND 必须具备全部要求属性。
  - `OR` 的原始匹配权重取所有有效匹配属性中的最高值；`AND` 取全部要求属性的有效权重平均值；通用功法固定为 100%。
- 槽位：可主修、可辅修或仅研读。
- 主修的起止境界；仅辅修秘籍不写可修至某境界。
- 核心战斗循环或日常修炼方向。

剧情来源不属于功法本体规范。例如某本秘籍由玄镜传下，应写在剧情节点、事件或引导中，不写进功法的学习条件、卷章条件和通常简介。

## 4. 卷章的固定信息

每一卷至少写：

1. 卷章名与 chapter_id：ID 只使用稳定的英文小写下划线形式；资源、前置条件与卡牌引用均以它为准。
2. 顺序与一句话定位：说明本卷解决什么问题，不用剧情代替机制。
3. 研读值：required_study_progress。它是累计研读进度门槛，不是精力，不会在解锁时扣除。
4. 学习条件：灵根条件、前置卷章、境界、基础属性或对应造诣门槛、是否仅主修可学。
5. 学会即得：基础属性或对应造诣的永久固定加成或永久倍率加成。
6. 纳气：装备后生效的固定/倍率加成；主修额外效果需单列。
7. 化法：明确目标是基础技能库技能，还是本秘籍授予的技能；写明加入或替换，以及主修专属结果。
8. 习得：本卷新增的主动技能按名称列出，不写卡牌复制数量；秘籍心法由主修/辅修槽位自动提供，不进入习得列表。

### 4.1 条件的语义

- 研读值：角色执行研读日程时，按学习效率累计；与精力的关系仅是研读日程可能消耗精力，不是卷章条件本身。
- 灵根条件：开始学习与继续参悟前均校验；只读取有效灵根类型和 OR/AND 条件，不读取灵根权重。
- 卷章境界：首卷为凡人及以上；第二卷须云息三层；第三卷须云息六层；第四卷须云息九层。后续卷章继续按每卷递增三层配置。
- 修行倾向：可记录卷章更适合锻躯、行炁或蕴神中的哪一种风格，但不作为研读或兼修的硬门槛；角色可通过当前主修表达主要侧重。
- 研读属性：每一卷必须配置与该秘籍路线相符的基础属性与造诣门槛，并随卷章递进；该条件只校验，不会扣除属性。
- required_attributes：只作数值门槛，不会扣除属性。新秘籍可使用体魄、灵慧、敏捷、神魂四项基础属性，以及与秘籍路线相符的造诣；不以生命、精力、心境、法力、回复速度等资源或战斗面板属性作为学习门槛。
- required_chapter_ids：必须已学会的前置卷章 ID。
- required_realm：当前代码按境界名称精确匹配；写入前必须确认是否希望未来改为达到该境界及以上。
- requires_main_slot：仅主修槽位可学习。

## 5. 秘籍允许使用的属性

所有资源键仍须存在于 `csharp/gongfa/AttrKeySets.cs`；未登记字段会被过滤，不能写入资源。除该技术限制外，新秘籍按以下分类使用属性。

### 5.1 学习条件与学会永久加成

可使用四项基础属性与对应造诣：

- physique 体魄、intelligence 灵慧、agility 敏捷、soul 神魂。
- sword_proficiency 剑道造诣、blade_proficiency 刀道造诣、spear_proficiency 枪道造诣、body_proficiency 体道造诣、magic_proficiency 术法造诣。

不将以下属性作为新秘籍的学习门槛或学会后的永久属性加成：

- fortune 机缘、comprehension 悟性、charisma 魅力。
- spirit_strands 灵力（缕）、core_count 灵核数。
- 生命、精力、心境、法力、灵识及其上限或回复速度。

### 5.2 纳气属性

纳气只从战斗与生存属性或成长与专长属性中选择；不直接提供上述四项基础属性，也不提供机缘、悟性、魅力与灵力体系属性。

常用战斗与生存属性：

- max_health 生命上限、max_stamina 精力上限、max_mind 心境上限、max_mana 法力上限。
- physical_defense 物理防御、precision 精准、dodge 闪避、critical 暴击、crit_resist 抗暴、initiative_speed 行动速度。
- health_regen_rate 生命回复、stamina_regen_rate 精力回复、mind_regen_rate 心境回复、mana_regen_rate 法力回复。

常用成长与专长属性：

- learning_rate 学习速率、cultivation_rate 修炼速率。
- sword_proficiency 剑道造诣、blade_proficiency 刀道造诣、spear_proficiency 枪道造诣、body_proficiency 体道造诣、magic_proficiency 术法造诣。

物理防御只可由护具、功法、锻体成果或状态等明确来源提供，基础属性不自动换算物理防御。不存在神魂防御或法术防御；神魂伤害必须写明攻击方与受击方神魂如何参与该招式的计算。凡人法力与灵识为 0，涉及法力、灵识的纳气或卡牌效果须标注云息后才有实际作用。

## 6. 数值层级不得混写

| 层级 | 含义 | 资源字段 |
| --- | --- | --- |
| 学会永久加成 | 学会后永久保留，不依赖是否装备 | learn_permanent_bonuses / learn_permanent_multipliers |
| 装备被动 | 作为辅修装备时生效，卸下即失效 | passive_bonuses / passive_multipliers |
| 纳气 | 启用纳气路线时生效；主修可另有额外效果 | naqi_* / main_naqi_* |
| 化法 | 改写基础技能库技能，或改写/加入本秘籍授予的技能 | GongfaDeckRewriteConfig |
| 习得 | 学会卷章后授予或解锁的主动技能 | learned_active_skills / main_learned_active_skills |

倍率字段以小数存储：0.10 表示 +10%。固定加成按实际数值写入。不得把获得卡牌技能库加入永久属性写成同一类收益。

### 6.1 化法的强制规则

每条化法配置必须明确目标范围：角色当前路线对应的基础技能库，或这本秘籍授予的主动技能。不得改写其他秘籍授予的技能或战斗中临时生成的技能。改写结果只影响技能运行时数据，不修改共享技能资源。

- **加入**：将结果技能加入指定范围；即时战斗中按一个可装配技能显示，不写 `×1` 或卡牌复制数量。
- **替换**：将指定范围内匹配的技能改为结果技能；写明原技能名与结果技能名。若目标是本秘籍授予的技能，只能匹配同一本秘籍的授予技能。
- **习得**记录学会卷章后新增或解锁的技能。它可以成为同一本秘籍化法的目标；化法结果作为该技能的当前版本显示，不重复列出原版与改写版。
- 图谱、文字稿和 `.tres` 必须一致地注明目标范围、加入/替换方式及结果。心法不列为化法目标，仍由主修/辅修秘籍槽位自动提供。

基础技能库目标的可替换来源以 `docs/基础牌库词典/` 为准：

- 体修：拳脚、调息、基础步法、卸力。
- 纳气：灵击、聚息、基础步法、护元。
- 剑修：斩剑、点锋、养锋、敛息观剑、基础步法、格剑、藏锋。

## 7. 卡牌与状态的写法

图谱和文字稿中，每项新主动技能至少写明：

- 来源卷章。
- 类型：攻伐、遁身、术诀、守御、业障。应对触发、单场次数、乘势条件等属于机制规则，不放入分类字段。锻躯七本秘籍统一用构筑关键词替代锻躯路径标签。
- 耗费：精力与法力是战斗施放成本，不能写成学习条件；灵识是祭出持续法宝时的占用容量。
- 伤害类型：物理或神魂；公式中使用的属性。
- 目标与射程、触发时机、持续时间、移除条件。

心法是秘籍提供的被动效果，不是主动牌。心法随秘籍主修或辅修槽位自动提供，并在战斗开始时由战斗快照生效；不得单独习得、装配或占用心法槽。主修秘籍可以提供心法的追加效果，辅修提供基础效果。锻躯七本秘籍的心法可标注与主动技能相同的构筑关键词；关键词只作检索，不带来额外规则。心法不得写耗费、灵识占用、目标与射程或独立生效方式。

### 7.1 牌头与机制字段的强制格式

图谱和文字稿中的每项主动技能都必须在技能名之后、效果之前先写技能信息；不得只在正文或数值公式里零散提及。

类型：<攻伐/遁身/术诀/守御/业障>；关键词：<构筑主题，可多选；无则留空>；耗费：精力 <X>、法力 <Y>；灵识占用：<X>；目标与射程：<目标>；<最小—最大格数或由触发对象决定>

- 精力与法力必须全部写出，未耗费的项目明确写 0，例如：耗费：精力 0、法力 0；灵识占用：0。
- 灵识占用只对祭出后持续留场的法宝、傀儡、阵旗或召唤物有意义；普通牌必须写灵识占用：0。
- 每张牌都必须独占一行写出目标与射程；目标可以是自身、单体敌人、友方单体、指定格、指定格范围、自身范围，或应对牌的明确触发对象。自身牌写自身；0格，应对牌写攻击者；由应对触发对象决定。
- draw.io 图中，牌名、类型、关键词、耗费、目标与射程必须各占一行，顺序固定为牌名 → 类型 → 关键词 → 耗费 → 目标与射程 → 其余字段。
- 锻躯七本秘籍使用可跨秘籍复用的构筑关键词“生命、闪避、回复、精力、增伤、伤势、防御、攻防联动”，每项最多三项。关键词描述构筑方向，不照搬秘籍专属状态名；例如游骸与身法归入闪避，血炉归入增伤，化解归入防御，借力归入攻防联动。关键词不代表硬路径、元素或规则触发。其他体系沿用各自已定义的分类方式。
- 应对触发、单场限次、心法自动生效、乘势条件等机制须写入效果、触发条件或相应机制字段；保留其运行行为，但不得把它们填入关键词栏。有限使用次数须在效果之后独占一行，统一写作“使用次数：每轮1次”或“使用次数：本场1次”；不限次字段可省略，若保留也须独占一行。首次触发、每第二次受击等效果触发计数继续写在效果或触发条件中，不移入使用次数行。
- 灵识占用、牌类型、伤害类型、目标和行动方式都不是构筑关键词，分别留在各自字段或效果说明中。
- 禁止使用零消耗无消耗等模糊词描述资源。应直接写明精力和法力均为 0，并写灵识占用：0。
- 心法被动不参照主动牌牌头书写：写类型：心法、关键词与被动效果；不得写资源耗费、灵识占用、目标与射程或独立生效方式。心法不进入技能槽或行动队列。
- 新 `.tres` 中未显式写出的 energy_cost、mana_cost、spirit_occupy 均按 0 处理。
- 神魂伤害不得写最终伤害 = 基础伤害 × 神魂对抗系数这类统一模板。每张神魂攻击牌必须在伤害公式行写明其自身的神魂差值、总神魂、缓冲值、权重与倍率上下限；应对牌需明确施术者与攻击者的对应关系。
- 战斗为行动条制。不得使用本回合、同一回合、轮到对方后、目标已经行动等无法由当前状态直接判定的描述；持续时间和触发时机必须写成自身行动开始、自身行动结束、目标下一次行动开始或目标下一次行动结束等可验证节点。
- 牌型判定以直接效果为准：只要牌结算时直接造成任何伤害，无论伤害是否附带控制、恢复、状态或追击，该牌一律为攻伐牌。术诀牌不得直接造成伤害，只能施加状态、控制、恢复、资源变化、牌序变化或其他非伤害效果。

### 7.2 术语白名单与防误用

- intelligence 的唯一正式显示名为灵慧。设计文档、图谱、UI 文案与说明中均不得写作才智智力或其他别名。
- 资源支付唯一称为耗费；消耗只用于描述卡牌进入消耗牌堆的机制，不能代替资源支付名称。
- 所有主动牌必须完整写明精力、法力与灵识占用；心法被动不设费用或目标字段。
- 新增或调整秘籍后，必须运行 tools/validate_miji_dictionary.ps1。校验未通过时不得将文案、图谱或数值视为完成，避免凭记忆沿用旧术语。
- 词典展示文案不使用中文引号、单引号或反引号；术语、卡名、状态名直接书写即可。draw.io 的 XML 属性引号和资源文件的语法引号不属于展示文案，不得改动。

新状态至少写明：

- 获得方式、最大层数、叠加规则。
- 若状态的层数或效果须按施加者区分，必须标为来源型状态：同一目标上不同施加者的层数、上限、消耗与效果分开记录；每次增伤或消耗须明确读取哪一名施加者的层数。
- 每层或生效期间的具体数值。
- 消耗、清除、过期和结算时机。

若图中写替换，必须明确原基础牌、结果牌、数量及是否仅主修；若写加入，必须明确加入数量。未建立的卡牌/状态只能标为设计中，不能在 .tres 中伪造已生效的引用。

## 8. .tres 同步检查单

- 功法名、五行、槽位与主修境界和图谱一致。
- 卷章 ID、顺序、前置 ID、研读值、条件与图谱一致。
- 所有字典键均在 AttrKeySets.gd 中存在。
- 所有主动牌资源、心法被动资源、技能库改写都指向实际资源路径。
- 构筑关键词与 draw.io、卡牌表和运行时展示字段保持一致；机制字段不混入关键词。
- 图中未实现的状态或特殊效果不写成已经运行。
- 运行 Godot 资源解析，并检查 XML 图谱可读取。

- 卡牌数、替换数、状态数的上限。
